Web コンソールは 容大AI のデフォルトチャネルです。起動後に自動的に実行され、ブラウザを通じて Agent と対話できるほか、モデル、Skill、メモリ、チャネルなどの設定をオンラインで管理できます。

## 設定

```json
{
  "channel_type": "web",
  "web_host": "0.0.0.0",
  "web_port": 9899,
  "web_password": "",
  "enable_thinking": false
}
```

| パラメータ | 説明 | デフォルト値 |
| --- | --- | --- |
| `channel_type` | `web` に設定 | `web` |
| `web_host` | Web サービスのリスンアドレス。デフォルトは `127.0.0.1`（ローカルのみ）。公開アクセスが必要な場合は `0.0.0.0` に変更してパスワードを設定してください | `""` |
| `web_port` | Web サービスのリスンポート | `9899` |
| `web_password` | アクセスパスワード。空欄の場合はパスワード保護が無効。`0.0.0.0` でリスンする場合は設定を推奨 | `""` |
| `web_session_expire_days` | ログインセッションの有効日数 | `30` |
| `web_file_serve_root` | web コンソールが直接読み取り/送信できるファイルのルートディレクトリ。デフォルトはユーザーのホームディレクトリと agent ワークスペースのみ。`/` に設定するとファイルシステム全体を許可 | `"~"` |
| `enable_thinking` | 深い思考モードを有効化するか | `false` |

パスワード設定後、コンソールへアクセスする際にはまずパスワード入力によるログインが必要です。ログイン状態はデフォルトで 30 日間保持され、その間はサービスを再起動しても再ログインは不要です。パスワードはコンソールの「設定」ページからオンラインで変更することもできます。

### インスタンスのブランド設定

Web コンソールには独自のブランド（ブランド名、ロゴ説明、カスタムロゴ、およびそこから派生するブラウザ favicon）を設定できます。ブランドはインスタンス単位（単一の Web デプロイ）で、デスクトップクライアントやドキュメントサイトには影響しません。

ログイン後、「システム設定 → ブランド設定」で編集・保存できます。機能の有効化は不要です。旧設定の `branding_enabled` は無視されます。

- **範囲**: インスタンス単位。ブランドデータは `<data_root>/branding/` に保存され、`config.json` には書き込まれません。
- **パスワード前提**: ロゴは未認証の訪問者にも配信されるため、`web_password` が設定されている場合のみ編集できます。パスワード未設定では設定ページは読み取り専用になり、その理由が表示されます。
- **認証モード**: 書き込みは単一インスタンスの `identity_mode=legacy` のみ対応します。データベース認証などのモードは、実際のプラットフォーム権限と監査が接続されるまで保存・復元できません。
- **API 認証**: 有効な Authorization Bearer またはログイン Cookie を使用します。URL token のみでの書き込みは不可です。Cookie の場合、`/api/branding` の `csrf_token` を同一オリジンの保存・復元リクエストの `X-Branding-CSRF` ヘッダーに設定します。画面では自動処理されます。
- **破損時の復元**: 公開設定が破損・欠落した場合、復元プレビューは読み取り専用です。明示的な復元では元ファイルを `branding/corrupt/` に保持し、新しいリビジョンを割り当てます。ブランドディレクトリの `.revision.json` を保持してください。
- **フィールド/形式の制限**: ブランド名 `1–32` 文字、ロゴ説明 `0–100` 文字（単一行、制御文字なし）、画像 `PNG / JPG / WebP`、`≤ 2 MiB`、一辺 `32–4096` px、総画素数 `≤ 16,000,000`、アニメーション画像は不可。アップロードされた画像は安全な PNG に正規化され（EXIF 適用、メタデータ除去）、`32×32` の favicon が派生されます。
- **公開モデル**: 保存または「全デフォルトに戻す」はアトミックに新しいリビジョンを公開します。別タブ/別ブラウザからの同時編集は検出され、上書きではなく競合として通知されます。
- **デフォルトに戻す**: 「全デフォルトに戻す」は確認ダイアログの後、名前・説明・ロゴ・favicon を内蔵デフォルトにリセットし、リビジョンを増やします。
- **バックアップ/ロールバック**: `cow backup` は公開済みブランドスナップショットと参照画像をまとめて保存します。`cow restore` はそれらを新しいリビジョンで対象のデータルートに再公開します。ブランドセグメントを含まないアーカイブは既存ブランドを削除しません（新規インスタンスは内蔵デフォルトにフォールバック）。アプリのバージョンをロールバックする場合は、先にブランドディレクトリをバックアップしてください。旧コードは新しいブランドデータを消費しません。

<Note>
  ログインページやサイドバーに表示されるロゴは公開リソースです。未認証の訪問者に見せても問題ないコンテンツのみを設定してください。
</Note>

## アクセス URL

プロジェクト起動後、以下にアクセスしてください：

- ローカル実行: `http://localhost:9899`
- サーバー実行: `http://<server-ip>:9899`

<Note>
  サーバーのファイアウォールとセキュリティグループで該当ポートが許可されていることを確認してください。
</Note>

## 機能紹介

### アカウントメニュー

個人アカウント（身分モード `database`）でログインすると、サイドバー左下のカードにアバター、表示名（またはユーザー名）と `@ユーザー名` が表示されます。ナビゲーションをスクロールしても常時表示され、テナントを切り替えても同じアカウント身分です。

カードをクリックすると上向きに6項目のメニューが開きます。各項目は現在のページから離れることなく操作できます。

- **個人プロフィール**：読み取り専用の引き出しで、氏名、ログインID、プラットフォーム身分フラグ、および現在のテナントのメンバー名・役割・部門・役職を表示します。グローバルアカウントとテナントメンバーの情報は分けて表示され、メンバー名がアカウントカードを上書きすることはありません。空値は「未設定」、テナントなしは「未加入」と表示します。読み取りに失敗した場合は再試行を提供し、確認済みログインとパスワード/ログアウトの項目は維持します。
- **パスワード変更**：現在のパスワード・新しいパスワード・確認の3項目のモーダルです。成功するとセッションが取り消され再ログインを求められ、他のログイン中のセッションも無効になる旨が表示されます。アカウントがパスワード変更を要求されている場合（初回ログイン/一時パスワード）は、テナント選択とビジネスデータ読み込みの前に同じフォームがゲートとして表示され、変更を完了するかログアウトするしかありません。
- **画面設定**：ライト/ダークテーマ、簡体/繁体/英語を現在のブラウザのみにローカル適用し、ヘッダーの切り替えと同期します。個人の選択はインスタンス既定を書き込みません。ブラウザストレージが使えない場合はこのページにのみ適用され、その旨が表示されます。
- **テナント切り替え**：有効なメンバーであるテナントのみを一覧し、現在の項目をマークします。0件なら「未加入」、1件なら現在名を表示、複数なら選択できます。切り替えはページ再読み込みで反映され、新しいページが対象を検証してから確定します。キャンセル時は元のページを変更せず、無効な対象が他のテナントに静かに入ることはありません。
- **現在のブランドについて**：現在のブランドとバージョンを表示し、元のリリースノートリンクを開きます。
- **ログアウト**：現在のログインセッションを終了してログインページへ戻り、単発送信と失敗時の再試行を備えます。

Esc キーまたは外側クリックでメニューが閉じます。引き出し/モーダルを閉じるとカードのトリガーへフォーカスが戻ります。モバイルや短いビューポートでも各項目に到達でき、非表示メニューはフォーカスを受けません。

legacy アクセスの場合、カードは「ローカルアクセス」を表示します。

- **パスワード保護**：メニューからログアウトでき、「画面設定 / について / ログアウト」のみ適用されます。
- **ログイン不要**：「画面設定 / について」を維持し、ログアウト操作も個人パスワード項目もありません。

初期ログイン確認に失敗した場合はログイン画面で「再確認」を選択します。コンソール内でアカウント情報が利用できなくなった場合はカードを開いて「再確認」を選択すると、現在のページと下書きが保持されます。ログインは確定しているがプロフィールを表示できない場合も「ログアウト」は利用可能です。「ログアウト未確認」の場合は「ログアウトを再試行」または「再確認」で復旧できます。

### チャット画面

ストリーミング出力に対応しており、Agent の思考プロセス（Reasoning）とツール呼び出しプロセス（Tool Calls）をリアルタイムで表示でき、Agent の意思決定をより直感的に観察できます。深い思考機能は設定またはコンソールの「Agent 設定」スイッチで制御できます。

#### マルチセッション管理

チャット画面はマルチセッション（Session）管理に対応しています。すべてのセッション記録はデータベースに永続化されます：

- **セッション一覧**：「ワークベンチ → セッション履歴」ページで、アクセス可能なすべての履歴セッションを表示・スクロール読み込みでき、プロジェクト/日付ごとにグループ化されます
- **セッション検索**：一覧上部の検索欄にタイトルのキーワードを入力すると、未読み込みのセッションも含め、アクセス可能な履歴全体を検索できます。中国語・英語に対応し、英字の大文字小文字を区別しません。検索欄を空にすると、元の一覧に戻ります
- **AI によるタイトル生成**：新しいセッションの初回対話完了後、自動的にモデルを呼び出して短いセッション要約タイトルを生成します
- **新規セッション**：セッション履歴ページ上部の「新しい会話」ボタンまたは入力エリアの `+` ボタンをクリックして新しいセッションを作成します
- **セッション操作**：セッション項目右側の「⋯」ボタンから、ピン留め・解除、名前変更、削除を行えます。削除には確認が必要で、確認後にそのセッションとすべてのメッセージを完全に削除します
- **コンテキストクリア**：入力エリアのクリアボタンをクリックすると、現在のセッションに区切り線が挿入されます。区切り線より上のメッセージは表示されたままですが、モデルのコンテキスト入力には含まれなくなります
- **ワークスペース / モデル**：入力欄の下で、現在のセッションにワークスペースとモデルを個別に設定できます。複数のプロジェクトを使う場合、過去のセッションは自動的にプロジェクトごとにグループ化されます。詳しくは [アーキテクチャ - プロジェクトワークスペース](/ja/intro/architecture#project-workspace) を参照してください

#### 権限モード

Agent がファイルやコマンドに触れられる範囲は権限モードで決まります：読み取り専用（read-only）、ワークスペース書き込み可（workspace-write）、フルアクセス（full-access）。シングルテナント構成では「設定 → セキュリティ」でグローバルの既定権限を選び、新しいセッションがそれを継承します。マルチテナント（データベースモード）構成ではこの設定は読み取り専用で、実際に実行できる内容は呼び出し元の**ロールリソース認可**（どのロールがどのツール・リソースを使えるかを管理者が割り当てる）で決まります。会話内で権限を緩める入口はありません。ツール呼び出しがブロックされた場合は理由が表示されますが、その場で権限を変更するボタンはありません。

#### エージェント

「エージェント」には 2 つの入口があります：**管理 → エージェント設定**（管理モード）と **ワークベンチ → エージェント**（利用モード）です。

- **ワークベンチ → エージェント（利用ページ）**：**保存済みかつ有効**なエージェントをカード形式で読み取り専用表示し、デフォルト項目を識別し、各カードに `開始チャット` ボタンを表示します。カードをクリックすると、そのエージェントに紐づく新しいチャットが開きます：エージェントの名前とアバターを表示し、入力欄にフォーカスし、そのエージェントのデフォルトワークスペースを使用します（他のプロジェクト／セッション設定は継承しません）。現在のモードで実行可能な場合のみ入口が表示されます。`view=workbench` の読み取りはホワイトリスト投影で、ワークスペースパス、チャネルインスタンス、コアファイルなどの管理データは公開しません。

- **管理 → エージェント設定（管理モード）**：エージェント（名前、役割、アバター、モデル、ナレッジベース、コアファイルなど）の完全な CRUD を提供します。ワークベンチ → エージェントと同じデータソースを共有します。ここでは編集でき、利用ページは読み取り専用です。同時編集はロスターリビジョンによって検出され、上書きではなく競合として通知されます。
