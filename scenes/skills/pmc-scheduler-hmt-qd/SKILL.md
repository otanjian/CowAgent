# Production Scheduling (生产排产)

## When to Use This Skill

- 用户提供包含"排产规则"、"产能"、"排产1"、"排产2"、"班组产线"等sheet的Excel文件
- 用户要求根据排产规则填写或更新排产2表中的早班/夜班产量
- 用户要求重新排产（规则变更、产能变更、备货周期调整等）
- 用户要求优化排产规则文字

## Excel Template

技能包内置了排产模板文件，路径：

```
templates/生产排产模板.xlsx
```

该模板包含完整的5个sheet结构和排产规则，可直接复制使用或参考其格式创建新的排产文件。

## Context / Background

### Excel文件结构

生产排产Excel包含5个核心sheet：

| Sheet | 用途 |
|-------|------|
| 排产规则 | 10条排产规则文本（A列=序号，B列=规则内容） |
| 产能 | SAP物料号→课别→产线→产能→优先级 |
| 排产1 | 需求数据源：SAP物料号、备货(G列)、备注(O列)、差异量减排产量(AC列/动态识别)、预估减出货量减库存量(AA列/动态识别)、生产线量(AB列/动态识别)、未来出货量(AZ-CI列) |
| 排产2 | 排产结果表：课别(B列)、产线(D列)、SAP(G列)、班组(K列)、日期数据(行3=日期) |
| 班组产线 | 产线→班组人员映射 |

### 关键列映射

**排产1表：**
- B列: SAP物料号
- G列: 备货产品（如"2周""3周"，表示需提前备货的周数）
- O列: 备注（含"设变""提前备货2周"等关键字）
- AC列（字段名「差异量减排产量」，动态识别）: 库存量。负数表示有库存，正数表示缺货。
  - 当「生产线量」<> #N/A 时：差异量减排产量 = 预估减出货量减库存量 - 生产线量
  - 当「生产线量」= #N/A 时：差异量减排产量 = 预估减出货量减库存量
- AA列（字段名「预估减出货量减库存量」，动态识别）: #N/A 回退源
- AB列（字段名「生产线量」，动态识别）: 生产线量
- AZ-CI列: 未来出货量（每列覆盖一周7天，AZ=第一周、BA=第二周，依此类推）

**排产2表：**
- B列: 课别，D列: 产线，G列: SAP物料号，K列: 班组
- 行3: 日期（7/28起，每隔一列一个日期）
- 奇数列(29,31,33...55): 早班产量
- 偶数列(30,32,34...56): 夜班产量
- 日期范围: 7/28~8/10共14天，7/31~8/10为11个工作日

**产能表：**
- A列: SAP物料号, B列: 课别, C列: 产线, D列: 产能(每天), E列: 优先级(1/2/3...)

## Instructions / Steps

### 推荐执行方式（脚本 CLI，v2 重构版）

优先使用引擎脚本 `scripts/schedule_production.py` 自动完成排产，避免手工 openpyxl 逐项填写（下文的 Step 1~3 保留为逻辑说明与手工降级参考）。

```bash
# 先 cd 到技能目录（SKILL.md 所在目录）
cd {workspace}/skills/pmc-scheduler-hmt-qd

# 解析预览（不写文件，输出 JSON，含 window/rules/capacity/teams/merge_rules/demands/skipped/warnings）
python3 scripts/schedule_production.py parse --excel <模板路径> [--config rules.json] [--capacity capacity.json] [--teams teams.json] [--merge merge_rules.json] [--demands <预估出货量.xlsx>] [--material <SAP号>] --json

# 执行排产（基于模板副本生成新表，输出 JSON + 写文件）
python3 scripts/schedule_production.py run --excel <模板路径> --output <输出路径> [--config ...] [--capacity ...] [--teams ...] [--merge ...] [--demands <预估出货量.xlsx>] [--material <SAP号>] --json
```

**配置化参数（均可由外部 JSON/Excel 传入，缺省时引擎自动读取模板内 sheet 或内置默认）：**

| 配置项 | CLI 参数 | 说明 |
|--------|---------|------|
| 排产规则 | `--config` | period_count / max_priority / shebian_keyword / stockup_keywords / stockup_trigger_keywords / stockup_start_on_monday / night_divisor / night_basic_enabled / night_enabled / early_col_parity |
| 产能表 | `--capacity` | `{SAP号: [{line, capacity, priority, dept}]}` |
| 班组产线 | `--teams` | `[{seq, area, team, count, lines[1..5], remark}]` |
| 拼线规则 | `--merge` | `[{team, line, partners[], raw, parsed}]`，从班组备注自动解析，未识别可人工补录 |
| 预估出货量 | `--demands` | 独立 Excel（含「排产1」sheet），作为出货需求数据来源；**优先于模板内排产1**，未提供时回退模板排产1 |

**拼线规则（规则10 扩展）：** 班组备注中如「开S5291线和黄根拼」「S2604跟郑波班组合」会被解析为拼线规则；执行排产时某班组开线需与伙伴班组拼线时强制合并执行（备注结构化输出）。

**v2 关键改进（对比原手工流程）：**
1. 日期驱动：排产2 表行3 日期动态推导早班/夜班列号，不再硬编码 7/31~8/10、8/3
2. 规则5 数量追踪：剩余需排产量 < 当日产能时填剩余量，次日填 0
3. 规则10 班组分配：按班组第一~第五产线偏好查找，支持替代班组，强制执行拼线规则
4. 预估出货量独立表：`--demands` 提供时排产1 数据源改从此表读取（含排产1 sheet），不再从模板读取
5. 运行 `run` 时先 `shutil.copy2` 生成模板副本再写入，原模板不被修改

### Step 1: 读取数据

用openpyxl读取Excel（`data_only=True`取公式缓存值，`data_only=False`取公式结构）：
1. 读取排产规则sheet的10条规则
2. 读取产能表全部物料→产线→产能→优先级映射
3. 读取排产1表每个物料的G列(备货)、O列(备注)、库存列(表头名动态识别，已取反)、周出货量列(动态识别至最后一列非空)
4. 读取排产2表当前排产值和班组信息

### Step 2: 逐物料计算排产

对每个SAP物料，按以下规则依次执行：

**规则1-2 计算需排产量：**
- 库存字段 = 「差异量减排产量」。当「生产线量」<> #N/A 时：差异量减排产量 = 预估减出货量减库存量 - 生产线量；否则 = 预估减出货量减库存量。
- 客户符号约定：该值为负表示有库存，为正表示缺货。
- 需排产量 = W1 + W2 + 库存

**规则3 确定排产期间：**
- 找出前两个出货量不为0的期间
- 第二期为0则仅取第一期
- 两期均有出货：从第一期起始日至8/10共11天全部安排早班

**规则4 选择产线：**
- 产能表查找物料对应产线及优先级
- 取优先级前2名（优先级3及以上不排产）
- 单产线物料使用唯一产线

**规则5 填入早班：**
- 匹配排产2表中SAP+课别+产线行
- 从第一期起始日在早班列逐日填入产能值
- 剩余量小于当日产能时填剩余量，次日填0

**规则6 夜班触发(基本规则)：**
- 11天早班排产总量不足以覆盖第一周出货量时，需安排夜班

**规则7 设变检查：**
- O列含"设变"原则上不排产
- 但G列有备货周期且库存不足时可按备货规则排产

**规则8 备货产品提前排产：**
- G列标注备货周期("2周""3周")时，计算库存可覆盖的出货周数
- 后续出货超出库存覆盖时，从缺货前一周周一开始排产
- 仅安排早班至排产期末(8/10)

**规则9 备货产品夜班触发：**
- G列含"2周""3周""4周"或O列含"提前备货2周"
- 且 (第一周出货量 + 第二周出货量) / 14 > 产线日产能(多产线取合计)
- 满足条件需安排夜班

**规则10 班组分配：**
- 根据排产2表产线(D列)在班组产线表中匹配班组人员
- 班组已安排在其他产线时选择可替代班组

### Step 3: 写入排产2表

1. 用openpyxl(data_only=False)加载保留公式
2. 清空目标行旧数据(列29-56)
3. 按计算结果填入早班/夜班产能值
4. 填入班组到K列
5. 保存文件

## Constraints / Guardrails

### openpyxl 保存陷阱
- **保存会清除公式缓存值**：库存/派生列（如旧模板 AY=`=AW-AX`）保存后变为0
- **解决方案**：读取用 `data_only=True` 取公式缓存值，保存用 `data_only=False` 保留公式结构

### 班组产线表匹配
- 部分产线无"S"前缀（如6605/6707在表中可能是"S6605"或"6605"）
- **解决方案**：同时匹配带"S"和不带"S"前缀的产线名

### 日期列对应关系
- 7/28~7/30不排产（未来出货从7/31开始）
- 7/31对应列35(早班)/36(夜班)
- 8/3对应列41(早班)/42(夜班)
- 8/10对应列55(早班)/56(夜班)
- 早班列(奇数): 35,37,39,41,43,45,47,49,51,53,55
- 夜班列(偶数): 36,38,40,42,44,46,48,50,52,54,56

### 夜班触发计算注意
- 规则9用 /14（两周日历天数），不是 /10（工作日）
- 多产线时产能取合计（如S5142=1400 + S6605=1350 = 2750）
- G列="3周"也会触发夜班检查（无例外）

### 文件操作
- **必须先备份**：`shutil.copy2(src, src.replace(".xlsx", "_backup.xlsx"))`
- 写入前清空目标行旧数据，避免残留
- 保存后验证写入结果

## Examples

### 示例1：两期出货物料（4406）

```
排产1数据: G="2周", 库存=-34380, W1=20000, W2=20000
产能: S0302=2050(p1), S0601=1950(p2), S2303=1950(p3,跳过)

计算:
- 两期均有出货 → 7/31~8/10共11天早班
- 夜班检查(规则9): (20000+20000)/14=2857 < 4000 → 不触发
- 结果: S0302早班11天×2050 + S0601早班11天×1950, 无夜班
```

### 示例2：备货产品提前排产（3925）

```
排产1数据: G="2周", 库存=-42920, W1=20520, W2=22080, W3=19440, W4=21120
产能: S6206=2150

计算:
- 库存42920覆盖W1+W2(42600)后仅剩320，不足以覆盖W3
- 规则8: 从W2起始日(8/3周一)开始排产
- 规则9: (20520+22080)/14=3043 > 2150 → 触发夜班
- 结果: S6206早班8天×2150(8/3~8/10) + 夜班8天×2150
```

### 示例3：设变物料例外排产（4362）

```
排产1数据: G="3周", O="预计设变", 库存=-400, W1=0, W2=0
产能: S3101=450

计算:
- 规则7: O列含"设变"原则上不排
- 但G="3周"且库存仅400不足 → 按备货规则排产
- 规则3: W1=0 → 仅取第一期...但出货为0
- 用户指定: 从8/3开始排早班至8/10
- 规则9: (0+0)/14=0 < 450 → 不触发夜班
- 结果: S3101早班8天×450(8/3~8/10), 无夜班
```
