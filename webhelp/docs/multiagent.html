CowAgent 不再只是一个 Agent，你可以创建多个 Agent 组成一支团队：每个成员有自己的职责、模型、技能和知识，既能各自独立工作，也能被拉进同一个会话里一起协作。

为什么需要团队

多个专家 Agent 组成的团队更合适处理来自不同业务领域的复杂任务，原因如下：

  • 独立的上下文：单个 Agent 职责过多会引入大量无关上下文，拖累效果、抬高 token 成本。按领域拆分后，每个 Agent 上下文更聚焦，回答更准，成本更低。
  • 不同能力协作：各 Agent 可绑定不同的模型与技能，通过分工、协作乃至互相审查，完成单个 Agent 难以胜任的复杂任务。
  • 数据和权限隔离：每个 Agent 有独立的工作空间，记忆、会话与产出的文件互不可见，适合按角色或按客户划分边界。
  • 更好的呈现效果：不同通道或同一通道的不同实例可接入不同 Agent，对外呈现为多个独立助手，也可将整支团队接入同一通道协作应答，轻松搭建一个数字员工团队。

对只使用单个 Agent 的用户，体验保持不变，团队相关功能在创建第二个 Agent 后才会出现。

创建 Agent

在 Web 控制台或桌面端的「智能体团队」页面点击创建，即可新增一个 Agent。一个 Agent 由以下几部分构成：

  • 名称与头像：团队里的身份标识，会显示在会话气泡、成员列表和通道绑定处。
  • 职责：一句话说明这个 Agent 负责什么。它既方便你区分成员，也会在协作时用于判断任务该交给谁。
  • 默认模型：可以为这个 Agent 单独指定模型。默认 Agent 跟随全局配置。
  • 技能与知识：可以与团队共享，也可以让 Agent 拥有一套专属的知识库，互不影响。
  • 从已有 Agent 复制：新建时可以复制一个现有 Agent 的配置、技能与知识作为起点。

创建后，Agent 会出现在团队列表中。点击任意成员，右侧可以在「概况 / 技能 / 核心文件」之间切换，分别配置它的基本信息、启用的技能，以及它的人设与规则文件（AGENT.md、RULE.md 等）。

团队里始终有一个默认 Agent，它是新会话和各处的兜底对象，跟随全局模型配置，不能被删除。

知识库：共享还是独立

每个非默认 Agent 都可以选择知识库模式：

  • 共享：与团队读写同一个知识库，适合面对同一批资料的场景。
  • 独立：拥有专属知识库，与其他成员互不影响，适合各领域资料差异较大的场景。

两种模式可随时切换，切回共享时独立库的内容会被保留。

加入会话与群聊

新建会话时，可以让单个 Agent 与你对话，也可以开启群聊让多个 Agent 参与。

在已有会话中，通过对话框左下角的 Agent 选择器可以：

  • 切换 Agent：空白会话可直接更换对话的 Agent；已有内容的会话则以新 Agent 开启一段新对话，原有历史仍归属原 Agent。
  • 添加成员：将其他 Agent 加入当前会话，转为群聊。
  • 移除成员：将成员移出当前会话。

群聊里，每个 Agent 用自己配置的模型作答，气泡上会显示是哪个 Agent 在发言。同一会话里的成员读到的是同一份记录，能看到其他人说过什么。

群聊不使用会话级的模型选择，每个 Agent 都用自己配置的默认模型，因此群聊里不会出现模型选择器。

通道接入

同一种类型的通道可运行多个实例，每个实例可以绑定不同的单 Agent 或整个 Agent 团队，对外呈现为各自独立的助手。

在「通道」页面，为一个已连接的实例设置绑定智能体即可：

  • 第一个选中的是负责人（owner），负责接收这个通道的所有任务。
  • 可以再添加若干成员，负责人会根据成员职责，将合适的任务分配给他们处理。
  • 在通道中通过 @ 加成员名称或 ID，即可直接与某个成员对话。

绑定的改动会即时生效，无需重启通道。支持多实例的通道包括微信、企业微信机器人、钉钉、飞书、QQ、Telegram、Slack、Discord 等。

协作机制

同一会话中的多个 Agent 通过两种方式协作。

1. 通过 @ 指定 Agent

在群聊里，用 @ 加上成员的名字，就能把这一轮交给指定的 Agent 回答。输入 @ 时会弹出当前会话里的成员供你选择，发送后气泡里也会带上被指定 Agent 的头像，标明这轮由谁负责。

2. 主 Agent 与委派

群聊里始终有一个主 Agent（负责人），除非用户 @ 了其他人，任务都由它接收。委派让主 Agent 把不属于自己领域的任务转交给更合适的成员：

  • 决策：主 Agent 收到任务后会自动决策，属于自己领域就直接回答，否则转发给会话里更合适的成员。
  • 执行：被委派的成员在自己的工作空间里完成任务，把结果交回主 Agent。
  • 回复：主 Agent 汇总后统一回复用户，用户始终面对同一个入口。

委派的范围、链路深度、时间预算等细节由 agent_delegate 工具 承载，可在配置中调整。

与子 Agent 的区别

Agent 团队和子 Agent 都能分担工作，但定位不同：

团队成员子 Agent
生命周期常驻，事先配置好为一次任务临时创建，用完即弃
身份有名称、头像，出现在团队列表，可绑定通道匿名，不在列表中
工作空间独立与主 Agent 共享
记忆独立没有自己的记忆
适用场景长期的专业分工、对外服务把自己的活拆开并行、隔离大量中间过程

简单总结：任务本身归属另一个常驻 Agent（拥有对应的知识、权限或客户关系）时用团队协作；只是想把自己的任务拆开并行、加快执行时用子 Agent。
