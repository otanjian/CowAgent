# agent-entry-navigation Specification

## Purpose
定义 Web 控制台中智能体使用入口与配置入口的菜单归属、页面标题及导航兼容行为，使用户可以从工作台使用已配置智能体，并在管理分组维护配置，避免进入使用页时误打开编辑界面。
## Requirements
### Requirement: 智能体使用与配置菜单分离
系统 SHALL 在工作台的「对话」之后、「待办」之前提供「智能体」使用入口，并将既有配置页以「智能体配置」名称放入管理分组的「配置」之后、「技能」之前。其他菜单的归属与行为 SHALL 保留当前有效约定。

#### Scenario: 查看双入口
- **WHEN** 用户在具有现有管理访问资格的模式下展开工作台和管理分组
- **THEN** 工作台显示「智能体」，管理显示「智能体配置」，两项分别打开使用页和既有配置页，均只出现一次

#### Scenario: 单智能体环境
- **WHEN** 当前只有一个可见且启用的默认智能体
- **THEN** 工作台仍显示「智能体」入口并可打开其使用页

### Requirement: 页面身份与导航状态一致
系统 SHALL 使激活菜单、面包屑和页面标题一致区分「工作台 / 智能体」与「管理 / 智能体配置」，并在离开配置页时收起其详情编辑区域。

#### Scenario: 在两个页面间切换
- **WHEN** 用户从「智能体配置」切换到工作台「智能体」
- **THEN** 激活菜单、面包屑与标题更新为使用页身份，配置抽屉不会覆盖卡片列表

#### Scenario: 多语言与窄屏
- **WHEN** 用户在简体中文、繁体中文或英文环境中使用展开、折叠或窄屏侧边栏
- **THEN** 两个入口的标签和提示含义对应各自页面，且均可正常导航

### Requirement: 现有管理能力与内部跳转兼容
系统 SHALL 保留现有智能体配置功能、管理写入规则和内部管理跳转的含义；从聊天选择器发起「创建智能体」仍进入「智能体配置」中的创建操作。

#### Scenario: 从聊天中创建智能体
- **WHEN** 用户通过已有聊天选择器或多智能体对话弹窗点击「创建智能体」
- **THEN** 打开管理分组的「智能体配置」及创建表单，而非工作台使用列表

#### Scenario: 配置保存后再次访问
- **WHEN** 管理用户在迁移后的配置页成功修改智能体名称或职责并重新打开该配置
- **THEN** 原智能体 ID 及配置保持一致，修改结果可见，原有版本冲突处理继续有效

### Requirement: 导航不授予权限
系统 SHALL 保留当前身份模式对管理和运行操作的限制，不能因入口移动或使用页可见而赋予配置写入权限。

#### Scenario: 只有读取资格
- **WHEN** database 模式下用户具有目标智能体读取资格，但对应管理操作未获授权或尚未开放
- **THEN** 使用页不提供创建、修改或删除入口，服务端继续拒绝未经授权的管理调用
