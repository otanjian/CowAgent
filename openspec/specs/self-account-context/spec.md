# self-account-context Specification

## Purpose
规定个人账号菜单通过一个只读接口获取本人全局资料、有效租户及本人成员摘要的最小契约，使普通成员无需管理权限即可查看身份与组织归属。前端按当前租户选择展示对应摘要；身份、成员关系、逐请求授权和会话生命周期仍由既有身份服务负责，不另建身份来源或授权规则。
## Requirements
### Requirement: 有效租户与成员摘要使用真实关系

租户列表 SHALL 仅包含本人当前有效成员关系对应的有效租户，不因平台管理员身份扩大为平台租户全集；每次读取使用当前服务数据。登录、认证检查和本人资料读取涉及租户筛选时 SHALL 复用同一有效租户筛选服务，登录与认证检查不要求返回完整成员摘要。全局显示名 SHALL 与租户成员显示名分开；平台身份来自全局布尔字段，角色来自本人的实际角色关系，部门来自该成员关联的同租户部门，不从姓名推断权限。缺省角色 SHALL 返回 `[]`，缺省部门返回 `null`，缺省成员显示名和岗位返回空字符串；界面将未设置的组织资料显示为「未设置」。这些摘要仅供展示，业务访问仍 SHALL 逐请求授权。

#### Scenario: 有效租户筛选与成员资格变化
- **WHEN** 用户具有有效、停用等不同成员关系，或其成员资格在登录后发生变化，包括平台管理员未加入的租户
- **THEN** 最新本人读取仅返回当前有效关系对应的有效租户，排除停用项及无成员资格项，并与登录和认证检查采用的有效租户筛选规则一致

#### Scenario: 姓名不同或组织资料未设置
- **WHEN** 全局姓名与成员姓名不同，姓名中含管理员称谓，或本人未配置角色、部门、岗位
- **THEN** 响应分别保留两种姓名，实际标记与关联决定身份展示；缺省字段按约定返回，界面显示「未设置」，不编造管理员身份或组织资料

### Requirement: 强制改密仅允许最小身份读取

database 模式的登录和认证检查响应 SHALL 携带 `must_change_password`，使登录及刷新采用一致的限制状态。受限会话访问 `/auth/me` 时 SHALL 仅返回规定的最小 `user` 投影、`must_change_password: true` 和 `tenants: []`，不返回租户或组织详情；登录和认证检查也不得通过租户列表引导其跳过改密。完整门禁和改密流程由 `self-password-flow` 负责。

#### Scenario: 受限账号登录与刷新
- **WHEN** 尚未完成强制改密的用户登录、刷新认证状态或读取 `/auth/me`
- **THEN** 响应明确标识强制改密；本人接口返回必要用户身份和空租户列表，不提供可越过改密步骤的组织信息

### Requirement: 认证失效与服务故障使用真实状态

本人接口 SHALL 通过既有身份服务验证会话与账号；会话无效、过期、撤销或账号停用返回 HTTP 401，身份库不可用返回 HTTP 503。错误 JSON SHALL 至少包含 `status: "error"`、可识别的 `code` 及适合展示的 `message`，与实际 HTTP 状态一致；不得伪装为成功、因状态格式错误产生 HTTP 500，或在故障时降级为 legacy 身份。

#### Scenario: 会话失效或账号停用
- **WHEN** 无效、过期、已撤销会话或已停用账号访问 `/auth/me`
- **THEN** 真实 HTTP 响应为 401，并返回认证失效错误，不返回旧用户或组织资料

#### Scenario: 身份库不可用
- **WHEN** `/auth/me` 无法读取身份数据库
- **THEN** 真实 HTTP 响应为 503，并返回可识别的服务错误，不返回免登录身份或虚构资料

### Requirement: 只读白名单与非缓存边界

`GET /auth/me` SHALL 仅执行读取，不更新账号、组织、AuthSession 当前租户或业务会话。正常与错误响应 SHALL 设置 `Cache-Control: no-store`；成功响应仅使用规定白名单，不直接序列化数据库行，不返回密码及摘要、临时密码、会话凭据、内部存储或工作区路径。浏览器 SHALL 仅在当前页面保留展示资料，不新增持久化用户副本、独立身份缓存或客户端授权依据；每标签租户选择仍属于客户端上下文，不写入 AuthSession。

#### Scenario: 检查读取副作用及资料保存
- **WHEN** 验收者检查本人读取的响应、服务端写入及浏览器存储
- **THEN** 正常和错误响应均有 `no-store`，成功响应仅含白名单字段，读取不修改身份或租户上下文，浏览器没有新增持久化本人资料副本

### Requirement: 本人接口由有效会话确定主体

系统 SHALL 提供 `GET /auth/me`，从当前有效会话确定本人，无需平台管理员、租户管理员或用户管理权限。正常成功响应 SHALL 为 `status: "success"`、`user: {id, username, display_name, is_platform_admin, avatar}`、布尔值 `must_change_password` 及 `tenants: [{id, code, name, membership: {display_name, roles: [{code, name}], department: {id, name} | null, position_text}}]`。其中 `avatar` SHALL 为账号是否已上传头像的标记（已上传时为 `"image"`，否则为 `null`），仅作为前端选择上传头像或默认头像的依据，MUST NOT 包含图片字节或文件路径。接口 SHALL 不依赖 `X-Tenant-ID`，不允许客户端通过用户或成员标识改选读取主体；没有有效租户时返回空列表，附带陈旧租户头不影响全局身份读取。系统 MUST NOT 构造虚假用户、回退免登录身份或保留共享密码语义。

#### Scenario: 普通成员一次读取本人资料
- **WHEN** 无用户管理权限的普通成员持有效且非受限会话请求 `/auth/me`
- **THEN** 接口返回规定的全局账号及本人有效租户成员摘要，前端按当前租户 ID 选取一条展示，无需另请求租户详情

#### Scenario: 客户端指定他人身份
- **WHEN** 请求通过参数或请求头指定另一用户或成员
- **THEN** 接口拒绝该选择或仍仅依据当前会话读取本人，不返回他人资料

#### Scenario: 缺少或失效的租户选择
- **WHEN** 有效用户未选择租户、附带陈旧租户头，或已无任何有效租户
- **THEN** 接口仍正常返回本人全局资料与最新有效列表，无有效租户时返回 `tenants: []`，不将租户选择问题视为退出登录

#### Scenario: 未认证请求
- **WHEN** 未携带有效会话的客户端请求 `/auth/me`
- **THEN** 接口返回 401，不返回任何账号或组织资料

#### Scenario: 头像标记随本人资料返回
- **WHEN** 本人已上传头像或从未上传头像时请求 `/auth/me`
- **THEN** `user.avatar` 分别为 `"image"` 或 `null`，且响应不包含图片字节或文件系统路径
