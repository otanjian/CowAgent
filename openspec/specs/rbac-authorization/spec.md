# rbac-authorization Specification

## Purpose
规定最小企业版本统一授权规则，区分平台管理、租户身份管理和业务读取，以固定权限目录及资源所有者约束支持四个管理页，避免自定义角色提权、前端隐藏代替鉴权或组织信息隐式扩大业务数据范围，并保留可事务验证的管理员连续性。
## Requirements
### Requirement: 平台和租户管理边界

系统 SHALL 将全局平台资格与租户tenant_admin/member分开。平台资格 SHALL 由平台作用域的内置角色绑定承载，与租户作用域的 `tenant_admin`/`member` 分属不同作用域与不同绑定路径，MUST NOT 通过租户角色、成员成员关系或角色权限并集获得。有效平台管理员按系统all经平台入口管理全局账号、租户生命周期及明确目标租户的角色授权和资源分配；平台管理不自动创建Membership或代登录。旧租户身份写接口 SHALL 继续要求当前有效tenant_admin，普通角色不得获得该管理资格。正常租户业务仍验证有效Membership、原资源归属与消费者开放；任何管理员不能因all绕过无有效租户恢复、owner或执行条件。

#### Scenario: 平台管理员使用租户业务
- **WHEN** 平台管理员未加入目标租户却经普通租户入口请求其成员写接口或业务资源
- **THEN** 系统拒绝访问，平台租户管理权限不被解释为业务访问或代登录权限

#### Scenario: 自定义角色尝试身份管理
- **WHEN** 普通成员凭自定义角色请求成员、角色或部门写接口
- **THEN** 系统返回 403，不因其业务权限数量、名称或组织归属授予 tenant_admin 资格

#### Scenario: 租户路径尝试获得平台资格
- **WHEN** 调用者尝试经租户角色保存、成员编辑或成员成员关系变更提交平台内置角色标识或平台身份标记
- **THEN** 系统拒绝变更并按真实身份授权，平台资格不因任何租户域写入而新增、转移或保留

#### Scenario: 管理员访问禁用能力
- **WHEN** tenant_admin 或 platform_admin 在 database 调用尚未开放的运行消费者
- **THEN** 系统保持拒绝，不通过管理员名称或全权限短路绕过版本功能边界

### Requirement: 固定权限目录与最小角色模型

系统 SHALL 使用代码中有限版本权限目录，保留现有九项并按本次登记增加技能、工具、模型、Agent和聊天动作。自定义角色只能选择允许分配的业务功能及同租户资源，不接受平台标识、身份管理资格、未知项和客户端通配符；平台all独立由服务端资格派生，平台内置角色属于独立作用域，MUST NOT 进入租户角色权限并集或作为可分配权限ID。`member`/`tenant_admin` 的显式默认集合按 `business-permission-catalog` 登记，新增权限不自动赋予普通角色。权限蕴含 SHALL 显式登记，功能/资源按当前有效角色各自取并集。

内置角色 SHALL 允许编辑名称、功能权限、资源授权与默认模型，MUST NOT 允许修改角色编码或作用域，MUST NOT 允许删除。编辑内置角色 MUST NOT 改变其身份管理资格（由角色编码派生），MUST NOT 绕过管理员连续性或最后管理员保护。保存内置 `tenant_admin` 时 SHALL 要求其功能权限仍包含 `tenant.info.read`、`tenant.members.read`、`tenant.org.read`，否则整笔拒绝且不落库。自定义角色支持创建、编辑、复制及无成员引用时删除。同租户关联约束、不可编辑数据范围和普通角色不可委派身份资格保持。

#### Scenario: 自定义角色使用允许权限

- **WHEN** tenant_admin 为本租户创建或复制角色并选择目录允许的业务权限
- **THEN** 系统保存合法权限集合，成员后续请求使用所关联角色的明确权限并集；角色不因此拥有身份管理资格或部门范围

#### Scenario: 提交非法权限或修改内置角色

- **WHEN** 请求包含未知权限、通配符、平台权限或 tenant_admin 资格，或尝试修改内置角色的编码/作用域、通过创建接口复用内置编码、或删除内置角色
- **THEN** 系统拒绝整个角色变更，不产生部分授权或隐式管理员角色，内置角色编码、作用域与存在性保持不变

#### Scenario: 编辑内置角色权限并生效

- **WHEN** 租户管理员以当前版本编辑内置角色 `member` 的功能权限并保存
- **THEN** 系统在同一事务内校验权限合法性与版本后落库并写审计，该租户持有 `member` 的成员在下一次请求中按新集合取得有效权限，其他租户的内置角色不变

#### Scenario: 编辑不改变身份管理资格与管理员连续性

- **WHEN** 租户管理员编辑 `tenant_admin` 的功能权限，或成员持有的自定义角色被修改
- **THEN** 身份管理资格仍只由 `tenant_admin` 角色编码决定，管理员数量与最后管理员保护不受权限编辑影响

#### Scenario: 移除管理员最小身份读取被拒

- **WHEN** 保存内置 `tenant_admin` 时其功能权限不再包含 `tenant.info.read`、`tenant.members.read` 或 `tenant.org.read`
- **THEN** 系统整体拒绝该次保存并说明原因，已有集合与版本不变，不产生无身份读取权限的管理员角色

#### Scenario: 平台角色不作为租户权限分配

- **WHEN** 角色保存请求把平台内置角色标识作为权限 ID 或资源授权提交
- **THEN** 系统拒绝整次变更，不将平台角色写入租户角色权限，也不因此产生平台资格

#### Scenario: 删除在用角色或跨租户关联

- **WHEN** 请求删除仍被成员引用的角色，或为成员绑定其他租户角色
- **THEN** 系统拒绝变更并保留原关联，不把其他租户的同名角色视为可替代对象

### Requirement: 服务端统一授权顺序与错误语义

受保护请求 SHALL 依次验证有效认证、接口控制面或可信租户上下文、有效用户及成员/租户状态、所需权限、资源归属和首期入口允许条件。权限与身份每请求从数据库重新解析，客户端角色、权限摘要、菜单状态或对象 ID MUST NOT 取代授权。无有效登录返回 401，非成员或本租户缺权限返回 403，越租户对象与不存在对象一致返回 404；身份库故障返回 503 并拒绝访问，不恢复旧全局路径。所有管理写入 SHALL 在事务提交时重验操作者资格。

#### Scenario: 已撤权会话继续请求
- **WHEN** 已登录成员的角色被撤销后凭旧页面或旧权限摘要请求相关接口
- **THEN** 系统使用当前授权返回 403，旧会话不能延续该操作权限

#### Scenario: 直接访问其他租户对象
- **WHEN** 成员携带合法本租户选择参数但提交其他租户资源 ID
- **THEN** 系统返回与不存在对象相同的 404，不返回目标租户名称、数据或权限详情

#### Scenario: 授权事实不可读取
- **WHEN** 身份库、租户绑定或授权事实不可用或损坏
- **THEN** 系统返回适用的拒绝或 503，不以客户端声明、默认 Agent、缓存权限或 legacy 路径继续访问

### Requirement: 固定个人和租户共享资源策略

系统 SHALL 以可信 Agent 租户绑定及资源所有者实现固定策略，不提供 SELF/部门/CUSTOM 等可编辑范围枚举。私有 Agent 及其资产 SHALL 仅由所有者本人读取、使用和维护；本人所有权 SHALL 作为统一对象授权来源，覆盖读、用、配置、调试、启停以及对本人自建对象的删除，无需逐对象角色 grant，并受当前有效身份、个人能力开放状态和租户策略约束。所有权 MUST NOT 扩大模型、工具、技能等依赖资源的授权，也不授予公共资源维护资格。

所有权的读取、使用与维护资格 SHALL 由 Agent 租户绑定本身派生：判定 SHALL 从既有绑定派生，MUST NOT 要求写入用户级 grant 记录或新增授权载体，该系统内 MUST NOT 存在第二份所有权真相。该派生 SHALL 同时作用于列表投影与发送路径，使同一主体对同一私属智能体得到一致结论。放宽 MUST NOT 扩展到非所有者、MUST NOT 扩大到共享 Agent 的同类维护动作或公共资源、MUST NOT 跨租户匹配。

明确租户共享的 Agent 资产 SHALL 继续按成员有效功能和资源授权开放。会话、消息、runs 和个人记忆 SHALL 额外校验个人 owner 及租户；tenant_admin 或平台 all MUST NOT 绕过本人私有内容边界。管理员的资源归属、数量、状态和用量治理投影 SHALL 与私有配置、正文和凭证分离。部门或岗位变更 MUST NOT 扩大资源权限，历史或缺失归属不得自动视为共享；列表、检索、总数和分页 SHALL 先授权再计算。

#### Scenario: 共享 Agent 中的个人会话
- **WHEN** 两名成员均可查看租户共享 Agent，且各自拥有会话记录
- **THEN** 普通成员仍仅能读取本人会话、消息和 runs，Agent 共享不使另一成员的个人历史可见

#### Scenario: 私有资产或组织变化
- **WHEN** 成员获得业务读取权限或被移到其他部门，但目标资产仍属于他人的私有 Agent
- **THEN** 组织和角色读取权限不绕过所有者策略，只有所有者本人在满足有效身份及相应动作条件时可读

#### Scenario: 列表分页与缺失归属

- **WHEN** 用户检索包含不可见资源的列表，或遇到未绑定 Agent、无法确定所有者的历史个人资源
- **THEN** 列表与总数仅统计授权资源，缺失归属的资源被拒绝而非当作租户共享返回

#### Scenario: 所有者无需逐对象维护 grant

- **WHEN** 有效 member 维护本人私有 Agent，但角色没有该对象的编辑或启停 grant
- **THEN** 在本人能力开放且租户策略允许时可以维护，不向其授予共享 Agent 的同类动作

#### Scenario: 管理员身份不授予私有内容

- **WHEN** 非 owner 的 tenant_admin 或平台管理员请求成员私有 Agent、会话、记忆或核心文件
- **THEN** 私有内容访问被拒绝，管理者只能通过获准治理接口查看必要的脱敏元数据

#### Scenario: 所有者仅持功能权限即可读可用

- **WHEN** 成员持有 `agent.read` / `agent.use`，其角色未携带任何 `agent:<id>` 资源 grant，而被请求的私属 Agent 的 `private_owner_user_id` 正是该成员
- **THEN** 该私属 Agent 对其出现在可见列表中且可发起会话，列表投影与发送路径给出同一结论，不出现「列表可见但发送被拒」或「有权限却不可见」

#### Scenario: 他人私属资源不放宽

- **WHEN** 成员请求同租户内 `private_owner_user_id` 为**他人**的私属 Agent，且其角色未携带该 Agent 的资源 grant
- **THEN** 该请求被拒绝且该 Agent 不出现在其列表中，不因请求者本人也拥有某个私属 Agent 而放行

#### Scenario: 写动作不随所有权放宽

- **WHEN** 私属 Agent 的所有者本人尝试编辑、调试或启停该 Agent，而其角色未携带该 Agent 的 `edit` / `enable` 资源 grant
- **THEN** 该维护动作在有效身份、个人能力开放状态与租户策略允许时放行，且 MUST NOT 因此获得共享 Agent 的同类动作资格

### Requirement: 页面能力与接口使用同一授权规则

管理菜单 SHALL 保留原内部标识兼容并遵循正式导航结构，依据菜单/页签授权或平台all、功能读权限及真实开放状态展示；普通成员按对应读取与资源范围查看，租户身份写由tenant_admin执行，平台身份可经明确目标平台入口管理。前端仅用能力改善交互，接口独立鉴权；目录/配置/执行分别报告可用性，403、身份或目标变化后刷新能力，保存失败不得显示成功。隐藏菜单不能替代后端关闭，也不阻止在获准业务中使用已分配模型。

#### Scenario: 普通成员查看允许目录
- **WHEN** 普通成员打开用户或组织菜单且具有相应读取权限
- **THEN** 页面只提供当前租户允许的名录读取，不出现身份管理写操作或其他租户列表

#### Scenario: 绕过隐藏按钮调用接口
- **WHEN** 既非有效 tenant_admin、也未经合法平台目标管理入口的调用者手工提交成员、角色或部门修改
- **THEN** 服务端返回 403 且无数据变化，页面是否显示按钮不影响结果

#### Scenario: 权限变化后界面处理
- **WHEN** 已打开页面的管理权限被撤销，或当前租户切换后原操作不再允许
- **THEN** 页面刷新能力并正确展示拒绝结果，不保留可执行旧操作的假象或显示虚假保存成功

### Requirement: 角色写事务审计与管理员保护

角色和成员授权修改 SHALL 提交 expected_version，并在同一 SQLite 写事务重验权限、版本、同租户关联、内置角色保护及最后管理员条件，再与脱敏 audit_events 共同提交。实例 SHALL 至少保留一个有效 platform_admin，每个 active 租户至少保留一个有效 tenant_admin；全局账号停用、成员停用及角色降权均不得绕过该约束。过期版本返回 409，审计插入失败回滚变更并返回 503。权限拒绝亦 SHALL 记录脱敏拒绝事件；身份审计仅供平台或本租户管理员在授权范围内查询，不建设投递队列或跨服务审计事务。

#### Scenario: 并发修改角色或撤销管理员
- **WHEN** 两个请求以相同角色版本修改授权，或并发减少仅剩管理员
- **THEN** 版本冲突或管理员连续性检查阻止冲突提交，最终权限不被旧内容覆盖且有效管理员约束始终成立

#### Scenario: 审计持久化失败
- **WHEN** 角色创建、成员角色变更或管理员降权无法追加同事务审计
- **THEN** 系统回滚角色与关联修改并返回 503，不留下缺少可靠成功记录的授权变化

#### Scenario: 受限审计查询
- **WHEN** 租户管理员查询身份授权事件及权限拒绝记录
- **THEN** 系统仅返回本租户脱敏事件，不包含其他租户信息、密码、哈希或令牌；重启和恢复后已提交事件仍可查
