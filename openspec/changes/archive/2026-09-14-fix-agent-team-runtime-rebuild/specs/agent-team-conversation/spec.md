## ADDED Requirements

### Requirement: 会话运行时装配跟随当前团队名册

团队会话的运行时可装配输入 MUST 与当前团队名册一致。系统的 Agent 运行时（工具集与系统提示词）SHALL 反映该会话此刻的 `members`：当名册发生变化时，该会话全部参与者的缓存运行时 SHALL 被退休，使下一轮消息按新名册重建。名册未发生变化时，系统 MUST NOT 退休任何仍在使用的运行时。退休运行时 MUST NOT 丢弃已持久化的对话历史——重建 SHALL 从会话存储恢复。

「参与者」SHALL 包含会话 owner 与旧名册、新名册中的全部智能体 id。名册中出现未知或已归档的智能体 id 时，驱逐失败 MUST NOT 使设置写入整体失败。

#### Scenario: 会话创建后邀请同事，交办工具随之可用

- **WHEN** 一个单人会话已经完成首轮（其运行时按单人装配，未含 `agent_delegate`），随后用户把另一位已启用智能体加入 `members`
- **THEN** 该设置写入成功，且该会话参与者的缓存运行时被退休，下一轮消息由按新名册重建的运行时处理，其工具集包含 `agent_delegate`，系统提示词列出新同事

#### Scenario: 移除成员后恢复单人装配

- **WHEN** 一个团队会话的 `members` 被清空或移除至只剩 owner
- **THEN** 参与者的缓存运行时被退休，下一轮重建为单人装配（不再包含 `agent_delegate`）

#### Scenario: 重复保存同一份名册不重建

- **WHEN** 用户重复提交与当前存储完全相同的 `members`（元素集合相同，邀请顺序可不同）
- **THEN** 不发生名册变化，热运行时及其内存消息被保留，不触发重建

#### Scenario: 不含 members 的设置写入不影响运行时

- **WHEN** 设置写入只包含模型或权限字段，不含 `members`
- **THEN** 不退休任何运行时，既有热运行时继续服务下一轮消息

#### Scenario: 名册含有无法解析的 id 时写入仍成功

- **WHEN** `members` 中出现已归档或未知的智能体 id
- **THEN** 设置写入仍返回成功，可解析的参与者照常退休，无法解析的 id 被跳过且不抛出错误

#### Scenario: 重建不丢失对话内容

- **WHEN** 因名册变化退休了某会话的运行时
- **THEN** 该会话已持久化的历史消息在重建后恢复，用户可见的对话内容不因重建而丢失
