## Context

动机和范围见 [proposal.md](proposal.md)。本设计以 2026-09-15 当前工作区主规范和源码为基线，包含其他工作的未提交改动；本轮产出规划，不代表已部署或已验收。

| 接入点 | 已核对的现状 | 本 change 的职责 |
| --- | --- | --- |

## Goals / Non-Goals

**Goals:**

- 相同状态和对象范围下，成员与管理员共用字段、动作、状态机、错误契约和真实运行链路。
- 一处计算合法数据范围，列表和对象写入均消费它；不通过可见菜单或客户端 owner 字段推导授权。
- 已有资源、用户偏好、外部身份、凭据与记忆索引只有一份真值；旧入口只转接到正式服务。
- 文档清楚记录从旧个人控制台方案到本方案的替代关系和真实交付边界。

**Non-Goals:**

- 不开放组织与权限、公共配置或平台运维给普通用户；这些是用户确认保留的管理职责。
- 不恢复“我的资源”、个人控制台、个人/租户两个渠道工作台、角色专属简化表单或第二套 CRUD。
- 不新增可编辑 SELF/部门/CUSTOM 数据范围模型，不改变聊天工作台对已授权共享智能体的使用规则。
- 不重建身份、业务 session、Agent Registry/Bridge、ExecutionRun、scheduler 或渠道提供方适配器。
- 不复制或删除历史用户数据，不将归档或模拟测试视为真实渠道、Desktop 或隔离验收。

## Decisions

### D1. 共用现有页面和正式业务契约

保留 `/admin` 及 `agents`、`memory`、`channels`、`skills`、`config` 等现有 view。进入资格由有效身份、当前租户、至少一个获授权正式业务页面决定，不再单独要求 tenant_admin。组织与权限的三个页面继续检查管理资格；平台菜单继续检查平台资格。模型服务在同一页面展示获授权目录，公共配置区域继续检查对应管理资格。

前端不按成员身份切换到 `personal-console.js`，不增加个人页签。每项功能共用组件和请求契约，按钮基于后端对象动作投影。管理员和成员在相同归属、授权、对象状态下获得相同结果；同一对象的所有者换成另一角色的本人时，操作能力也应一致。普通用户尚无对象时仍可进入有创建资格的页面，不用“已有可读对象”阻断首次创建。

正式业务接口：智能体沿用 `/api/agents`；记忆沿用 `/api/memory`、`/api/memory/content` 并补共用管理动作；消息渠道沿用 `/api/tenant/channels` 及其对象子资源，`tenant` 表示业务租户边界而非管理员资格；工具/技能沿用 `/api/tools`、`/api/skills*`。模型目录与公共配置操作分别鉴权，共用页面不把 `/api/config` 变成成员接口。

只改菜单会留下管理员专属写入和个人运行分支；复用个人页面会保留用户明确否定的两套功能，因此本设计收敛到现有正式页面和业务链路。

### D2. 可信对象范围统一覆盖读写

服务端从已验证会话、当前有效 Membership、当前租户管理资格及资源真实归属构造操作范围，客户端只能指定目标，不能授予 scope/owner/tenant。先限定集合再计算总数、分页、搜索和首页指标。单对象读取、修改、删除、复制来源、预览和实际执行重验同一边界。

| 对象 | 普通用户 | 租户管理员 |
| --- | --- | --- |
| 智能体管理 | `tenant=T AND owner=U` | `tenant=T AND (owner IS NULL OR owner=U)` |
| 用户记忆 | `tenant=T AND user=U` | 同左，不能浏览其他用户记忆 |
| 智能体记忆 | 当前租户本人私有智能体 | 当前租户共享智能体及本人私有智能体，另验实际根归属 |
| 渠道连接 | `tenant=T AND scope=user AND owner=U` | 当前租户公共连接及本人连接；他人连接只在既有治理职责中提供有限元数据 |
| 工具/技能/模型 | 当前租户获授权目录及本人可维护配置 | 同一功能；公共维护另验管理资格、功能权限及资源范围 |

平台管理员在普通业务页面也受所选租户及私有 owner 约束；明确跨租户管理仍从独立平台职责入口执行。普通用户不能因为自定义角色含某个公共编辑 grant 就修改公共定义；公共写入同时要求对应管理资格。所有权检查先于管理员/all 例外，治理元数据不能混入私有配置列表。

权限撤销、成员失效、租户切换后下一次操作重新判定。使用已有 401/403/404/409/503 契约，跨用户、跨租户和不可见对象不能通过错误、计数或状态字段探测内容。保存必须在事务提交前复核归属和版本，不能依赖列表时的快照。

### D3. 智能体统一生命周期

合并现有管理与私有生命周期的创建、配额预占、模板隔离、工作区初始化、补偿、审计和引用检查。保留同一创建表单，归属选项由服务端给出：普通用户只有“本人私有”，管理员可选本人私有或租户共享，既有管理员默认共享保持。owner 一律由当前身份生成，不允许表单指定另一用户。普通用户创建租户首个对象仍为本人私有，不触发首个共享默认规则。

管理列表包含可管理的停用对象，便于重新启用；聊天列表只保留适合使用的对象。系统供应来源是对象事实：专属助理、未知历史来源和实例模板的保护对所有角色一致，不能管理员作为 owner 可删而普通 owner 不可删。可删除对象的运行/渠道引用冲突、清理失败恢复及默认指针清理也走共用规则。系统来源保护不等于对成员另造功能开关。

模板复制仍校验合法来源；不能复制他人记忆、会话、凭据或绕过模型、工具、技能授权。本人知识模式等字段继续使用现有编辑器及实际数据根判定。

### D4. 用户默认与租户默认明确分开

同一详情页「设为默认」统一提交 `/api/agents` 的 `action=set_user_default`，主体固定为当前 tenant/user，不接受代设用户 ID。普通用户候选是本人可管理且可使用的私有智能体；管理员候选是其可管理且可使用的共享或本人私有智能体。保存和每次解析均验证注册存在、租户绑定、owner、启用及使用资格，失败不改变当前值。

复用 `memberships.default_agent_id`，新增 `default_agent_version` 独立乐观锁，避免与成员管理编辑版本互相冲突。请求携带版本；同一目标重试在重验授权后幂等返回，竞争更换目标只有一个成功，另一个 409。偏好和 `member.set_default_agent` 审计在同一事务提交；客户端只在成功后更新标识。

系统供应成功仅在默认尚为空时原子初始化，不能覆盖已有偏好或与用户提交竞态互相覆盖；来源判断仍取 `agent_bindings.origin`，不根据默认字段倒推系统助理。

新会话缺省解析为：有效用户默认 → 本人可用的租户共享默认 → 当前租户已获准共享智能体的稳定候选 → 当前租户本人可用私有智能体的稳定候选。整个候选池先做真实使用授权，完全无可用项时拒绝；不能从租户所有私有对象中任选。解析为只读，停用偏好可保留但显示失效及实际回落来源；删除清理对应指针。已建立 session、显式选择和渠道显式绑定不随偏好改变。

租户默认留在明确标为“租户默认智能体”的管理配置中；旧 `action=set_default` 保留管理员租户动作兼容，并以明确结果字段标示租户范围，不能把旧请求静默解释成用户偏好。任命只接受已共享目标，不清除 owner。迁移若发现租户默认指向私有对象，先记录修复报告再清除该非法租户默认指针，保留私有归属与用户偏好，按合法共享候选回落。

### D5. 记忆统一管理而不混并存储根

同一记忆页面提供现有类别、列表、内容和适用的编辑/删除/清空操作，目标选项是服务端过滤后的记忆资源。普通用户只能选择本人用户记忆及本人私有智能体记忆；管理员额外选择获准共享记忆。目标选择是同一组件的数据，不增加独立个人页签。系统生成的只读类别，对所有角色都按相同类别规则处理。

统一记忆服务内部按目标真实归属解析 tenant/user 或 tenant/agent 根，吸收既有读写逻辑，不复制第二套存储实现。路径校验、版本、generation、索引屏蔽/重试和后台固化在所有入口保持一致；清空所选目标不能变成清空整个租户。`/api/memory/personal*` 只作参数转换和正式服务委托，不保留独立动作/功能开关。共享目标的写入须有管理资格，普通用户即使获准与共享智能体聊天也不能由此管理共享记忆。

### D6. 渠道统一接入和运行，归属只形成资源边界

同一消息渠道页面使用现有卡片、字段、扫码和手工提交；没有个人/租户双工作台。新增表单的 Agent 候选按管理集合和 use 条件过滤：本人私有目标创建本人连接；管理员选择共享目标创建租户公共连接。管理员保留公共连接“不指定，使用租户默认”的选项，普通用户没有该候选。连接归属由目标和管理资格派生，更新既有实例不得通过改绑自动改变 scope/owner；管理员作为 owner 维护本人连接时遵守同一私有目标规则。

手工、扫码自动保存、改绑、启用和启动恢复都调用同一实例领域服务。个人连接不再有专属提供方适配器、角色专属简化功能或第二套字段校验。扫码会话绑定发起会话、用户、租户、目标和服务端确定的归属；目标改变或上下文切换使旧扫码授权失效，不自动跨范围转用。提供方协议差异仍可决定扫码能否自动提交，这种差异对两种角色一致。

运行走同一连接管理与入站流程。实例所属租户是路由锚点，私有目标只有已验证 owner 的允许会话可达，共享目标按现有成员/会话规则执行。这是资源访问条件，对管理员本人私有连接同样适用，不由“创建者是否普通用户”选择运行实现。保留治理停用、凭据撤销和身份解绑的生效条件；未绑定或失效私有目标不得回落公共默认。

目录与提供方运行接受状态由同一注册及实测结果投影，不把原空的个人验收集合直接扩成已验收。合并后的首批运行需证明同一提供方在公共/本人私有两种合法归属下均正确处理；没有证据的具体资源/传输条件如实关闭，不能标为整个普通角色永远不可运行。纯配置阶段不宣称整个 change 功能一致性已验收。

### D7. 旧入口、菜单及开关的有序收敛

`personal-agents → agents`、`personal-memory → memory`、`personal-channels → channels`、`personal-tools/personal-skills → skills`；旧链接保留可解析对象和原 tenant/user 约束，经过离页确认和新页面授权再提交正式地址。越界对象拒绝，不改指向其他默认。账号菜单不恢复业务资源。

`nav:personal.*` 映射到相应正式页面 grant，工具/技能共用页面但页内资源仍各自鉴权。只迁移当前存在的旧 grant，不重置权限、不按角色名重建已有角色。删除别名 grant 前事务性保留映射结果；重复执行幂等；不删除共享后仍需要的目标 grant。新租户默认按统一正式页面初始化。存量“从未有个人或正式授权”的自定义角色不自动加权；无法区分用户主动撤权与旧默认缺项时保留限制并在迁移报告列明，由既有授权管理决定，不猜测授权。

旧个人 API 在一个兼容发布周期内只转换请求/响应并委托统一服务，仍验证原目标范围；正式页面不调用旧 API。期满移除前依据调用记录确认客户端迁移，并明确废弃响应；移除不得删除旧对象、记忆或凭据。

不新增成员专属开关。旧 `member_personal_console`、`user_private_agent_management`、`personal_memory_write`、`personal_channel_onboarding`、`personal_channel_runtime` 在迁移期仅作为旧入口的收窄兼容约束；统一路径采用共用功能/提供方状态。显式关闭值先保留为对应对象范围的部署限制并列入迁移报告，不能借新入口绕过旧关闭意图；管理员维护相同归属对象也受相同限制。历史默认关闭且缺乏真实执行证据的范围仍未验收；达到门槛后通过统一配置显式启用。完成迁移后移除旧键的运行读取，不能永久形成两套准入。

### D8. 首页、公共配置与兼容客户端

首页使用同一布局，普通用户仅取得本人可见智能体、连接及本人消息等指标；成员数、组织信息和公共运行细节只对管理资格开放。统计由数据层限定，不能先下发全租户统计再由前端隐藏。无管理权限时不请求其数据源。

公共工具/技能定义、公共模型服务地址和密钥、系统设置继续按对应管理资格保护。个人参数作为同一资源配置组件中允许修改的字段，不形成另一产品页。模型读目录不回显公共凭据；实际 use/execute 继续验证资源授权。Web、共享壳与受支持 Desktop 消费者使用相同契约；原生 Desktop 登录/传输尚缺证据时单独记录，不对外宣称已通过。

## Risks / Trade-offs

- 旧规范刚归档、部分历史 change 未合入主规范 → 增量只匹配当前主规范 requirement；历史 archive 不改写，独立列出取代关系，实施前复核共享文件差异。
- “共用功能”被实现成只替换菜单 → 双角色用同一对象条件的端到端用例比较字段、动作、网络契约和运行状态，并检查正式页面不加载个人实现。
- 旧默认动作泄露私有对象 → 新用户默认用独立动作，旧租户动作拒绝私有目标；启动校正也不能清除 owner。
- 合并渠道路径误恢复未验收连接 → 先登记并验证真实归属/提供方矩阵，配置保存与可运行状态分别显示，恢复时重验实例与发送者。
- 菜单多对一和自定义撤权被覆盖 → 逐条旧 grant 映射、保存迁移清单、重跑验证，不把没有授权当成默认同意。
- 记忆和凭据并发写入跨越迁移 → 维护窗口或写入收敛后升级，保留原版本/索引恢复记录，禁止两套服务同时写不同真值。

## Migration Plan

1. 盘点版本、菜单、自定义角色、私有 owner、来源保护、默认指针、实例归属、旧开关和仍使用旧 API 的客户端；备份身份库、资源配置与记忆状态，输出预演报告。
2. 增量迁移增加默认偏好版本及菜单映射/迁移记录，迁移号从当前 schema 尾部追加；保留所有业务 ID、owner、scope、凭据版本和记忆根。对非法租户默认做不共享私有对象的修复。
3. 先落实统一对象授权与领域服务，再接正式页面；旧 API 变为薄适配。统一页面未就绪前不放开管理员壳入口，避免到处 403 或读取未过滤数据。
4. 验收授权/版本/审计和双角色功能一致性后开放入口、智能体/默认、记忆及渠道配置；提供方真实运行按依赖门槛单独启用并明确交付状态。
5. 保留一个兼容发布周期，完成旧菜单、URL/API、开关迁移；正式入口只调用新统一契约，历史文档注明取代状态。
6. 回退优先暂停本次新增入口或受影响共用动作并停止相应连接，保留数据范围与 owner 校验、偏好版本和撤回操作。不能降级到忽略 user scope、允许默认转共享或失去记忆版本保护的旧构建；需要恢复旧数据版本时只使用一致备份并先停写/停连接。

### 分阶段门槛

| 阶段 | 启动前置与验收证据 |
| --- | --- |
| 授权与迁移 | 主规范/源码基线、现有凭据/审计/配额切片；多租户多用户直调与迁移幂等、失败重试 |
| 正式控制台与智能体 | 统一范围拒绝证据；真实 HTTP 及浏览器共用表单、创建、启停、来源保护和删除冲突 |
| 用户默认 | 双用户双租户、供应竞态、偏好并发、旧默认兼容、会话/渠道不被重绑 |
| 记忆管理 | 路径归属、版本与 generation、索引失败/重启恢复及普通用户共享写拒绝 |
| 消息渠道配置 | 唯一实例服务、密文和审计原子性、扫码目标绑定、重复应用及配额竞争 |
| 消息渠道运行 | 实际提供方往返、owner/其他发送者/群聊、停用撤权、启动恢复及适用审批/隔离；模拟不足以启用 |
| 最终交付 | Web 功能一致性矩阵、旧入口转接、菜单与开关迁移、回退演练、文档和严格规范校验 |

实施参数仅包括与发布节奏匹配的兼容周期日期、首批具备真实测试凭据的提供方及部署配额数值；不改变上述业务规则，不能以参数未确定为由恢复两套产品功能。
