## Context

本次完成角色分配菜单、技能、工具、模型、智能体，以及平台管理员默认all。2026-09-09复核取舍见review.md；与前期docs/design/role-resource-authorization-plan.md不同之处，以本change为实施范围。

现有roles.permissions_json/version、IdentityService角色CRUD、SQLite事务、审计和schema_migrations均可扩展。资源继续来自导航登记、技能管理器、ToolManager、模型配置和Agent Registry。OneAgent的集中过滤和模型解析值得参考，其用户匹配、优先级和独立策略存储不是此次角色分配的必要条件。

## Goals / Non-Goals

**Goals:** 五类资源显式分配、多角色允许并集、动态平台all；配置/页面/实际调用共享授权；复用现有角色界面、接口及存储，保持成员有效租户和原owner。

**Non-Goals:** 独立IAM、资源索引数据库、fixed/priority策略、个人例外、deny/继承/部门授权、独立成员权限预览中心、全量平台成员/组织CRUD、新导航布局。database Web聊天、流/轮询/取消及其他客户端开放另立change；本次仍须把守卫接到现有实际分发位置，不能仅做前端勾选。

## Decisions

### 1. 平台all和租户边界

每次从可信User.is_platform_admin派生authorization_mode=all，自动覆盖未来已登记功能和资源。普通角色只存明确权限及资源ID，禁止保存通配符、all或平台身份。all跳过功能及资源分配限制（包括租户分配上限），不跳过真实归属、账号/租户有效、强制改密、owner、Agent能力限制和消费者开放检查；未知资源仍拒绝。

资源状态按动作校验，停用禁止执行，但合法查看、编辑和重新启用仍可进行，不能用执行条件阻断维护。

每个启用账号含平台管理员至少有一个有效Membership且对应Tenant有效；正常租户业务必须加入该租户，不伪造默认租户或代用他人会话。原tenant_admin/member业务默认九项/七项不自动扩充。

平台跨租户管理本次只增加目标租户角色和全局资源分配入口，共用原服务并在事务内验证平台资格、目标与审计，不创建虚假tenant_admin。既有账号、成员和组织接口保持原合同，不为all复制整套管理API。平台自身all与被编辑普通角色严格分开：替租户角色保存仍须满足该角色所在租户的资源上限。

### 2. 两张关系表，目录按需读取

| 存储 | 用途与约束 |
| --- | --- |
| 新增tenant_resource_grants | tenant_id/resource_kind/resource_id/action唯一；平台给租户开放的全局资源/动作 |
| 新增role_resource_grants | role_id/resource_kind/resource_id/action唯一；角色外键确定租户，事务校验资源范围 |
| 新增roles.model_defaults_json | `{capability: model_resource_id}`，可空，跟随原角色version |

不建resource_catalog或model_policies表，不加授权revision。租户上限整体保存复用tenants.version，同事务更新版本/审计，接受与租户资料编辑发生正常409冲突；角色授权整体保存复用roles.version。

目录由原来源按需投影非敏感元数据，不复制配置和凭据。菜单/页签沿用登记ID；Agent沿用原ID与唯一租户绑定；技能用来源命名空间＋来源内稳定键，区分内置与租户实例；MCP工具用连接ID＋工具名，内置工具用builtin命名空间。模型用供应商配置稳定ID＋模型代码＋能力；缺ID时只在原配置补元数据。

显示名称变化不影响ID；无独立ID的来源键变更视为新资源，须重新分配。同一逻辑键的内容升级仍属同一资源，授权不是内容版本锁；不同来源不得复用该键。删除或解析失败使引用失效，不按显示名寻找替代品。

租户自有资源上限来自原归属；全局技能、模型、工具/MCP等由平台显式分配；菜单上限来自页面作用域，平台菜单不能分给普通租户角色。普通成员的功能集合、资源集合分别按多角色取并集，再与租户上限、归属和执行条件相交。历史、待办、记忆不新增grant。

### 3. 共用授权函数与现有角色接口

在auth域增加共用判断及批量过滤函数，复用IdentityService/RuntimeIdentity，无需插件式策略引擎。原九项外登记skill.read/use/edit/enable、tool.read/execute/configure、model.read/use、agent.use/edit/enable、chat.use十三项动作；管理不隐含执行，普通权限不产生身份管理员资格。

| 接口 | 处理 |
| --- | --- |
| 现有GET/POST /api/tenant/roles、POST /api/tenant/roles/{id} | 扩展resource_grants、model_defaults，一次保存，不另建authorization写接口 |
| 新增GET /api/tenant/authorization/catalog | purpose=assign仅管理员；purpose=use返回本人业务资源最小投影；参数白名单、先过滤后分页 |
| 新增/api/platform/tenants/{tenant_id}/roles[/{id}] | 平台目标薄层适配，共用角色服务/请求体，列表/创建/更新/删除沿用租户角色方法 |
| 新增GET /api/platform/tenants/{tenant_id}/authorization/catalog | 同一目录实现的目标管理投影，不改变业务租户 |
| 新增GET/PUT /api/platform/tenants/{tenant_id}/resources | 整体保存全局资源上限，使用租户expected_version |
| 现有/auth/context | 补authorization_mode及逐页/页签能力，不加revision或全量资源列表 |

assign与use分别鉴权。有使用权但无管理读取权时，选择器仅返回ID、名称和能力，不提供配置或技能正文。不另建/api/me/resources或成员有效权限预览接口。

角色更新的新增字段**省略表示保留，显式空集合/空对象表示清空**；创建省略为空。旧客户端改名称/功能不能抹掉资源分配。expected_version覆盖整个角色，功能变化后也重验模型默认值一致性。复制走现有创建，不复制系统资格。

同一写事务内重验操作者、目标、上限、引用、版本、内置角色、最后管理员及成员归属约束，再保存并审计，失败全部回滚。源文件不能和SQLite原子提交，保存及实际使用分别重新解析；来源服务失败拒绝，不能当空目录覆盖选择。

沿用401未认证、400参数/需选择、403无动作资格、不可见对象404、409版本/关联冲突、503权威服务不可用。有功能权限但目录无可见条目返回空列表，不泄露不可见对象是否存在。

### 4. 原角色页面增加资源选择区

保留列表、编辑、成员关联和复制。功能及五类资源按现有组件分组或页签展示，不强制新建七页流程；搜索/分页保留草稿，一次保存，普通全选存具体ID。平台自身显示只读all，编辑目标普通角色仍显示有限选择。

首期预览限当前角色草稿：已选数、缺少动作、失效资源、超出上限、执行未开放。明确提示成员权限由所有角色合并，不把单个角色选择称为成员有效权限，不建成员权限解释系统。依赖缺失可提示，不能暗中附赠授权。

菜单可达需menu:view或all、页面读取资格、真实开放状态共同满足；父项由可达子项生成，侧栏/hash/首页/页内入口共享投影。业务API不要求相应管理菜单。保持三语、键盘/窄屏、未保存保护、并发冲突及迟到响应保护。

### 5. 现有调用点接守卫，不扩建运行协议

技能读取/正文/维护按独立动作鉴权，装配/动态加载按skill.use与Agent选用范围相交。旧过滤器会把空列表归一为None，新路径必须保留空集合为无技能。技能接口增加resource_id定位；name兼容仅限当前范围可唯一解析对象，歧义返回400，不按覆盖顺序猜测。写回保持expected_mtime与原文件边界。

目录过滤、提示词装配和动态加载贯穿同一来源对象；不能按resource_id鉴权后再仅用name查找另一个覆盖实例。现有管理器只暴露覆盖结果时，先明确可操作来源，不能把另一来源的grant用于该结果。

工具目录、配置、schema、实际分发分别检查；真正调用前验证tool.execute，覆盖override、MCP和代理分发。技能文字和模型输出不赋权。Agent读/编辑/启停/启动/恢复/委派分别检查动作、原绑定及owner，委派继承调用者，不采用目标作者身份。

首期不缓存跨请求授权结论。单个列表请求批量读角色/grants并过滤，避免逐项查询；每次实际工具或模型调用重读当前身份、授权和资源状态。既有Agent/模型/schema缓存不能充当授权凭据或带入另一user/tenant的裁剪结果，按当前调用重建授权视图。撤权阻止尚未开始的后续步骤，不声称撤回已发生副作用。

database关闭入口继续关闭。对真实装配/分发组件，用真实身份库及受控本地工具/模型替身集成验证是否实际调用和目标；此证据证明守卫接入，不是线上Web聊天验收。后续开放仍按正式tenant-resource-isolation验证身份、凭据、审批、配额与隔离。

### 6. 模型仅允许集合与可选默认值

允许集合与租户上限、配置状态、能力及Agent限制相交，默认值不授予使用权。每角色每种已接通能力最多一个默认值，保存时该角色必须具备model.use功能及该模型use grant。

选择顺序：合法显式会话选择→当前有效角色唯一默认值→已有Agent/租户/平台默认链中的合法候选。多个角色默认相同可合并；不同则不设优先级，继续已有合法默认链，仍无候选返回model_selection_required。普通角色不设默认时沿用原流程并过滤；显式越权或失效持久选择必须说明，不静默改投。

平台all使用显式选择或现有默认链，不受普通角色默认值强制限制。需要成员只能用一个模型时，确保其所有角色合并后仅允许一个该能力模型；单角色只选一个不抵消其他角色授权，不能宣称等同跨角色fixed策略。

会话模型保存、初始化、Bridge、摘要/子智能体、重试/fallback均验证最新允许集合；仅回退至已配置、获准且能力兼容的模型。无候选或服务失败明确拒绝，不回退未授权全局模型。只处理现有能力，凭据仅服务端解析。

### 7. 一次迁移与明确交付范围

维护窗口复用schema_migrations：只读预检→备份→显式授权映射及结构迁移→启动带守卫版本。预检失败阻止升级，不增加staged/enforced开关或混合运行状态机。新库使用同一结构及最小授权。

保留旧合法菜单/资源读取时，预检输出具体grant及必要只读兼容自定义角色和成员关联，由迁移操作显式应用；兼容角色只表达新增read，不自动授予edit/use/execute。已有功能选择保持；关闭执行不视为既有授权。内置角色继续只读，需要业务能力时绑定普通自定义角色。平台all无需生成grant。

迁移标识与守卫同版本生效。已升级实例只运行理解新授权的兼容构建，或停机恢复一致备份，不能仅回旧代码忽略授权。UI布局开关不影响后端规则。

完成要求：角色配置及平台目标API、五类授权、技能写拆分、实际分发守卫、模型集合、菜单、迁移和回归全部通过；原关闭入口仍有拒绝验证。不等待另一个运行开放项目，说明实际可用入口及组件集成证据。

## Risks / Trade-offs

- 按请求读取先保证一致性，实测性能问题出现后再加缓存，不预建多层版本失效体系。
- 来源键变化需要重新分配，不承诺跨任意改名/安装保持授权。
- 多角色模型默认冲突可能需要选择，避免难理解的优先级规则。
- 角色分配完成不表示database聊天可用，运行交付须另行规划。
