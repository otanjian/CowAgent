## Goals / Non-Goals

**Goals:** 用户能预览并选择背景风格，立即感知结果，刷新保持选择，随时恢复默认；同一外观在公共框架、对话首页和本次面板中一致；旧用户保留熟悉的配色。

**Non-Goals:** 任意颜色编辑、图片背景、主题商店、云端同步、租户默认主题及全站样式重构不进入本期。追加的首页布局属于第 6 节显式范围，不改品牌名称/Logo来源、业务API或现有菜单路由权限。

## Decisions

### 1. 配色与明暗独立，使用三套内置预设

外观面板先选择“配色方案”，再选择“明暗模式”。三套预设均提供浅色与深色值，“跟随系统”只解析明暗，不擅自改变用户所选配色。

| 预设 | 标识 | 浅色时的主要颜色 | 深色时的主要颜色 |
| --- | --- | --- | --- |
| 商务青蓝（推荐） | `business` | 侧栏 `#F6F8FA`；顶栏/卡片 `#FFFFFF`；内容背景 `#F8FAFC`；强调 `#087CA8` | 侧栏/顶栏 `#17212D`；内容背景 `#121A24`；卡片 `#1A2634`；强调 `#55C6EE` |
| 深蓝侧栏 | `slate` | 侧栏 `#18232F`；顶栏/卡片 `#FFFFFF`；内容背景 `#F8FAFC`；内容强调 `#087CA8`，侧栏强调 `#62C9EC` | 侧栏 `#111C28`；顶栏/卡片 `#1B2938`；内容背景 `#152231`；强调 `#62C9EC` |
| 经典配色 | `classic` | 保留现有黑色侧栏、浅色内容及绿色交互方向 | 保留现有深色配色方向 |

表中为初始设计值；正文、辅助文字、边框、悬停、焦点、选中、危险与禁用状态需要成套定义，以实际可读性验收为准。经典预设先记录现状再进行 token 接入，避免不经意改变既有视觉。品牌 Logo 图片保留原色，品牌文字仅按背景选用可读的前景色。

取舍：预设组合能控制可读性，也便于用户比较；本期不采用自由调色板，不增加背景上传和透明玻璃效果。预设都使用本地资源，离线也能显示。

### 2. 一个轻量外观面板，两个可复用入口

- 顶部原主题图标位置保留，点击改为打开“外观”面板；按钮提示与可访问名称同步调整。已有直接切换明暗的内部调用保持兼容，但不得有独立状态。
- 配色选项用缩略图呈现“侧栏 + 顶栏 + 内容”的关系，同时展示中文名称与勾选标识。明暗用“浅色 / 深色 / 跟随系统”单选项；系统模式旁可显示当前解析为浅色或深色。
- 选择立即应用并保存，不引入“暂存/发布”流程；关闭面板保留选择。底部提供“恢复默认”，只恢复商务青蓝 + 跟随系统，不重置语言或其他偏好，无需破坏性确认。
- 面板明确标注“仅在当前浏览器生效”，补充“此浏览器中的不同账号共用外观设置”；不把本地偏好展示成账号资料或租户品牌。
- 接入 `extend-sidebar-account-actions` 时，“界面偏好”复用此外观区和状态，语言选项仍由该 change 负责；只保留一个偏好面板，不叠加弹层、不重复注册事件。若该 change 尚未实施，顶部入口即可独立交付本能力。
- 复用现有弹层的关闭、Esc、焦点归还及窄屏布局方式，配色支持键盘单选。菜单收起后打开面板；面板不遮住自身关闭与恢复操作。

取舍：不新增设置页或顶层导航，也不等待资料/密码/租户切换等无关功能。当前 `setLanguage()` 仍可能写实例 `/config`，外观路径不得调用它；语言本地化修正仍归原 change。

### 3. 颜色变量限定接入区域，保持现有明暗契约

在根元素使用 `data-web-palette` 标识预设，继续使用 `.dark` 表示解析后的明暗。围绕实际消费定义 `--web-sidebar-*`、`--web-header-*`、`--web-content-*`、`--web-surface-*`、`--web-text-*`、`--web-border-*`、`--web-accent-*` 等小规模语义变量，不提前建设完整设计系统。实现将控制器放在独立 `appearance.js` 同步加载，将样式放在 `appearance.css` 并在既有 CSS 后加载，避免继续扩大 console.js 或覆盖原样式文件；资源复用现有缓存更新机制。

实施覆盖清单：

1. 侧栏背景、品牌文案、分组标题、图标、选中/悬停/焦点、分割线、底部账户卡片与向上菜单。
2. 顶栏背景、面包屑和图标；将当前页面名称与 Agent 身份合并为单顶栏，其他页面隐藏 Agent 上下文。
3. 对话首页使用左对齐欢迎文案、真实输入框和三条任务建议，所有建议仅填入可编辑草稿，发送仍由用户主动触发。
4. 输入框外层、工具区、发送/禁用按钮、焦点、拖入及 chip 状态；空态时视觉位置居于介绍与建议之间，有消息后回到底部。通过 CSS 排序复用唯一输入框DOM，不重建附件、监听器或业务状态。
5. 新外观面板和品牌加载/认证遮罩的基本背景与前景一致，避免首屏明显反色；品牌设置里的局部深浅预览保持独立。

业务页面随现有 `.dark` 行为继续工作；只更新公共壳层，不将整个知识库、配置等页面纳入配色重构。保留错误、警告、成功的语义色，避免统一强调色后丢失含义。代码高亮按解析后的明暗同步切换，不能直接将 `system` 当作浅色。

### 4. 浏览器持久化与默认规则

`cow_theme` 保存 `light | dark | system`，`cow_web_palette` 保存 `business | slate | classic`，各自是相应字段的唯一持久化来源；内存中的 resolved mode 只用于显示与 CSS，不反写覆盖 `system`。不新增第二份 JSON 快照或服务端偏好。

按以下优先级解析启动状态，首屏与运行时使用同一规则：

| 已保存状态 | 启动结果 |
| --- | --- |
| 配色与明暗均合法 | 恢复两项；system 查询系统明暗 |
| 无配色键，旧明暗为 light/dark | 经典配色 + 原明暗，兼容旧用户 |
| 无配色键，明暗为 system | 商务青蓝 + 跟随系统 |
| 两项均未保存 | 商务青蓝 + 跟随系统 |
| 配色值非法 | 配色回退商务青蓝；合法明暗独立保留 |
| 明暗值非法/缺失且已有合法配色 | 保留配色；明暗回退跟随系统 |
| 无配色键，明暗非法 | 商务青蓝 + 跟随系统 |

无偏好时不因页面初始化自动创建“用户已选择”的键。用户首次改动任何外观选项或恢复默认时，尝试保存当前完整的两个字段；每项仅使用上述唯一键，处理单次或部分写入失败并提示，避免旧用户切换明暗后因未记录 classic 而误用新默认。解析/写入失败不向外抛出，当前页保留用户已选状态并提示“仅本页生效，刷新后可能恢复之前设置”。不清空整个 localStorage。

账号登录、退出、租户切换不改变这两项设备偏好，也不依赖尚未实现的 `/auth/me`。此选择与现有界面偏好 change 的当前浏览器范围一致；若后续需要按账号隔离或跨设备同步，另行变更数据归属及迁移规则。

### 5. 初始化、并发与失败恢复

- 首屏在主要内容绘制前解析两项偏好与系统模式；运行时复用解析结果/相同解析器，不出现先暗后亮的二次默认覆盖。主题恢复不等待网络；同一启动块里访问语言存储的异常也不得阻断外观恢复。现有 `console.js` 的任务通知、默认/当前 Agent、记忆/知识 Agent 等顶层读取同样可能在外观入口初始化前抛错：对保证脚本继续加载与外观入口可达所必需的启动读取提供最小回退，不重构所有业务存储或改变认证持久化协议。验收须让真实页面的 localStorage 读取统一抛错，确认启动脚本继续运行且在原本允许进入的控制台中可打开外观面板，不能只验证独立解析器。
- 一个外观状态入口负责更新根属性、`.dark`、按钮/选中项和高亮。切换不 reload、不重新加载认证、不重建会话、不清草稿或中断流式回复。
- 仅在 system 模式下响应系统明暗变化；显式 light/dark 忽略系统变化。系统检测 API 缺失时采用浅色，保留用户的 system 偏好。
- 同源其他标签通过 storage 事件更新已保存选择；处理事件只读取最新有效值并应用，不反写形成循环。近同时修改按浏览器持久化的最终两个字段收敛，采用最终存储值，不承诺跨字段事务；清除两个键回到默认。存储不可用标签保留本页内存值，不承诺同步。
- 选中项和页面外观必须一致；读取到未知预设不动态加载外部文件，直接回退。缺少某个 UI 元素时控制器仍能更新根外观，不阻断登录遮罩或首页启动。

### 6. 用户追加授权：首页布局实施

用户提供的目标截图明确追加以下范围：

- 单顶栏约 64px，显示当前页面与原 Agent 名称，default 仍按实际 Agent 含义展示；顶部侧栏按钮同时承担桌面折叠和窄屏抽屉。
- 桌面侧栏约 240px，折叠约 72px；增加“新建对话”，复用原 newChat 流程，已有草稿、附件及后台流式会话保持原有继承行为。品牌/管理表单离开保护先执行，再创建会话。
- 工作台保留对话、历史、智能体、场景应用、待办、定时任务；低频配置、智能体配置、技能、记忆、知识、通道收纳进“资源管理”；日志及系统设置保留，进入相关页面时展开所在组。折叠保留图标、名称提示、键盘可达及当前项非颜色标记。
- 空白首页以品牌来源生成轻量介绍，主标题“你好，今天想完成什么？”，输入框置于说明之后。使用 chat-home 状态、display:contents 和 flex order 排序，唯一 composer DOM 始终留在原父级，避免清空欢迎区时丢掉附件或监听器。
- 三条纵向建议为查看工作空间、设置定时提醒、搜索并整理资料；语义 button、点击只填入本地化提示草稿，不自动发消息、建任务或执行外部动作。
- 第一条消息、历史恢复和流式恢复移除欢迎区后回到既有消息滚动及底部输入；新建会话恢复同一欢迎模板，按当前语言与品牌重绘。首页整区可滚动，375px/短屏不裁剪关键操作。
- 账号与顶部复用同一外观 dialog，保留账号语言的本地归属；三配色与明暗模式可用于新布局，经典配色指颜色兼容，不再保留旧首页结构。

追加范围沿用前端静态资源交付，不新增服务端API、数据库或功能开关。验证必须同时覆盖新旧会话切换、附件及草稿、顶部/账号入口、三语与三种视口。

## Risks / Trade-offs

- [浅色侧栏暴露固定白字、固定黑底等遗漏] → 按指定区域逐项替换消费点，覆盖普通、hover、focus、active、disabled 与账号弹层，不能只改根背景。
- [在途账号偏好产生重复面板与主题写入] → 共用同一外观状态及打开函数，接入前核对最新代码；归档时合并相关明暗要求。
- [旧版不认识 system，回滚时解析错误] → 回滚前将 cow_theme 的 system 转为当时解析出的 light/dark；新版配色键可保留供以后恢复。
- [同浏览器不同账号共享偏好] → 在面板直接告知浏览器范围；本期接受此取舍，不暗示用户级隔离。
- [两键部分写入或不同标签同时修改] → 当前页保留已选视觉并提示保存失败；其他标签及刷新按最新有效存储值解析，不宣称事务一致性。
- [新预设暂未覆盖全部业务内页] → 公共框架与首页明确列出范围，内页沿用原明暗；回归确认可读性和既有路由功能。

## Migration Plan

1. **阶段 A：接入核对。** 确认当前 Web 入口和相关在途 change 的实际实现状态，记录经典配色与旧偏好行为；品牌来源及账号交互保持原职责，PRD 原文恢复后复核归属。
2. **阶段 B：外观状态与配色。** 首屏/运行时解析、CSS 接入、系统模式和高亮同步形成闭环后，才接入可选择面板；验证真实浏览器行为，不以静态字符串测试代替视觉验收。
3. **阶段 C：交互与恢复。** 顶部入口可独立使用；账号偏好已存在时必须验证两入口同步。覆盖旧 light/dark、无偏好、坏值、部分存储失败、多标签、系统切换与恢复默认。
4. **阶段 D：交付。** 沿用现有登录及运行门禁，无新 feature flag、接口或数据库迁移；具备本地外观验收后随前端静态资源发布，不等待原账号 change 的无关任务。任务和验收记录中明确“无新增开关”及不适用的服务器门禁，不能标记为已通过的模拟证据。
5. **回退。** 用户侧可选择经典配色及显式明暗。发布回退需对 system 做前述兼容投影，再撤回新主题入口/样式；保留新配色键，不删除业务数据、品牌设置或其他浏览器偏好。

## Open Questions

- 初始色值在浏览器验收时可小幅调整，以文字与控件可读性为准，不改变三套预设和存储契约。
- 面板缩略预览的最终尺寸根据既有弹层布局确定；入口、即时应用、关闭保留及恢复默认行为已确定。
