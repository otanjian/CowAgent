# 设计：手册改为视频为主

## 背景与目标

现行手册（`product-manual-site`）已交付为文字版操作手册：15 章 / 51 个内容块 / 双语各约 700 行文案。目标是改为**视频为主的培训目录**：主题 + 视频要介绍的内容 + 视频位，文字只做定位与概览。

## 决策

### D1：数据模型由「章节 + 块」改为「主题 + 视频」

```php
'manual_topics' => [
    [
        'id' => 'chat', 'part' => 'workbench', 'icon' => 'chat',
        'videos' => [
            ['id' => 'new',     'duration' => '2:40'],
            ['id' => 'compose', 'duration' => '3:20'],
            // 录制完成后补 'src' => 'assets/video/chat-new.mp4' 即可
        ],
        'docs' => [], 'links' => [],
    ],
],
```

- 主题沿用原章节的 id 与分组（`manual_parts` 不变），使导航与既有锚点语义连续，检视 diff 时能对应到旧结构。
- 一个主题含一至多个视频；视频是渲染与维护的最小单位。
- `duration` 放在结构里而非语言包：它是排期信息，两种语言一致，不必翻译。

### D2：视频位用占位组件，声明 `src` 后自动切换为播放器

`manual_video()` 在未声明 `src` 时渲染 16:9 占位（播放图标 + 时长徽标 + 「待录制」标签），声明 `src` 后渲染 `<video controls preload="metadata" poster>`。

- 取舍：不引入 iframe/外链播放器，保持站点离线自包含（既有 requirement 要求不引用站外资源）。
- 取舍：不把占位做成「点击无反应」的空盒子——显式标注待录制，避免使用者误判为加载失败。
- `src` 为相对路径，不是 URL，因此不违反「正文不出现网址」。

### D3：文字收敛为「主题定位 + 视频内容要点」

每个主题保留一句话定位（`lead`）；每个视频有标题与 3–5 条内容要点（`covers`）。

- 删除：逐条界面步骤（`steps`）、字段填写口径（`fields`）。这些内容改由视频演示承载；需要细节时深链既有能力文档。
- 理由：这类内容与界面强耦合，改版即过期，维护成本高于收益；且使用者照做的场景已被视频覆盖。
- 保留：命令速查的两张命令表（命令是稳定的短清单，读比看视频快）；故障排查速查表（状态码与错误语义属查阅型内容，视频不适用）。它们排在对应主题的视频之后，作为次要参考。

### D4：要点必须可被视频覆盖，不得写成步骤

`covers` 写「这个视频会讲到什么」，不写「先点这里再点那里」。校验脚本只强制「至少一条要点」，写作口径由评审把关（避免把长文换行后塞进列表）。

### D5：沿用既有分组、顺序、入口与离线约束

分组（工作台 / 管理控制台 / 个人与参考）、工作台在先的顺序、Hero 入口、无外链、双语对齐全部不变——本 change 只改内容形态，不动信息架构。

## 校验

`tools/check-manual.php` 断言：

1. 两种语言的 `manual.*` 键路径集合一致。
2. `content.php` 声明的每个主题在两种语言下都有 `nav` / `title` / `lead`。
3. 每个主题声明的视频在两种语言下都有 `title`，且 `covers` 至少一条。
4. 主题的 `part` 已在 `manual_parts` 声明；引用的 doc slug 已登记、页面 id 已映射。
5. 声明了 `src` 的视频必须具备标题与时长（避免出现无标题播放器）。
6. 结构或文案缺项时以非零状态退出并列出问题项。

## 退出条件

- 手册页面渲染出主题分组导航、视频占位、时长与内容要点；双语一致，无键名泄漏。
- 声明 `src` 的视频能直接播放（以本地样例验证占位→播放器的切换分支）。
- 手册正文无网址、无外链。
- `openspec validate --strict` 通过。
