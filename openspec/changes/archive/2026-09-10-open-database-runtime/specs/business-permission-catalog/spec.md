## MODIFIED Requirements

### Requirement: 内置角色采用显式默认权限且升级不自动扩权

member与tenant_admin的原业务默认集合 SHALL 保持显式七项与九项；新增普通功能/执行权限（含 `agent.use`、`chat.use`、`model.use` 及资源 grant）必须明确分配，不因目录扩充或运行消费者开放而自动获得。保留既有读取的兼容角色及具体资源清单 SHALL 经过迁移预检和显式应用，不能把旧关闭执行当作授权。平台管理员另按系统all获得已登记功能/资源，不受普通角色默认枚举限制；未知资源/动作仍拒绝。租户管理员与平台管理员的执行旁路仅适用于已开放消费者上的既有规则，不得暗示内置 member 默认可聊天。

#### Scenario: 升级保留既有角色权限
- **WHEN** 已有 tenant_admin、member 和自定义角色用户在目录或运行开放后再次请求有效权限
- **THEN** 内置角色分别取得明确的九项和七项权限，自定义角色保持原选择，不出现自动新增的 `agent.use`/`chat.use`/`model.use`，既有读取及待办继续遵守原资源范围

#### Scenario: 管理员不能短路未登记业务权限
- **WHEN** tenant_admin 尝试请求未登记的业务执行能力，或仅持有默认九项权限但未获显式 `chat.use`/目标 `agent.use` 时请求对话执行
- **THEN** 请求按实际路由开放状态及权限检查被拒绝，不因管理员名称、九项权限或资源可读而放行未授予的执行权

#### Scenario: 平台管理员自动包括新目录项
- **WHEN** 平台身份有效且目录新增合法动作
- **THEN** 平台all包括该动作，普通member/tenant_admin不会因扩目录自动获得，执行仍须满足运行条件

### Requirement: 本期目录整理不得开放延期消费者

功能目录、角色资源授权、模型默认值和现有分发守卫 SHALL 复用现有组件交付。目录/配置与运行状态分别标示，不以执行关闭隐藏合法目录，也不以管理完成开放执行。对已由独立运行开放规范验收的 Web 对话、文件、调度、通道与 OpenAI API，SHALL 允许按权限真实执行；Desktop 企业登录等仍未适配消费者 SHALL 保持关闭，后续单独验证身份、凭据、审计及适用审批/配额/隔离。平台all、导航或组件测试 MUST NOT 解锁未验收客户端；database失败不回退legacy。

#### Scenario: 九项权限齐全但运行仍延期
- **WHEN** tenant_admin 仅持有现有九项默认权限（未获显式 `chat.use`/目标 `agent.use`）并查看能力状态或直接请求聊天入口
- **THEN** 能力状态以权限不足说明（不再以版本延期关闭），相关直接请求返回 403 类拒绝，不触发真实执行；已被显式授予执行权的成员则按开放消费者执行

#### Scenario: Desktop 仍未适配企业身份
- **WHEN** 当前 Desktop 连接 database 服务并尝试使用其旧认证或未适配企业运行入口
- **THEN** 系统不通过共享密码、旧 token 或 legacy 回退赋权，明确显示企业接入未开放，不把 Web 运行开放当作 Desktop 可用证明
