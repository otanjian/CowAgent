## Context

见 `proposal.md` 的动机与范围。本 change 补记同一会话中已完成的两轮前端调整，最终以单行 40px 按钮为准，早一轮 56px 两行按钮为中间状态。

现有接入点为 `chat.html` 的独立账户 footer、`console.css` 的账户布局、`appearance.css` 的主题与折叠样式，以及 `console.js` 的身份渲染。认证和个人操作沿用现有状态机、接口和组件；本次只调整呈现及文字更新目标。

## Goals / Non-Goals

**Goals:**
- 用更小的底部入口保留账号识别和菜单操作能力；菜单通过图标、间距和分组形成清晰层次。
- 让默认、主题、收起侧栏三处 CSS 不再相互覆盖按钮高度。
- 保留隐藏副标题的可访问内容、长姓名省略、错误恢复和已有焦点行为。

**Non-Goals:**
- 不重建个人资料、安全、偏好、租户或帮助组件，不调整各状态的可用权限。
- 不将参考产品的品牌、源码、运行时配置或图标库引入应用。
- 不修改既有首页卡片数量、在途权限 change 或生产认证数据。

## Decisions

### 1. 单行入口，完整身份按需读取

采用「28px 圆角头像＋姓名＋省略号」；保留姓名 13px、20px 行高，按钮最小高 40px、内边距 6px 8px，footer 上下各 4px。默认 1px 顶部分隔线下，实测 footer 为 49px。前一轮按钮为 56px、footer 为 73px，最终减少 24px，约三分之一。粗指针设备以媒体规则将按钮最小高提高到 44px。

副标题保留 DOM，用视觉隐藏样式移出常显布局；已有 title 仍包含姓名及用户名/访问状态。这样避免继续靠缩小两行文字获得高度，也避免删除身份及错误提示的可访问内容。菜单内仍显示完整数据库姓名和用户名。

### 2. 默认几何集中，主题只负责皮肤

按钮基础尺寸统一放在 `console.css`，移除 `appearance.css` 重复的最小高度。桌面收起态仅覆盖居中和水平内边距。入口头像通过 `.sidebar-account-toggle > .sidebar-account-avatar` 单独缩小，菜单头像仍为 30px，不受影响。

### 3. 分组与装饰图标

`chat.html` 为资料、安全、偏好、帮助、退出和重试添加内联线性 SVG，均标记 `aria-hidden`。已有操作文字的 `data-i18n` 移至内部 span；退出进度文字由 `account-menu-logout-label` 接收，身份重绘不会再覆盖整个按钮并删除图标。

设置组随 `dbUser || local` 显隐，子项继续遵守原适用规则。弹层保留原生 button/a 与 `role="group"`，沿用 Tab、Escape 和外部关闭协议；未引入要求方向键导航的 ARIA menu 模式。

### 4. 主题与动态效果

菜单表面、文本、图标和分隔线消费既有 `--web-sidebar-*`；退出悬停消费危险操作颜色。版本链接采用次级文字，保留发布地址与动态品牌/版本文字。菜单进入使用短暂淡入位移，减少动态效果规则放在常规 transition 声明之后，确保覆盖生效。

## Risks / Trade-offs

- [用户名不再常显] → 完整身份保留在悬停提示、辅助技术名称和展开菜单；legacy 模式详情在 title 和辅助技术内容中保留，不声称当前菜单会显示访问模式说明。
- [CSS 覆盖导致高度反弹] → 删除主题层重复高度，收起态不再覆盖最小高度；实测普通和收起入口均为 40px。
- [翻译或状态重绘删除 SVG] → 只更新标签 span，已有身份/退出状态行为沿用；英文菜单实测保留 5 个适用操作图标。
- [视觉测试有历史假设] → 18 组矩阵完成采集，但整条测试因期待首页 3 张卡片、当前及修改前均为 6 张而退出失败；报告保留失败，不修改无关首页以迎合断言。
- [隔离样例的覆盖限度] → 浏览器验证使用实际前端资源和受控后端响应，不等同于真实账号或后端权限验收。最终单行入口另行做了桌面/收起态尺寸检查；未重跑最终状态下全部主题矩阵或物理触屏、屏幕阅读器检查。
- [历史动作规范的已有差异] → `account-menu-actions` 仍描述六项及菜单内租户入口；本次修改前截图与 HTML 已为五项，顶部租户入口另存。本次不将该既有差异归因于视觉调整，也不补造新的租户操作。

## Migration Plan

1. 前置证据为已存在的账户、操作与外观能力，以及本会话记录的验证结果；本 change 无跨服务启用门槛或新增 feature flag。
2. HTML、两份 CSS 与账户渲染文字节点须一起交付；运行中的 `/chat` 与 CSS 已确认返回新结构及 40px 样式，刷新即可生效。
3. 无数据、配置或偏好键迁移。回退时同时恢复本 change 的 HTML、样式和退出文字目标，避免只回退 HTML 后找不到标签。
4. 回退范围限定本次账户相关修改，保留同一工作区其他任务的未提交变更。补记阶段不主动归档；后续归档按 delta 合并 `sidebar-account-menu`，不改写旧归档证据。
