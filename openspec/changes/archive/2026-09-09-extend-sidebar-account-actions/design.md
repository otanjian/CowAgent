## Context

六项能力及界面形式以 proposal.md 的表格为准。原设计的主要成本来自两个本人接口、多个独立面板实现，以及租户切换的全页面 SPA 清理。本版通过复用和整页刷新降低成本，保留只读资料抽屉、密码弹窗及全部字段。

代码核对发现三处不能直接复用的行为：顶部租户选择调用平台管理员列表；`setLanguage()` 会 POST 实例配置；Agent/会话选择存在未按用户和租户区分的 localStorage 键。改密服务目前还存在密码提交与会话撤销分离的问题。这些是本次需要处理的具体接入点。

## Goals / Non-Goals

**Goals:** 六项功能完整、入口一致、普通成员可用，复用现有组件和服务，以少量明确的改动交付。

**Non-Goals:** 不新增路由页面、通用弹层/草稿/缓存框架，不做资料编辑、头像、设备或套餐。临时密码签发/到期策略等完整身份生命周期仍由身份 change 负责，本次不新增其改造任务，也不宣称已验收该能力。

## Decisions

### 1. 保留界面形式，复用现有基础组件

个人资料使用侧边抽屉，改密和偏好复用现有弹窗样式与关闭/焦点处理；不再建设独立面板协调模块。打开一个入口时收起账号菜单，当前弹层关闭后再打开另一个。保留键盘、Esc、移动端和短视口滚动；对有输入的改密表单离开时确认。

关于直接在菜单行显示“关于品牌 · 版本”，点击原发布记录链接，不增加专用关于页面；品牌与版本来自已有状态，版本未知时显示未获取。退出仍调用现有处理器并置底，保留单次提交、失败重试；复用已有离开检查，增加本次密码表单检查，不新增全平台草稿系统。

### 2. 只增加一个本人接口

`GET /auth/me` 返回以下白名单及 `status:success`：

| 字段 | 内容 |
| --- | --- |
| user | id、username、display_name、is_platform_admin |
| must_change_password | 是否要求改密 |
| tenants[] | id、code、name，以及该租户中本人的 membership |
| membership | display_name、roles[{code,name}]、department{id,name}或null、position_text |

普通成员也可读取，只返回其有效租户和本人成员摘要；前端按当前租户 id 取一条展示，成员姓名不覆盖全局姓名，未设置字段明确提示。平台管理员不因平台身份获得未加入租户的成员资料。登录列表与此接口复用同一有效成员筛选逻辑，登录不必携带全部成员详情。

接口只按会话确定本人，不依赖租户请求头，不接受客户端改选用户。受限会话仅返回最小 user、改密标志和空 tenants；失效会话返回真实 401，身份库失败返回 503，响应 no-store，禁止返回密码、令牌、目录等内部字段。业务租户访问仍逐请求验证权限，列表不代表永久授权。

登录/刷新及打开资料或租户选择时读取，保留现有认证代次和一个资料请求序号即可；同一时刻合并重复读取。读取失败局部提示重试，清除失效资料，但不把资料失败当作退出，不重复业务初始化；换账号/退出后的旧结果不能恢复资料。

### 3. 租户切换重新加载页面

两入口共用一个函数和本人列表，点击当前租户只关闭菜单，不刷新。零租户保留个人入口及适用的平台管理；单租户自动选择；多个保留仍有效的当前项，否则要求选择。发现当前成员资格失效也走下述新页面校验流程，旧业务页面不先清空租户存储；新页面阻止旧租户初始化后清除失效选择并展示最新列表，不退出仍有效的全局登录。

为避免“先写租户、浏览器又取消刷新”的错位，使用当前页的一次性 `switch_tenant` 查询参数发起导航；旧页面此时不改 `cow_tenant_id`。现有编辑器 beforeunload 提示继续生效，取消后选择和页面都不变。新文档读取 `/auth/me` 验证目标仍属本人有效租户后，才写 sessionStorage 并移除查询参数；参数只是选择值，不是授权。目标失效则提示重新选择，不自动进入其他租户。切换或改密提交中禁用重复切换。

整个新页面重新初始化，旧页面的请求回调不能写入新页面，因此不再要求全页面 generation、取消注册表、订阅清理或 SPA 缓存重构。已提交的服务端操作可能继续在原租户完成，不承诺被切换取消；另一标签选择不变。

刷新不会自动解决持久化上下文：仅为现有 `cow_active_agent`、`cow_default_agent`、`cow_memory_agent`、`cow_knowledge_agent` 和 `cow_session_id[:agent]` 增加小型 storage helper。database 键包含 user_id/tenant_id，待认证、强制改密和有效租户确认后才恢复这些标识并启动相关业务请求；旧的未分区值不自动带入 database。legacy 沿用原键，不批量删除共享 localStorage，也不改造所有业务缓存。恢复的 Agent 还须在当前服务端可见集合中，无可用 Agent 时显示空态。

### 4. 改密复用已有接口及表单

普通和强制改密使用同一三个字段的表单。前端检查必填/两次一致，原样发送原密码与新密码，确认字段不上传；强度沿用后端规则。写请求单次提交并与退出互斥，关闭清空密码，不写 storage/URL/日志。

按 HTTP 状态和业务码区分：`invalid_old` 留在表单，`unauthorized` 回登录，`weak_password` 提示纠正；网络结果未知不报成功、不自动重放，提供重新登录恢复。成功返回 `must_relogin:true`，后端清 HttpOnly Cookie，前端清身份和输入，明确提示全部旧登录会话失效后重新登录；不删除聊天数据。

登录和 `/auth/check` 均提供强制改密标志，先改密再选择租户/初始化业务。服务端共享认证守卫限制受限账号的业务及平台/租户管理访问，仅允许改密、退出及必要身份读取；受限请求返回 `403/password_change_required`。原密码验证、密码更新、强制状态解除、审计和旧会话撤销保持一致事务，Cookie 写请求具备来源/CSRF 防护；本次复用的认证错误返回真实状态。这些是已有改密能力接入的必要修补，不扩展密码算法或账号生命周期。

### 5. 界面偏好只在浏览器生效

顶部与偏好弹窗调用纯本地的主题/语言切换，沿用 `cow_theme`/`cow_lang`。三语和深浅选择立即应用，storage 不可用时提示仅本页生效；界面明确“仅在当前浏览器生效”。从现有语言函数分离实例写入，配置页按原权限独立保存实例默认语言；个人切换不写 `/config`，不改其他用户或 Agent/CLI 的默认语言。

legacy 密码保护仅有偏好、关于、退出，免登录没有退出；数据库个人资料与个人改密不映射到共享访问密码。

## Risks / Trade-offs

- 租户切换有一次整页刷新，接受这一体验以避免全页面状态清理；保持取消不改变选择、启动时确认权限和上下文分区。
- 本人接口返回各有效租户的本人成员摘要；限定字段并复用服务批量读取，不返回组织全集、不新建缓存服务。
- 改密已有底层缺口仍需修补并验证事务/CSRF/真实状态；简化任务不代表可以跳过这些保障。

## Migration Plan

1. 保留其他在途修改，先验证本人/改密所用后端切片，再接通前端；使用隔离测试数据，不以模拟返回代替接口验收。
2. 前后端配套交付，无数据库结构迁移；database 不继承旧未分区的页面选择，原业务数据保留，legacy 键不变。沿用 identity_mode 和已有消费者门禁，无新增开关。
3. 回退 UI 时保留已修复的认证限制和可用强制改密页，不恢复已撤销会话或旧密码。
4. 归档前协调上期“仅展示”的范围与菜单条款：本次增加个人接口，保留侧栏卡片/旧模式边界；身份算法及授权仍归身份规范。当前正式基线为空，使用 ADDED，本轮不归档其他 change。
