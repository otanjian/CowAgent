## Why

侧栏账号菜单需要提供完整的个人操作入口。按用户确认，保留个人资料、修改密码、界面偏好、切换租户、关于、退出登录六项能力，同时简化接口、页面组织和租户切换实现。

## What Changes

| 入口 | 本次必须具备的能力 |
| --- | --- |
| 个人资料 | 侧边只读抽屉：姓名、登录账号、当前租户、角色、部门、岗位；区分全局账号与当前租户成员资料 |
| 修改密码 | 弹窗输入原密码、新密码、确认密码；成功后重新登录，并说明其他旧登录会话也会失效 |
| 界面偏好 | 浅色/深色、简体/繁体/英文；与顶部同步，标明仅当前浏览器生效 |
| 切换租户 | 只列本人可进入租户并标记当前项；多租户可切换，单租户显示名称，零租户显示未加入 |
| 关于当前品牌 | 展示当前品牌与版本，可进入原更新记录链接 |
| 退出登录 | 退出当前会话并回到登录页，保留失败提示与重试 |

- 个人资料仍用抽屉、修改密码仍用弹窗，复用现有样式与基础交互，不建设新的面板管理框架。
- 本人信息合并为一个 `GET /auth/me`，返回全局账号及各有效租户中的本人成员摘要；当前租户资料从列表中选取，不再新增 `/auth/me/tenant`。
- 两个租户入口共用列表和切换函数，切换通过重新加载当前页完成，省去对所有页面请求、订阅和缓存逐项进行 SPA 清理。只处理现有 Agent/会话选择标识的账号、租户分区。
- 复用 `/auth/password` 和已有认证状态；保留登录/刷新强制改密、服务端限制、改密失败不部分提交等必要保障。个人主题/语言与实例语言保存分开。
- legacy 密码保护提供偏好、关于、退出；免登录提供偏好、关于。个人改密不会修改系统共享访问密码。
- 不增加资料编辑、头像、设备管理、套餐、跨设备偏好同步、全平台草稿框架或认证生命周期改造任务。

## Capabilities

### New Capabilities

- `account-menu-actions`：六项菜单与其交互、个人偏好、刷新式租户切换和旧模式兼容。
- `self-account-context`：单一本人只读接口、有效租户和成员资料白名单。
- `self-password-flow`：本人改密及强制改密的最小完整流程。

### Modified Capabilities

无已归档基线修改。当前正式 specs 为空，沿用三份 ADDED；本次扩展上期“仅展示”的实现范围。归档时协调上期账号菜单与身份规范，保留授权和会话真值归属，不提前修改或归档其他 change。

## Impact

- **依据**：用户的六项菜单截图和“方案简单、能力保留”要求；对应 PRD-02 平台导航 v1.2 增量。PRD 原文当前不可用，以项目配置、现有 change 和代码核对，不声称逐项核对原文。
- **接入点**：现有 `chat.html`、`console.css`、`console.js`，以及 `auth_handlers.py`、`web_channel.py` 路由和现有身份服务；仅在必要处修正改密事务与错误响应。
- **唯一数据来源**：账号、成员、角色、部门、会话仍归 identity.db；只新增本人读取接口，不新增数据库字段。品牌/版本与主题/语言复用现有来源，租户选择按标签保存。
- **依赖**：复用 `add-sidebar-account-menu`、`add-tenant-identity-access-management` 的认证/改密/审计、`add-branding-settings`；只验证本次使用的接口，不承担整个身份 change 的改造。
- **交付**：本轮只调整方案，未实施。沿用 `identity_mode`，无新增 feature flag、数据库结构迁移或运行能力开放；完整改密和准确 HTTP 状态是本次上线必需条件。
