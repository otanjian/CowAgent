## Why

当前 Web「工作台 → 智能体」打开的是智能体配置编辑页，浏览使用与配置管理混在同一入口。需要将配置能力归入管理，并让用户从工作台查看已配置的智能体、直接进入聊天使用。

## What Changes

- 将现有智能体管理页更名为「智能体配置」，移至「管理」分组，放在「配置」之后；保留已有创建、编辑、复制、删除、能力与核心文件配置功能。
- 工作台保留「智能体」菜单名称与当前位置，改为新的智能体使用页，卡片展示头像、名称、职责简介及默认标识，不承载配置编辑器。
- 使用页展示已保存且启用、在当前访问范围内可见的智能体，包含默认智能体；单智能体模式也显示入口。不额外引入发布、审核、上架或应用市场生命周期。
- 点击卡片或「开始对话」进入现有聊天界面，创建归属于所选智能体的新会话，展示该智能体身份并使用其工作空间；不自动发送消息，不复用其他智能体的会话。
- 复用既有配置与会话服务，补齐列表加载、空列表、失败重试、配置变更刷新及智能体失效处理；保持简体中文、繁体中文、英文和现有响应式布局。
- 本期范围是截图所示 Web 控制台。Desktop 保持现有页面结构与接口兼容，不另建桌面工作台；企业身份模式沿用其已验收的读取/运行边界。

## Capabilities

### New Capabilities

- `agent-entry-navigation`: Web 智能体使用与配置双入口、菜单归属、标题、面包屑及既有内部跳转兼容。
- `agent-workbench`: 已配置智能体的只读卡片展示、可见性、刷新和异常状态。
- `agent-chat-launch`: 从智能体卡片进入指定智能体的新聊天，会话归属、工作空间、并发点击及运行限制。

### Modified Capabilities

- 无。当前 `openspec/specs/` 无正式基线；上述是新建规范，其中配置与聊天大部分属于既有产品代码复用。未归档 `prd-02-platform-navigation` 中「管理分组不含智能体」的草案要求由本次用户要求补充调整，归档时合并最终导航约定，不在本次改写其他 change。

## Impact

- **需求依据**：用户 2026-09-08 的菜单调整要求与截图。文中的「进入了解界面使用」暂按「进入聊天界面使用」解释，卡片简介用于了解职责。项目配置引用 PRD-02 平台导航及 PRD-01～12 v1.2；当前 `doc/优化规划/` 缺少 PRD 原文，不能声称已逐条核对。本 change 是导航的增量调整，恢复原文后核对 PRD 映射。
- **接入点**：`channel/web/chat.html`、`channel/web/static/js/console.js`、`channel/web/static/css/console.css`；按需扩展 `channel/web/web_channel.py` 的 Agent 列表读取投影，复用 `agent/admin.py`、`agent/registry.py`、`agent/routing.py` 与现有聊天处理链路。
- **数据唯一归属**：Agent 配置继续由现有配置、AgentAdminService 与 Registry 管理；会话和历史继续由现有会话存储拥有；工作台仅为读取投影，不复制配置、不增加业务数据库或另一套 Agent ID。
- **接口兼容**：保留 `/api/agents` 默认响应、管理写入与 `revision` 语义，新增工作台读取投影不影响 Desktop/已有选择器；保留显式 `agent_id` 的运行路由语义。
- **跨 change 依赖**：接续 `prd-02-platform-navigation` 导航骨架；与 `add-workbench-todos` 的相邻菜单改动合并时互相保留。若启用 `add-tenant-identity-access-management` 的 database 模式，列表须使用其已验收的 Agent 读取授权；该模式未开放模型运行时只读展示并明确提示不可启动，本 change 不解除其运行门槛。
- **交付性质**：本次仅生成 change 文档与未勾选实施任务；不修改产品代码、不调整现有智能体数据。
