## Context

动机与产品范围见 `proposal.md`。本设计是 PRD-02 平台导航 v1.2 侧栏账号展示的增量，依据本轮已确认方案；当前工作区未找到配置引用的 `doc/优化规划/PRD/` 原文，不将旧草案中未落地的认证方式作为新增实施要求。

现有 Web 控制台采用 HTML、CSS 与普通 JavaScript。侧栏已经是纵向 flex 布局，导航独立滚动、footer 不收缩，可直接容纳账号卡片。

| 接入点 | 当前行为与约束 |
| --- | --- |
| `channel/web/chat.html` 的 Sidebar Footer | 包含状态圆点和 `#sidebar-version` 发布链接，位于可滚动导航之外 |
| `channel/web/static/css/console.css` 的 Sidebar 样式 | 黑色侧栏，已有悬停、菜单激活与主题规范 |
| `channel/web/auth_handlers.py` 的数据库登录/检查处理器 | 均返回 `user.username`、`user.display_name`、`user.is_platform_admin`；本次只消费前两项 |
| `channel/web/static/js/console.js` 的认证区 | 初始 `/auth/check` 与 `_afterLogin()` 未消费 `user`；多租户选择完成只传 `identity_mode`，丢失登录响应中的用户信息 |
| `showLoginScreen()`、全局 401 拦截、`handleLogout()` | 已承担登录过期及退出入口，需同步清除新增展示状态 |
| `initApp()`、品牌渲染与 `applyI18n()` | 版本异步写入旧 footer；品牌有统一状态与发布刷新机制，新增菜单应使用同一来源 |

账号 API 尚无用户头像或套餐字段。本次默认头像独立于品牌 Logo 和智能体头像。`openspec/specs/` 当前为空；旧 `prd-02-platform-navigation` 的免登录版本栏约定与本次方案的合并关系见提案，不在本轮改写旧 change。

## Goals / Non-Goals

**Goals:**

- 使用一份本页账号展示状态同时驱动卡片和菜单，保证首次登录、刷新、租户选择和身份失效后一致。
- 复用现有 DOM、认证接口、品牌状态、版本请求与国际化，限制改动范围为三个 Web 前端文件及必要验证材料。
- 保证账号未知、未认证、数据库账号、legacy 密码保护和免登录状态不会混淆。

**Non-Goals:**

- 不新增身份数据存储、用户接口、认证令牌机制、前端角色授权或跨标签页同步协议。
- 不建设头像上传、个人中心、修改密码界面、套餐或租户/角色管理入口。
- 不更改 Desktop/Channel、业务 session、租户授权接口或当前受限的执行能力；不替其他 change 宣称完成验收。

## Decisions

### 1. 在原 footer 内放置卡片和向上展开的菜单

footer 保持不收缩，导航设置必要的最小高度约束，账号卡片最小高度约 72px、头像约 36px，文字缩放时允许卡片增高。卡片使用原生按钮，包含头像、两行文本及展开箭头；文本容器允许收缩和省略，菜单身份区允许换行以展示完整账号。重试、退出和版本链接位于卡片按钮之外的弹层，避免按钮嵌套。

菜单锚定 footer 顶部，避免放入导航的滚动容器；限制最大高度、允许内部滚动，保证短视口和移动端侧栏内可操作。采用现有黑色侧栏配色、轻量悬停底色和可见焦点，主内容主题切换不改变账号信息。

卡片提供 `aria-expanded`、`aria-controls`；弹层使用原生按钮/链接和普通 Tab 顺序，不引入需要完整方向键模型的 ARIA menu 角色。Enter/Space 打开并将焦点移入首个可操作项；再次点击、外部点击、Escape、侧栏关闭或登录失效时收起。关闭态内容不参与 Tab 顺序；Tab/Shift+Tab 离开卡片与弹层时关闭并保留新焦点，只有 Escape 且卡片仍可见时返回触发按钮。语言、品牌、版本更新优先更新文本节点，不重建正在操作的按钮或抢走焦点。

账号菜单开启时关闭语言和租户菜单；反向点击顶部菜单时账号菜单也关闭。顶部两个按钮当前会阻止 click 冒泡，因此外部检测使用捕获阶段 `pointerdown` 与包含关系判断，或等价的显式关闭联动；不阻止原顶部操作。临时监听只绑定一次并在关闭后清理，避免多次登录/开关菜单叠加事件。

选择在现有页面内实现，避免新增弹层库或重构全部顶部菜单。若验收发现层级或裁剪问题，优先调整 footer 定位与层级，不增加第二套侧栏。

### 2. 用户展示状态只来自既有认证响应

在 `console.js` 建立统一的状态更新、清空与渲染入口，区分认证结论与资料可用性：身份模式初始为 unknown，只有有效认证响应可确认 database/legacy；认证状态与 `user` 是否完整分别保存。状态只保留必要的阶段、布尔值、姓名/用户名和并发标识，不保存包含令牌的整个登录响应，也不新增 localStorage/sessionStorage 用户缓存。状态声明需早于读取它的 fetch 包装、国际化渲染和初始化调用。

| 已确认状态 | 卡片主行 / 次行 | 菜单动作 |
| --- | --- | --- |
| database 已登录且 `username` 有效 | `display_name` 去除空白后优先，否则 `username` / `@username` | 完整姓名账号、退出、品牌版本链接 |
| legacy 且密码保护已认证 | 本地访问 / 密码保护 | 退出、品牌版本链接 |
| legacy 且明确不要求认证 | 本地访问 / 免登录模式 | 品牌版本链接 |
| 启动检查中或失败，尚未确认认证模式 | 在现有登录遮罩显示加载或错误与重试 | 不显示猜测的登录表单；暂不执行应用业务初始化 |
| 控制台内重新检查，认证结果尚未确认 | 账号信息加载中 / 空 | 可查看已有版本；不展示已确认身份或退出项 |
| 认证未知，检查失败或结果格式不合法 | 账号信息暂不可用 / 重试提示 | 重新检查、品牌版本链接；不推断为免登录 |
| 响应明确已认证，但 database 用户名缺失 | 账号信息暂不可用 / 重试提示 | 重新检查、退出、品牌版本链接；不显示旧名字 |
| 退出中 / 退出结果未知 | 正在退出 / 退出未确认 | 退出中禁用两个退出入口；失败后提供重试退出与重新检查 |
| 明确未认证、登录界面可见 | 清空账号与菜单 | 沿用现有登录入口 |

用户名必须为有效非空字符串；显示名只以去除空白判断是否可用，展示保留原文。database 头像取展示名称首字，legacy/加载/错误使用人物图标，不把「本地访问」等状态文案做成用户首字头像。头像不发起额外网络请求。用户文本使用 `textContent` 或统一转义，不作为 HTML。卡片与弹层均不展示角色、套餐、令牌或凭据。

认证响应先检查 HTTP 成功、JSON 对象和业务成功，再解析字段。database 检查使用显式 `identity_mode`、`auth_required`、`authenticated`；legacy 检查没有 `identity_mode`，免登录还缺少 `authenticated`，须通过成功响应中的明确布尔值 `auth_required: false` 识别免登录，通过 `auth_required: true` 和明确的 `authenticated` 识别密码模式。缺字段、服务错误或无法确认的模式都不从默认值推断为免登录。已知模式下本人检查明确返回 401 或合法的 `authenticated: false` 时按登录失效处理；模式 unknown 时保留中性恢复入口。legacy 登录只返回 `status` 和可选令牌，使用已确认的登录模式规范化结果，必要时复核一次既有检查，不要求后端加字段。

本人 `/auth/check` 保持同源 Cookie 请求，不附加 `X-Tenant-ID`、不复用租户管理请求封装。否则失效租户可被现有处理器折算成 `authenticated: false`，将租户问题误当作全局账号退出；本次不改服务端语义。

选择复用 `/auth/check` 而不新增 `/auth/me`；选择姓名首字而不创建头像字段。对于用户资料实时变更，第一版通过已有重新登录或页面刷新获取最新信息，不新增轮询。

### 3. 在现有认证生命周期中统一更新

- **启动/刷新**：在现有登录遮罩显示中性加载，认证模式确认前暂不调用 `initApp()`，也不按默认 legacy 渲染密码表单。失败显示错误与可见重试；有效认证/明确免登录结果才进入控制台，明确未认证则显示正确模式的登录表单。首次重试成功只补齐一次本次应用进入初始化，避免现有 `catch → initApp → 业务401 → 错误登录表单` 链路。只重排必要的认证入口，不重构其他模块的加载。
- **登录成功与租户选择**：在进入租户选择前保存最小 `user` 展示状态；单租户直接进入，多租户选择完成沿用已保存状态，零租户账户也可显示本人身份并退出。重新显示登录表单、完成选择和身份失效时，清空旧选择回调 `login-btn.onclick`、旧选项及待选择的临时状态，恢复正常提交；选择完成保留当前已认证用户。复用原选择界面，不重构顶部自动选租户或管理权限请求。
- **租户切换**：同一账号切换租户不清空账号；卡片不查询平台租户/成员管理接口，避免普通账号因无管理权限无法显示本人信息。
- **失效与退出**：两个退出入口继续调用同一 `handleLogout()`。发起退出时关闭菜单、清除身份文字、进入退出中，禁用重复提交；HTTP 与 JSON 均确认成功后沿用刷新。HTTP 错误、非成功 JSON、解析失败和网络错误统一显示「退出未确认」，提供重试退出/重新检查，不自动宣称成功。重新检查明确未认证才进入登录页，若仍已认证则按最新结果恢复显示。错误入口使用非隐藏区域或允许重新打开的菜单，不能在清空卡片后失去操作入口。
- **身份代次与检查序号**：分开 `authEpoch` 和 `checkSeq`。首次从 unknown 确认当前访问身份、登录建立新身份、退出及确认当前登录失效时推进身份代次，避免启动前已发出请求的迟到 401 污染初始身份；普通同身份检查/重试仅推进检查序号，不使当前会话的真实 401 失效。账号检查从请求、解析到全部 UI 副作用均校验身份代次和检查序号，旧回调不得调用登录页、初始化或重新显示旧身份。
- **全局 401 的最小联动**：在现有 401 fetch 包装中捕获请求发起时的身份代次，只有同一身份的 401 才触发失效处理；旧身份响应仍原样返回调用方，但不退出新账号。认证模式 unknown 时保留中性检查/重试入口，不调用默认 legacy 表单。沿用 `/auth/*` 排除规则，由认证调用方区分凭据错误与检查失效；业务 403 不作为退出信号。保留 Agent 参数包装和原 response，不在这里改写业务结果、授权或缓存；本次只约束登录失效副作用。
- **重复操作**：同一页面串行处理登录与退出提交，避免重复认证写请求；展示代次不能撤销已发生的 Cookie 写入，故不依赖取消请求解决重复登录。跨标签页会话协调仍沿用现有行为。
- **控制台内重试**：仅调用 `/auth/check` 并更新账号状态，不调用 `initApp()`、`_afterLogin()` 或触发知识/工作区/版本重载，不改变当前视图、草稿、租户与会话选择，不聚焦聊天输入框。检查中禁用重复重试；仅明确未认证时进入现有登录流程。
- **legacy 开关变更**：沿用现有密码保护配置成功后的状态刷新入口；必要时重新调用既有 `/auth/check`，从确认结果更新本地访问文案及退出项，不根据配置输入框推断认证状态。

选择显式状态入口而不在多处直接拼写用户名，避免多租户选择路径漏传 `user`。所需变更限于启动认证协调、租户选择临时处理器、退出失败反馈和 401 失效副作用；现有顶部 `_identityMode` 比较、自动选择时序等独立缺陷不作为本账号展示 change 的修复前置。

### 4. 迁移版本 DOM，并连接统一品牌渲染

将唯一 `#sidebar-version` 元素移至菜单，保持现有发布页地址、新标签页与 `noopener noreferrer`。统一使用有效品牌名和 `APP_VERSION` 渲染，品牌加载/发布及版本请求完成时均可更新该节点，防止返回顺序不同导致名称回退或覆盖账号。只有 HTTP 成功且版本字段为有效非空值才更新版本，错误 JSON/缺字段按读取失败处理，避免显示 `vundefined`。

版本请求失败时保留本页已取得的有效版本；尚无有效版本时只显示有效品牌名称，不产生空版本或 `undefined`。不依赖版本请求成功才显示账号。第一版不保留旧状态圆点，避免将它误解为用户在线状态。选择移动现有元素而不新增重复 ID，以保持原请求接入清晰。

### 5. 分阶段验证，沿用既有启用开关

实施任务按 PRD-02 增量的依赖核对、状态接入、界面联动、验收交付分组。前一阶段的相关证据就绪后再进入后一阶段；所需切片仅为登录/检查/退出和品牌读取契约，不要求租户管理、聊天运行等其他 change 全部完成。验证使用现有 `node:test` + VM 风格执行生产处理器，不新增框架，模拟请求用于确定性复现并发，实际接口记录用于证明认证契约，两者用途分开。

重点回归为启动失败重试且只初始化一次、多租户账号过期后正常提交新登录、旧账号成功/失败/401 均不影响新账号、当前账号 401 在检查重试后仍生效、资料缺失仍可退出、退出非成功 JSON 可恢复。布局使用桌面、手机、手机横屏三个代表性视口；三语与主题切换做覆盖检查，不将语言×主题×视口×租户数做全组合测试。账号单独重试须验证没有新增业务初始化请求和焦点跳转。

不新增 feature flag；沿用 `identity_mode` 与密码保护开关，分别验证 database、legacy 密码保护、legacy 免登录。后端权限、审计及执行隔离保持原有门槛，本 change 不为其他能力开启开关。实施进度见 `tasks.md`，实际验证结果和限制见 `acceptance-report.md`，设计本身不替代验收证据。

## Risks / Trade-offs

- [多租户选择丢失用户信息] → 在选择前保存最小身份状态，覆盖零/单/多租户及刷新路径。
- [旧请求恢复上一账号或旧 401 退出新账号] → 身份代次和检查序号分离；账号响应的全部 UI 副作用及全局 401 失效动作校验身份代次，用乱序响应做针对性验证。
- [启动失败跳入错误登录表单、资料缺失无法退出] → unknown 使用现有遮罩的中性检查/重试；认证结论和资料完整性分离，已认证但资料缺失仍可退出。
- [品牌或版本更新覆盖账号] → 各自使用专属 DOM 与唯一状态来源，验证品牌保存、版本失败和请求返回顺序。
- [菜单被导航裁剪、移动端遮罩层级异常] → 弹层位于固定 footer，检验桌面、窄屏、短视口和长账号；关闭侧栏同步关闭弹层。
- [现有共享前端文件含其他在途改动] → 实施前重新读取接入点，只提交本次增量，保留其他 change 的功能和改动。
- [旧规范免登录版本栏冲突] → 归档时协调 PRD-02 的侧栏要求，保留本次明确的本地访问卡片和菜单版本入口，不改写认证域。

## Migration Plan

1. 实施前记录现有认证接口与品牌行为证据，以及侧栏/顶部入口基线；确认本地在途改动，按任务分组进行局部修改。
2. 随 Web 静态资源一同交付 HTML、CSS、JavaScript；无需数据库迁移、身份缓存转换、新配置或业务会话迁移。升级后从现有认证检查恢复展示。
3. 验证三种模式、刷新/多租户/401/重新登录、品牌版本及响应式行为，执行相关已有回归，更新验收记录后才将任务勾选。
4. 需要回退时仅撤回本 change 的静态资源增量，恢复原 footer 版本栏及对应渲染；保留其他 change 改动，不删除用户、AuthSession、租户选择或业务 session。

## Open Questions

无阻塞设计问题。卡片高度约 72px、头像约 36px、菜单间距和最大高度可在实际视口验收时微调，不改变规范；用户头像上传与套餐展示不属于本 change。
