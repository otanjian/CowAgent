## Why

Web 控制台侧栏底部目前只显示品牌版本，用户无法直接确认当前登录账号。按用户已确认的截图方案，将该位置改为头像与两行账号信息，并提供向上展开的账号菜单，让身份识别、退出登录和版本查看集中在侧栏底部。

## What Changes

- 以固定在侧栏底部、约 72px 高的账号卡片替换原版本栏，上方导航独立滚动；沿用黑色侧栏风格。
- 数据库账号模式显示默认圆形头像、`display_name || username` 和 `@username`；长名称省略并可查看完整内容。
- 点击卡片向上展开菜单，包含完整姓名/账号、退出登录及原品牌版本发布链接；支持再次点击、外部点击与 Escape 关闭。
- 复用 `/auth/login`、`/auth/check` 的 `user` 数据及现有退出入口，覆盖首次登录、页面刷新、多租户选择、登录过期与重新登录；清理租户选择临时回调，隔离旧身份的迟到检查结果与 401。
- 共享密码模式显示「本地访问 / 密码保护」，免登录模式显示「本地访问 / 免登录模式」；免登录时不展示退出操作。
- 将原版本链接移入弹出菜单，沿用 `/api/version` 与当前品牌名称；保留现有顶部租户选择、退出入口及其行为。
- 支持简体中文、繁体中文、英文、深浅主题与移动端侧栏，补齐菜单互斥、键盘焦点、加载/失败和退出失败重试。
- 首次认证检查失败时，在现有登录遮罩提供可见重试，待认证模式确认后再进入登录或控制台；进入控制台后的账号重试只更新身份信息。区分「认证未知」与「已认证但资料缺失」，后者保留退出入口。
- 实施范围为 Web 前端的账号展示及其必需的认证入口联动，不新增头像上传、套餐体系、个人中心、API、数据库字段或运行时依赖，不重构租户选择器或所有业务请求。

## Capabilities

### New Capabilities

- `sidebar-account-menu`: 侧栏底部账号卡片、账号菜单、认证状态同步、版本入口迁移及旧模式兼容。

### Modified Capabilities

- 无。当前 `openspec/specs/` 没有正式规范基线，本次为既有 Web 产品代码新增规范。与未归档 `prd-02-platform-navigation/specs/user-auth/spec.md` 的侧栏展示约定存在重叠，归档时仅就侧栏展示合并：账号卡片以本次方案为准，旧模式也使用本地访问卡片，版本改在菜单中查看；不重定义登录、会话令牌或授权规则，不修改其他 change 文件。

## Impact

- **需求依据**：用户 2026-09-08 提供的两个截图、上一轮账号卡片方案及本轮「按上面的方案生成 change」要求；对应 PRD-02 平台导航 v1.2 的侧栏账号展示增量。PRD 原文路径由项目配置指定，当前可核对资料为既有 PRD-02 change 与代码；本提案不声称完成原文逐条验收。
- **代码接入点**：`channel/web/chat.html` 的侧栏 footer 与菜单结构；`channel/web/static/css/console.css` 的侧栏样式；`channel/web/static/js/console.js` 的认证初始化、登录/租户选择、退出、国际化、品牌与版本渲染。
- **数据唯一归属**：账号及 AuthSession 由现有认证服务管理，前端只保留本页展示所需状态；不保存密码/令牌到展示状态，不将身份写入业务 session。租户选择仍由既有流程负责，版本仍来自 `/api/version`，品牌仍来自现有品牌状态。
- **跨 change 依赖**：接续 `prd-02-platform-navigation` 的侧栏骨架、`add-tenant-identity-access-management` 已有认证接口及模式边界、`add-branding-settings` 的品牌唯一来源。实施时检查所用登录/检查/退出接口切片的真实验证证据；不依赖其他 change 全部完成，也不开放其尚未验收的写入或执行能力。
- **兼容与交付**：Web 前端展示增量，不改变 Desktop/Channel、API 响应、会话存储、权限或租户隔离；无需数据迁移或独立 feature flag，沿用现有身份模式与认证开关。文档产物齐备不代表代码已实现或验收通过。
