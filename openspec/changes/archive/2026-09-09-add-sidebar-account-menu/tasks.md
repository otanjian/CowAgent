## 2. PRD-02 增量阶段二：账号展示状态接入

- [x] 2.1 在读取状态的包装和渲染入口之前声明最小账号状态，分离初始 unknown、认证结论和资料完整性；校验 HTTP、JSON 与业务结果，按真实契约规范化三种访问模式。统一姓名回退、纯文本渲染和头像策略，已认证但资料缺失仍可退出；不保存完整响应或新增身份持久化，本人 `/auth/check` 不附加租户头。
- [x] 2.2 重排必要的启动认证入口：unknown 在现有登录遮罩显示中性加载或错误重试，模式未确认时不显示猜测的密码表单、不执行业务初始化；有效结果进入正确登录或控制台路径，首次检查重试成功只补齐一次应用进入初始化。
- [x] 2.3 登录成功后在租户选择前保留最小本人信息，覆盖零/单/多租户与刷新；重新显示登录表单、完成选择或身份失效时清理 `login-btn.onclick`、旧选项和待选择状态，恢复正常提交。串行处理登录提交，同一账号切换租户或业务会话时保持身份，不重构顶部租户选择器。
- [x] 2.4 分开 `authEpoch` 与 `checkSeq`：首次从 unknown 确认身份、登录建立身份、退出和确认失效推进前者，普通同身份检查仅推进后者；检查从解析到登录页、初始化及展示等 UI 副作用均校验代次。全局 401 包装仅让当前身份请求触发失效，保留原 response、既有 Agent 参数包装及 `/auth/*` 排除规则，unknown 仍进入中性重试；普通重试不能屏蔽当前账号真实 401，业务 403 不触发退出。
- [x] 2.5 两个退出入口统一复用 `handleLogout()`：立即关闭菜单、清除身份文字、禁用重复提交；仅 HTTP 与业务结果均成功后刷新。HTTP 错误、非成功 JSON、解析失败和网络错误显示可触达的「退出未确认」与重试退出/重新检查入口，按重新确认的认证结果恢复账号或进入登录页。
- [x] 2.6 实现控制台内账号重试及 legacy 密码配置成功后的状态复核，检查中防止重复请求；仅更新账号状态，不调用 `initApp()`、`_afterLogin()` 或重载业务/版本数据，不改变当前视图、草稿、租户、会话和焦点，明确未认证时才进入现有登录流程。
