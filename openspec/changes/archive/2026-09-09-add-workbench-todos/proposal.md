## Why

工作台需要把对话中遗留的人工事项保存下来，并让用户持续查看、处理和完成。原稿在这一目标上叠加了多人协作及调度可靠性改造；本次按用户“最简最优、直接优化”的要求，收敛为个人待办与会话跟进闭环。

## What Changes

- 接通 Web“待办事项”页面：个人列表、详情抽屉、手动创建、编辑、完成、取消和重新打开，保留“待处理/处理中/已完成/已取消”四种状态。
- 保留标题、说明、可选分类、优先级、截止时间和来源；四种分类只用于识别事项，不决定审批流程或强制填写完成说明。修改截止统一走编辑，取消独立延期动作。
- 从有权访问的消息“加入待办”，并从事项返回正确的 Agent/会话；保留轻量 Agent create/list/get，复用同一服务，仅在可信 Web 主体及既有聊天运行能力可用时开放。
- 所有事项只属于一个用户；本人创建给本人、Agent 在明确委托下为该用户创建。只提供个人范围，取消首期指派/转交、创建人旁观范围、租户全量管理及其权限和成员选择接口。
- 采用“事项＋处理记录”两张业务表。创建通过稳定创建键去重，更新通过版本条件写入防覆盖；移除通用请求结果表及提醒意图表。
- **范围延期**：周期生成待办、单次自动提醒及其投影同步、投递回执、调度时区/补偿改造移至后续独立设计，不属于本 change 验收范围。本期待办截止只产生逾期标签；原“定时任务”及已有提醒继续独立运行，完成待办不自动取消这些独立提醒。
- 保留身份隔离、来源权限、原子持久化、处理记录、备份恢复和真实失败反馈；不以简化为由放开免登录、跨用户访问或未适配的企业运行入口。

## Capabilities

### New Capabilities

- `todo-management`: 个人事项、四状态、字段编辑、创建去重、版本并发、处理历史与身份边界。
- `todo-workbench`: 单页列表与详情、个人筛选、角标、表单和失败反馈。
- `todo-conversation-integration`: 消息加入待办、来源回链及可信 Web 会话中的最小 Agent 工具。

### Modified Capabilities

- 无。当前无正式 `openspec/specs/` 基线；本次改写尚未实施的三份新增规范，移除未实施的 `todo-scheduler-integration` 草案，不对不存在的主规范写 REMOVED delta。与 `prd-02-platform-navigation` 的待办占位要求在归档时协调。

## Impact

- **范围依据**：用户本轮优化要求及前文确认的产品定位。项目配置引用的 PRD-00、PRD-01～12 v1.2 原文当前缺失，仍需恢复后核对业务编号，不虚构 PRD 覆盖范围；本次明确记录延期，不把删减功能称为已经实现。
- **接入点**：Web HTML/JS/CSS、`web_channel.py` 的新待办 handler、独立 `agent/todo/`、最小 `agent/tools/todo/`，复用现有身份上下文、状态目录、会话服务和备份。既有协议 Task、runs、scheduler 存储与调度算法不改。
- **唯一真值**：待办库拥有个人事项及处理记录；身份域拥有用户/租户，原会话库拥有正文，scheduler 继续拥有独立定时任务。待办不保存提醒计划、接收人或调度执行状态。
- **依赖**：个人 Web 功能可在已登录 legacy 模式独立发布；database 仅在身份 change 的主体、权限、数据根和受控读取切片真实可用后启用。待办写入与最小内部审计同事务验收。Agent 接入使用已允许的聊天运行链路，本 change 不承担建设 10B/08S/09G 或解除企业运行禁用；相关动作原有门槛继续生效。
- **交付性质**：仅优化既有 change 文档，所有实现任务仍未完成。本期完整交付范围是三份规范；延期项不预建表、接口、开关或占位页面。
