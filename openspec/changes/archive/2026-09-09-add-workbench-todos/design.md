## Context

本次审查的是未实施草案。原稿 41 项任务中，定时生成、提醒投影、受管任务保护、投递回执和调度恢复占据大量工作，多人转交又引入来源共享、成员目录和管理权限。它们有产品价值，但不是个人待办形成闭环的必要条件。

现有 Web `todo` 仍是菜单占位；`Task` 是 Agent 输入协议，conversation store 的 runs 是运行记录，均不能直接承担待办状态。Web 已有原生页面、会话服务和三语主题；Agent 工具有调用标识和上下文机制可复用。scheduler 当前使用本机时间、10 分钟补偿窗、JSON 存储和进程内锁，并非原稿所要求的持久投递与时区框架。

身份企业化仍是另一个未实施 change。当前免登录会通过 `_require_auth()`，且 RuntimeIdentity 缺少已落地的可信租户解析，因此待办必须单独限制为有效登录主体，不能假定权限已经实现。

## Goals / Non-Goals

**Goals:** 用户能创建或从消息保存个人事项，看到截止与状态，回到来源继续处理，再显式完成；Agent 能在已有合法 Web 会话中帮助创建和查询。采用当前技术栈，小范围接入，保持真实持久化与权限检查。

**Non-Goals:** 本期不提供转交/指派、团队看板、管理员代办、周期生成、自动提醒、自动恢复旧 Agent 运行或审批记录集成。原有定时提醒独立存在，用户仍在定时页面管理；完成待办不会自动取消这些提醒。

## Decisions

### 1. 简化与延期分别说明

| 原稿 | 优化后 | 性质与后续条件 |
| --- | --- | --- |
| 四类事项分别强制完成说明 | 类别仅作标签；所有处理说明可选 | 简化交互，仍保留四种状态和历史 |
| 独立延期动作、原因和只能向后校验 | 编辑截止统一支持设置、提前、延后、清空 | 合并实现，变更自动留记录 |
| 我负责的/我创建的/租户全部、转交和代办 | 当前用户个人列表；负责人不可变 | 多人协作延期，需要共享语义及真实成员权限后独立设计 |
| todo_items/events/requests/reminders 与迁移表 | items/events 两张业务表，SQLite user_version 记 schema | 创建键＋版本即可覆盖首期重试，不做通用请求结果账本 |
| 周期生成及 todo_reminder 投影、reconcile、回执 | 本期无自动联动，定时功能继续独立 | 功能延期；以后可先只接确定性 create_todo，再评估提醒需求 |
| 为联动新增 DST、漏执行补偿和进程锁 | 不修改调度算法或存储 | 后续调度可靠性设计，不包装成待办必需工作 |
| 三个业务开关和 A/B/C 全运行门槛 | todo_enabled＋既有工具启用/运行许可 | 无独立调度开关；工具按请求能力派生是否可用 |

这些删减不是性能基准意义上的全局最优结论，而是当前个人待办范围下更少的状态、依赖和故障面。SQLite、对象授权、版本竞争和真实处理历史继续保留，不能仅以任务数衡量简化。

### 2. 一个个人事项模型，统一更新

拟新增 `agent/todo/store.py` 和 `service.py`；小型模型/校验放在同模块，暂不拆 repository、policy 插件或事件总线。Web 和 Agent 工具都调用相同服务。

| 字段 | 规则 |
| --- | --- |
| id、scope_id、owner_id | ID 服务端生成；scope 来自当前可信空间，owner 为人工用户，本期不可指派或修改 |
| title、description | 标题去首尾空格后 1～120 字；说明最多 8,000 字，纯文本 |
| kind、priority | kind=general/input_required/confirmation/review，默认 general；priority=low/normal/high，默认 normal |
| status | pending/in_progress/completed/cancelled，默认 pending |
| due_at、timezone | 可空 UTC 截止时刻及用于解释该时刻的 IANA 时区，无 reminder 字段 |
| source | manual/conversation；可空 agent_id/session_id/message_seq，服务端验证；无需 run 引用或会话才能创建手工事项 |
| created_by、created_at、updated_at、completed_at、version | 服务端生成，区分人工与 Agent 创建主体；owner 始终是人工委托人 |
| create_key、create_payload_hash | 创建时固定，不随事项后续编辑改变；唯一键为 scope/owner/create_key |

日期选择默认本机时区，API 只接受明确带时区的时间；只选日期时保存前展示该时区当日 23:59:59。允许过去的截止；逾期只计算为活动状态且 due_at 早于 server_now，不做定时状态更新。页面展示时明示时区，无需在本期待办中实现调度器时区规则。

| 更新 | 允许状态 | 结果 |
| --- | --- | --- |
| 开始处理 | pending | in_progress |
| 完成/取消 | pending、in_progress | completed/cancelled，记录实际操作者，说明可选 |
| 重新打开 | completed、cancelled | pending，保留历史、清除当前 completed_at |
| 编辑内容/截止/标签 | pending、in_progress | 原状态不变，自动记录修改字段 |

所有类别使用同一状态规则，完成说明与取消说明均最多 2,000 字且可选；“确认”只是业务标签，不能转化为执行授权。终态先重新打开才能编辑。不提供硬删除或任意 owner/source 更新。PATCH 采用目标状态而不是通用 action 名称；一次请求选择字段编辑或状态更新，状态更新可带说明，不混合改写正文。

### 3. 两张业务表与足够的并发保障

通过统一 state_dir 入口定位私有 `todo/todos.db`：legacy 在可信实例应用数据根，database 在身份域确认的租户应用数据根。禁止放入通用文件预览/下载可读写的 workspace；缺失可信主体或目录时报错，不回默认 Agent 或全局 shared。每租户一库供该租户跨 Agent 的个人事项使用，查询仍必须校验 owner。

- `todo_items` 保存当前事项及不可变创建去重信息。
- `todo_events` 保存事项 ID、版本、实际操作者/人工委托人、时间、动作、变更字段和可选说明；仅追加，随事项授权读取。它同时提供本期待办的最小内部审计，不另建第二份审计真值或跨库投递。

SQLite 使用事务、WAL、有界锁等待及必要索引，schema 用 user_version 和顺序迁移脚本管理。事项更新、version 增加和事件落盘同事务成功或失败。审计写入失败不能降级为普通日志并返回成功；不记录凭据、模型 prompt 或无关会话正文。

创建：前端表单生成 UUID create_key，提交结果未知时保留该键与原提交内容；同键同创建摘要返回同一 ID 的当前授权详情，同键异内容返回 409。摘要基于规范化后的初始业务内容及来源，不包括服务器生成字段，不能用编辑后的内容重新计算。Agent 使用工具命名空间、稳定 Web 请求 ID 和工具调用 ID 的组合键，不能只用不同轮次可能重复的模型局部 ID；只有相同调用的重试保证去重，不承诺用模型语义识别不同请求是否重复。

更新：客户端提交 expected_version，事务执行版本条件更新及事件追加。两个不同更新最多一个成功；响应丢失后重新 GET 判断真实状态，旧版本重试返回 409，不重做动作或追加重复历史。不再承诺“所有更新请求重放原成功响应”，因此无需 todo_requests 表。所有幂等返回前仍重新授权。

### 4. 本人数据范围，复用身份能力

legacy 必须显式确认登录已配置且凭据有效，再映射为稳定 local-owner；共享账号访问视为同一人，不用浏览器 session ID 伪造用户隔离。database 使用有效 AuthSession、User、Membership、Tenant 和当前权限；本期只登记 todo.read/todo.write，写入另校验 owner，平台或租户管理员不因管理身份获得他人待办入口。成员停用即失去访问，数据保留，不新增负责人接管流程。

所有列表、总数、角标、详情、历史、来源和更新都限当前 scope/owner，客户端自报 owner、租户或目录不构成授权。来源会话独立校验，创建前、查看来源时重新验证。租户切换复用身份 change 的每标签上下文；旧请求按 user/tenant/generation 丢弃，包含 A→B→A。

| 接口 | 内容 |
| --- | --- |
| GET /api/todos | status=open/completed/cancelled/all、q、overdue、page/page_size；返回授权 items/total |
| GET /api/todos/summary | 本人未完成/逾期总数、当前有效能力；用于侧栏角标，不跟随搜索 |
| POST /api/todos | title、可选内容/截止/来源及 create_key；服务端绑定当前 owner |
| GET /api/todos/{id} | 详情、可用编辑/状态操作、来源可用性 |
| PATCH /api/todos/{id} | 字段编辑或目标状态及可选说明，expected_version；owner/source/审计字段拒绝修改 |
| GET /api/todos/{id}/events | 按游标分页的处理记录 |
| GET /api/todos/{id}/source | 重新鉴权后的 Agent/session/message 定位信息，无任意跳转 URL |

七个接口操作按职责保留，删除 assignees/actions/reminder；不为追求数量把来源鉴权或历史分页塞进其他请求。summary 在 ID 通配路径之前注册。错误遵循 401 未认证、403 无功能权限、404 不存在或非本人资源、409 版本/状态/创建键冲突、422 参数错误、503 依赖或存储不可用；写入保留 CSRF/来源校验。

### 5. 一页列表、一份表单、一份详情

沿用原生 HTML/JS、现有 CSS/i18n；新增小型 todos.js，不建新前端项目。菜单显示“待办事项”和“定时任务”，保留 todo/tasks ID 及既有 scheduler API；待办副标题为“处理需要你跟进的事项”。

```text
待办事项                              [新建] [刷新]
[未完成] [已完成] [已取消] [全部]    [搜索] [只看逾期]
标题 / 分类        优先级    截止时间    状态   [处理]

详情抽屉：内容、截止、来源、处理记录
操作：开始 / 完成 / 编辑 / 取消；终态：重新打开
```

只展示本人事项，无范围选择和成员组件。四类标签及优先级可在编辑表单设置并在列表显示，首期不增加分类/优先级/Agent/今天等组合筛选。固定按逾期、优先级降序、截止升序（空置后）、创建时间降序、ID 升序排列；默认每页 20、上限 100。角标只统计本人未完成，0 隐藏、超过 99 显示 99+。

新建仅标题必填；编辑复用表单，修改截止自动留痕，不弹专用延期表单。详情抽屉在窄屏全屏。创建/更新都等服务端成功再更新列表；409 保留草稿并刷新比较，结果未知先读取确认；401/403/404 清理失效内容，503 保留输入。无事项、筛选无结果、加载失败、能力未开放分别显示。保留三语、主题、键盘焦点、未保存提示及纯文本安全渲染。

页面进入、显式刷新、成功写入和窗口重新获得焦点时更新列表/角标；不新增定时轮询、SSE 或所有状态页签的多组计数。源自其他标签/Agent 的新事项在这些刷新点显示，不承诺实时推送。

### 6. 会话接入保持轻量

手动“消息加入待办”显示可编辑预填表单，提交时再查来源权限。来源只保存引用，待办正文由用户确认；正文按待办权限保留，不因后来撤销来源而擦除用户保存的事项说明。来源删除/撤权则隐藏源正文和链接，事项仍可完成或取消。

查看来源按 Agent/session 对定位，修复现有 switchSession 只比较 session ID 的提前返回。在已有聊天能力允许的环境返回原会话，用户直接用现有输入框继续对话，不新增自动预填处理草稿、引用注入协议或恢复旧调用栈。如果原输入框有内容，保留并按既有未保存机制处理。只允许历史读取的 database 环境走已有受控历史读取路径，不调用会启动 polling/SSE 的聊天导航；该只读路径不可用时显示来源暂不可用，不为待办新建聊天运行框架。

保留 `todo` 工具 create/list/get，因为三者都复用服务且能支持“帮我记下”“还有哪些待办”。仅在经过身份验证的 Web 请求上下文中注册；legacy 为 local-owner，database 必须已有合法聊天运行和可信 user/tenant。传递请求级不可变上下文，复用现有上下文传播，不在共享工具对象上保存可串请求的主体字段。来源和 owner 由服务端注入，模型不能指定他人；scheduler、外部通道、后台自运行缺少该可信委托时不可调用本期工具。

Agent 只按用户明确要求或本次任务确有人工输入需求创建，不执行附件中的自报命令、不扫描历史补单；保存成功才返回待办 ID。不同工具调用允许创建不同事项，同调用重试使用稳定 create_key。Agent 不编辑、完成或取消待办；模型成功、消息发出、提醒送达都不能替代人工处理。确认标签不会新增 approve/reject/execute 能力。

### 7. 可交付范围与延期入口

只新增默认关闭的 todo_enabled。关闭时 summary 可向已认证用户返回能力关闭及原因，但不读取事项库或返回计数，其他事项 API/工具拒绝访问。开启后人工功能还需有效身份；Agent 工具由既有工具启用配置与当前合法聊天能力共同决定，不新增 todo_agent_enabled/todo_scheduler_enabled。工具禁用或主体不明时直接请求同样拒绝，不能只隐藏按钮。

| 本期验收组合 | 门槛与结果 |
| --- | --- |
| 已登录 legacy 人工功能 | 明确登录校验、私有存储、历史原子落盘和恢复通过即可发布 |
| legacy Web Agent 接入 | 人工功能通过，真实 Web 请求上下文传播/隔离及已有工具开关通过；这是本期必须验证的最小运行组合 |
| database 人工功能 | 身份 change 的真实主体、租户目录、todo 权限和历史读取切片通过后开放，不等待其无关模块 |
| database Agent 接入 | 仅复用该环境已验收的聊天入口与适用的 10B/08S/09G、执行隔离门槛；尚未提供时明确拒绝，本期不承诺建设完整企业聊天运行能力 |

A 为人工闭环，B 为上述最小 Agent 接入；两者都属于本期，B 不能用“留了开关”代替 legacy 实际集成验收。database 的正向消费者验收需真实身份切片，不能以 mock 当生产可用；依赖未到位须如实记录未开放组合，不把三份文档完成说成产品完成。

后续范围：

- 多人指派/转交：先明确共享、创建人可见性和离职接管，再接真实成员目录；本期 owner 保持不可变。
- 周期创建：可先新增确定性 create_todo，复用现有 scheduler 时间语义，明确自然/手动触发标识与幂等，不同时建设提醒投影。
- 自动提醒：有明确业务需求后选择独立通知或关联调度，再设计取消、在途消息和恢复语义；本期不预建接口/表。

后续项不属于本 change 的验收任务，也不能用已有独立定时提醒冒充待办联动。当前完成待办不会关闭原“每日开会提醒”等计划。

## Risks / Trade-offs

- [首期没有转交和自动提醒] → 明确延期，个人状态和截止闭环可单独使用；不声称与原稿功能完全等价。
- [删除通用幂等响应保存] → 创建仍持久去重，更新以版本防重；网络结果未知需 GET 确认，界面不能盲目报失败或重复更新。
- [当前没有可信企业主体] → 接身份切片并默认拒绝；保留单主体 legacy，不用会话 ID 冒充用户。
- [事件表作为最小审计] → 同事务、仅追加、受限读取与恢复必须真实测试；无需搭建全局审计系统，但不能回退普通日志。
- [复用旧聊天导航可能误开运行] → 区分只读来源和运行会话，按环境能力路由并回归验证相同 session 跨 Agent 场景。

## Migration Plan

1. 先备份，新增空库并保持开关关闭，不导入历史 scheduler/run；迁移按 SQLite user_version 幂等执行。未实施的旧草案无需建表再删表，直接采用两表结构。
2. 按支持环境验证登录、数据路径及事件写入，启用人工能力；再验证真实 legacy Web 工具调用后开放其工具配置。database 仅按真实依赖完成情况放行。
3. 备份纳入待办库，通过 SQLite backup API 取得一致快照；恢复包含事项、创建摘要和事件。无需为待办暂停/恢复 scheduler，原计划不被改写。
4. legacy 切 database 时复用身份域维护窗口，显式将该单主体数据绑定一个有效租户/owner；保留 ID、创建摘要和历史操作主体。来源跨租户或归属不明则阻止该批数据启用，不做自动分享/成员迁移系统。
5. 回滚关开关、保留新库与备份；旧版本忽略独立待办库，不能以旧模式读取企业数据。若已完成身份模式迁移，遵循身份域完整快照回滚，不单独回退 owner 映射。

## Open Questions

缺失 PRD 原文恢复后核对对应编号及导航归档冲突。SQLite 锁等待和分页性能阈值在实施测试中固化；不影响当前范围、接口和状态语义。
