## 1. 范围和启用边界

本期按 A（人工闭环）、B（轻量 Web Agent 接入）分阶段实施；PRD 原文恢复后再核对编号，不虚构阶段映射。多人协作、周期生成、自动提醒及调度改造已明确延期，不作为隐藏前置，也不预建表/接口/开关。

- [ ] 1.1 核对现有导航、登录、私有数据根、会话读取与工具调用接入点，确认三份规范的首期范围以及待办占位的归档接续关系。
- [ ] 1.2 增加默认关闭的 todo_enabled，接通已登录 legacy 的 local-owner 与 database 的真实主体/个人权限适配；依赖未到位拒绝访问，不解除既有聊天或通道运行限制。

## 2. A 阶段：两表存储和个人 API

- [ ] 2.1 建立独立 todo_items/todo_events 及 SQLite user_version 迁移和统一私有目录入口，验证不依赖 Agent/run、不落入通用文件可访问目录。
- [ ] 2.2 实现最少字段校验、明确时区截止、逾期派生与持久 create_key/初始摘要；测试事项编辑后原创建重试仍返回同一 ID，同键异内容冲突。
- [ ] 2.3 实现统一字段编辑和四状态目标更新，所有处理说明可选；expected_version、事项与历史同事务，旧版本重试拒绝且不重复记历史。
- [ ] 2.4 实现个人列表/summary/创建/详情/更新/历史/来源七个接口操作，含固定排序分页、状态/q/逾期筛选及统一 HTTP 错误，不增加指派、actions 或提醒接口。
- [ ] 2.5 在每个服务/API 入口验证 scope/owner 和 todo.read/write，保留 CSRF/来源校验、非本人 ID 统一不可见；来源独立授权，审计失败不得降级为成功。

## 3. A 阶段：一页列表与共用表单

- [ ] 3.1 接通待办视图、小型前端模块和菜单文案，保留 todo/tasks ID 与原定时路径，展示“处理需要你跟进的事项”。
- [ ] 3.2 实现个人状态列表、搜索、只看逾期、分页和 summary 角标，只在进入/刷新/成功写入/焦点恢复时更新，不新增轮询或多组页签计数。
- [ ] 3.3 实现共用新建/编辑表单及详情抽屉、四状态操作和分页历史；截止通过普通编辑调整，分类不强制说明，终态先重开再编辑。
- [ ] 3.4 实现创建键保留、409 草稿比较、未知更新结果先 GET 确认、503 重试及空态区分；身份失效清理和 user/tenant/generation 拒绝晚响应。
- [ ] 3.5 完成简体中文/繁体中文/英文、深浅主题、窄屏详情、键盘焦点、未保存提示和纯文本安全显示。

## 4. A/B 阶段：会话来源与最小工具

- [ ] 4.1 实现消息“加入待办”的用户确认表单、来源提交时重验和当前本人绑定，取消表单不创建事项。
- [ ] 4.2 实现来源回链与正确 Agent/session 定位，修复同 session 跨 Agent 提前返回；复用既有输入框和受控只读路径，无合格只读路径时提示不可用，不新增草稿注入或运行框架。
- [ ] 4.3 在 B 开始前验证 A 和合法 Web 请求主体传播，新增 todo create/list/get 工具并复用服务、既有工具启用配置和不可变请求上下文，拒绝无可信委托的后台/通道/scheduler 调用。
- [ ] 4.4 为工具创建提供稳定 create_key，覆盖同调用重试、不同调用独立、真实成功反馈；限制模型操作为本人创建/查询，不执行附件自报指令，不自动完成或授权外部动作。

## 5. 行为和依赖验收

- [ ] 5.1 验证最少字段、四状态、可选说明、截止设置/提前/延后/清空、终态约束，以及查看来源/模型完成不改变待办状态。
- [ ] 5.2 验证免登录拒绝、伪造 owner/租户/路径、列表计数与历史越权、来源撤权、成员停用和跨请求主体隔离；database 正向用例须接真实身份切片，不能以 mock 标记生产通过。
- [ ] 5.3 验证真实 SQLite 并发完成/取消、创建后编辑再重试、旧版本重放、事务/审计写入失败及进程重启恢复；确认只有两张业务表且无请求账本/提醒投影。
- [ ] 5.4 完成人工浏览器验收：创建→编辑→处理→完成→重开/取消、消息来源、三语主题/窄屏、网络未知/409/503 和 A→B→A 晚响应。
- [ ] 5.5 在已登录 legacy Web 中实际执行 Agent 创建/列表/详情并核对落盘结果和正确来源；工具禁用、database 仅只读、后台调用均应拒绝，不能用接口占位替代 B 阶段验收。
