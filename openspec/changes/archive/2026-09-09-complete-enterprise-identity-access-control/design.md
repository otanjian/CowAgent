## Decisions

### 1. 一个HTTP策略入口，沿用两层校验

在 `auth/http_policy.py` 登记实际匹配路由与HTTP method的public/personal/platform/tenant/closed、必要功能权限和消费者；`_WEB_URLS`仍是路由来源。`WebChannel.startup()`与测试统一调用安装processor的`build_web_app()`。覆盖测试检查所有实际方法、别名、HEAD/OPTIONS，不逐路由复制整套认证测试，也不自动把预检当作业务授权。

processor负责凭据、身份域和功能权限；handler/service保留资源归属、输入引用及返回字段控制。未登记的已存在业务方法不得进入handler，未知URL仍404。关闭消费者稳定503；其余按无会话401、缺租户400、无权403、版本/引用冲突409、依赖故障503区分，保持已有响应envelope。不可见资源与不存在统一404，普通响应不包含shared_root、密码哈希或会话凭据。

database分支先于且独立于legacy，空web_password、共享token、URL token都不授予权限。凭据选择规则固定如下：

| 请求凭据 | 处理 |
| --- | --- |
| 仅cow_session Cookie | 验证数据库会话，写请求执行Cookie来源检查 |
| 仅Bearer | 验证该数据库会话，只有认证成功才豁免Cookie来源检查 |
| Cookie与Bearer内容相同 | 认证一次，视为Cookie请求，继续来源检查，兼容旧客户端重复发送 |
| 两者不同、格式异常或所选凭据无效 | 不尝试另一个凭据；不同值400 mixed_credentials，其余按认证错误处理 |

Cookie写入与Web登录采用同一来源规则：核对可信服务origin的scheme/host/port，优先Origin，无Origin才用Referer，出现不合法来源不回退。缺来源且无独立可信CSRF证明时拒绝；现有客户端没有CSRF token流程时，直接拒绝缺来源即可，本次不另建token服务。代理提供的host/proto只有受信配置可参与判定。

Web `/auth/login` 只设置HttpOnly、SameSite Cookie，按服务HTTPS状态设置Secure；JSON兼容token字段可为空。Web登录页和请求清除旧database token、停止自动附带Bearer。原生`/auth/native/login`与Desktop成套延期，不提供Web改参数读取token的分支。既有合法Bearer会话可使用至正常到期/撤销，本次不新增原生签发渠道；Desktop在database模式明确提示尚未支持及Web管理入口，不能退回共享密码。Legacy模式独立回归。

个人/平台域忽略残留租户头，平台资格不赋予租户业务范围。tenant域必须显式选择有效租户并具备当前有效Membership。受限会话只允许最小本人读取、改密与退出。每个HTTP请求只解析一次权威身份快照，读取当前AuthSession、User、Tenant、Membership和角色；不能以缺session验证的旧revalidate helper代替认证。finally清理上下文，写入前仍在事务内重验。

### 2. 事务与认证并发使用现有SQLite能力

现`_tx()`仅返回连接，不能把Python with块当作“读版本时已获得写锁”。身份写采用短`BEGIN IMMEDIATE`事务，在同一连接重验操作者有效会话/资格、目标expected_version、租户内引用及管理员连续性，执行条件更新、必要会话撤销与成功审计后提交。条件更新影响行数不符返回409，忙锁超时或审计不可写返回503并回滚。事务由最外层服务持有，内部helper接受该连接，不另开连接提交部分结果。

密码哈希/验证放锁外完成，进入事务后核对其对应User版本和password_hash仍相同，并重验账号、凭据期限与适用会话。登录在同一事务核验后签发AuthSession：并发重置先提交，旧校验结果不能签发；登录先提交，重置须撤销该新会话。敏感改密/管理员写同理，不能凭事务外刚验证过的密码通过已撤销身份。复用已有版本字段，不新增认证版本服务；版本变化拒绝本次操作并要求重试。

成功身份变更与逐次审计同库同事务，记录真实actor和target。拒绝事件脱敏并允许按窗口聚合；审计失败不能放行，拒绝流量不能形成无界身份库写入。不引入outbox/事件总线，不把其他业务库或外部动作纳入本事务的原子性承诺。

### 3. 登录保护有明确生命周期

复用临时密码到期字段及受限AuthSession。过期临时凭据不能登录，由其取得的受限会话也不得越过该期限用于改密，须由管理员重新重置。不存在账号、错误密码、失效临时凭据采用一致失败响应；未知账号使用等价密码工作，避免明显时序分支。

bootstrap同样须写有效临时期限，首次安装在期限内完成真实管理员登录/改密后才登记既有数据或接入业务。过期则停止初始化，使用初始化前快照重新完成；不能重建已有业务库来恢复身份。验收必须使用allow_weak=False，不能用绕过强制改密的测试账号证明首次登录可用。升级前先在兼容旧流程中完成原NULL期限bootstrap账号改密，确认至少一名已完成改密的有效平台管理员可用；未满足则停止升级，不能先锁住账号再要求管理员登录重置。

使用应用生命周期共享的有界限流器，不能把计数放进每请求新建的IdentityService。按规范化账号与可信来源分别限制，直接连接地址为默认来源，仅受信代理可提供转发地址。单进程Web是本期部署基线；未具备共同计数的多worker/多实例不列为支持配置，已知不受支持的worker配置启动时拒绝；不为尚未存在的多实例部署引入Redis，也不宣称进程内计数跨重启持久。

初始默认：账号15分钟最多10次失败、来源15分钟最多100次失败，任一超限返回429和Retry-After；阈值/窗口允许有界配置。计数键有TTL及容量上限，默认每类10,000项；容量满时新键受限，不能靠驱逐仍有效计数绕过。拒绝审计记录首次/阈值及窗口计数，避免逐次写入攻击流量。新临时密码默认24小时有效，受限会话TTL取凭据剩余期限与既有会话TTL较早者。普通会话TTL及PBKDF2算法不变；只有调整哈希成本才做性能测量，安全期限采用策略与边界测试，不建设基准项目。

### 4. 管理服务补缺口，复用现有查询

| API/服务 | 本次增量 |
| --- | --- |
| GET `/api/platform/users` | 接通已有列表服务，q/status/page/page_size、平台权限、白名单字段、一致total |
| PATCH `/api/platform/users/{id}` | 全局启停/平台管理员标识、expected_version、平台权限及管理员连续性 |
| POST `/api/platform/users/{id}/reset-password` | 服务端生成限期临时密码，一次响应、强制改密、全会话撤销和审计 |
| 现有平台租户collection/detail/admins | 名称修改与搜索分页，接通管理员配置/独立启用，复用目录校验 |
| 现有 `/api/tenant/members` | 接通q/department/page与两种创建模式，仅补status/role筛选及role_codes，先过滤去重再分页/计数 |
| 现有成员detail | 省略roles保留，[]返回400；显式替换校验本租户角色/最后管理员，资料变更不改变授权 |
| 现有角色/部门API | 按需汇总角色人数，关联成员复用role/department过滤，树使用parent_id/sort_order；无专用复制或树成员API |
| `/api/identity/audit` | actor/action/result/time筛选分页，平台与本租户管理员显式分域 |

敏感平台操作复用当前请求`recent_password`复核操作者密码，不新增“近期验证凭证”、二次登录token或状态机；事务内仍核验密码版本有效。平台重置不能直接暴露内部`_set_password_for_user`。响应丢失后不取回旧临时密码，须读取新版本再重置并产生新密码、新审计。

管理员重置接口拒绝target=actor，本人使用既有改密入口；避免唯一管理员自我重置后因响应丢失或临时期限耗尽失去管理入口。管理员主动停用/降级自身时，事务内须确认还有另一名已完成改密的有效平台管理员；这只补平台连续性谓词，不引入恢复命令或资格状态机。

平台至少保留一个活跃管理员，活跃租户至少一个活跃User的活跃tenant_admin。全局停用须检查受影响活跃租户，成员停用只影响当前Membership；全局停用/重置撤销账号所有会话，恢复不复活旧会话或独立停用的成员。停用租户可先补管理员再单独启用。

bind-existing通过精确用户名复用已有服务，不改变全局密码或其他租户资料，不为租户管理员新增全局账号搜索；新建冲突不自动变成绑定，停用成员不自动恢复。角色复制用读取后create_role，只复制可分配权限，不复制成员/内置标识/管理员资格；空权限自定义角色合法，不补member默认权。

新租户目录由服务在部署受控根内生成，普通表单不接受shared_root；复用canonical path/软链/根互含保护，保留合法原地登记。缺受控根明确报配置错误，创建失败不留可用租户；不另建目录生命周期服务。已有CLI `register --admin-username`精确选择指定账号并验证租户资格/归属，不按列表排序取首项；新增CLI账号命令延期。

### 5. 九权限目录与四管理页

本期只维护九个ID：tenant.info.read、tenant.members.read、tenant.org.read、agent.read、history.read、knowledge.read、memory.read、todo.read、todo.write。补group/label/description/scope/assignable元数据，tenant_admin显式默认九项，member保持除成员/组织读取外的七项；自定义角色采用显式并集。

修改default_permissions_for、_admin_permissions及通用功能guard中的tenant_admin短路，不能只改目录函数。平台/租户身份写入仍按独立管理员资格；资源私有owner、合法共享及待办仅本人的条件保持原样，不借本次治理扩大数据范围。测试证明目录将来增加条目不会自动赋给旧角色，生产目录不预注册延期的执行权限。

保留一个GET `/auth/context`：显式选择有效租户后，只返回本人effective_permissions、管理资格和静态消费者状态/原因，不要求tenant.info.read，不返回租户资料/其他成员/凭据。零权限成员可得到空权限集合。无租户的平台管理员使用`/auth/me`中的个人/平台资格，不强迫选择租户。受限会话不得调用context，`/auth/me`不扩展为全租户权限批量计算。前端只缓存本页展示，后续API独立鉴权，不建权限同步服务。

四菜单复用现有组件：用户页增加平台账号页签；租户页补资料/管理员；角色页补分组/复制/关联成员；组织页将已有平面部门转树并联动同一成员列表。审计放在已有管理区，不新增顶层导航。只读用户只请求有权的租户资料/成员/组织，不请求平台列表或显示写按钮。

409保留当前表单并提示冲突，可重新加载，重载前提醒丢弃修改；不自动合并、不持久化草稿、不做版本差异比较。401/403/503复用错误组件，不能显示为成功。重置密码只在成功响应展示一次，关闭清空，不写storage/日志。

复用账号菜单unknown/退出重试、整页刷新式切租户和user/tenant存储helper；管理表单接未保存保护，局部请求沿用generation防迟到响应串租户。新页面先用/me验证目标再保存选择，不新建SPA切换框架。首页、can_chat及轮询按实际消费者状态工作，关闭能力显示原因，历史/待办来源导航不能隐式启动执行。

### 6. 完成条件与明确延期

A提供鉴权/事务/关闭边界，B接通管理服务与页面。开始B切片前检查实际使用的A依赖；独立表单、树呈现和查询接线可并行。对应写接口在授权/事务测试通过后才能开放，A/B联合发布完成全部适用验收，开发并行不降低发布门槛。

现有管理及已验收受控读取纳入交付。HTTP聊天归属补丁不能证明Bridge、工具、长流撤权和依赖切片齐备；本change不移除运行关闭保护。若其他change已有真实接入证据，按消费者核对并保留已验收行为，不机械恢复旧断言。复用现有开关及静态策略表示状态，不新增readiness服务或依赖引擎。

| 延期交付 | 后续起点与避免复杂化的约束 |
| --- | --- |

| 钉钉SSO | 先一个provider、一种绑定流程及Web登录，验证稳定身份/一次性state/并发解绑。关联会话须有绑定来源字段，或明确接受全账号撤销的产品代价；不同时预做任意绑定/重绑体系。消息sender与SSO subject映射独立验证，不顺带承诺通道支持。 |

| CLI账号操作 | 本次仅修register归属；有明确运维需求后新增交互式查询/重置，复用服务，不以客户端声明用户名取得维护权。 |

以上属于从原方案移出的范围延期，不计入当前specs/tasks，也不计为已完成；原对比中的技能、模型、SSO和企业多端差距仍存在。

## Risks / Trade-offs

- [统一processor掩盖资源越权] → 保留handler/service的租户、owner和白名单检查；策略完整性测试与危险操作行为测试分工。
- [双凭据兼容绕过CSRF] → 同值按Cookie来源处理，不同值/异常值不回退，新增Web登录不返回token。
- [旧密码或管理员资格在并发后继续有效] → 短写事务内重核当前会话/资格/密码版本，签发与撤销共用连接并明确提交顺序。
- [SQLite被拒绝事件占满] → 应用级有界限流、失败聚合，成功审计仍逐次同事务；不宣称多实例已支持。
- [收口误认为完成全部对标] → proposal/review/延期表一致，运行、SSO、Desktop企业功能不计入通过。
- [工作区及相邻change变化] → 按版本记录证据，不改其他change勾选，归档前核对接口与关闭/开放规范。

## Migration Plan

1. 盘点身份/角色、活跃管理员、目录与当前消费者，确认精确迁移账号，保留User/Membership/Agent ID。升级前验证至少一名已完成改密的有效平台管理员；原bootstrap的NULL期限在旧流程完成改密，不能在唯一管理员仍受限时升级。
2. 维护窗口停止身份写入，备份identity.db及受影响配置/租户根登记；原地登记涉及的业务目录纳入对应快照，不为未变动业务库另建全量迁移项目。
3. 复用既有表/版本字段，仅对实际需要的字段或索引执行schema_migrations，无需变化则不加schema版本；禁止预建五张延期表，不改私有/共享归属。
4. 保留tenant_admin九项、member七项及自定义角色权限，Web停止旧database token存储并改Cookie契约，legacy独立回归。已有临时凭据期限缺失/非法时拒绝使用，由管理员重置，不赋永久期限。
5. 隔离副本演练重复执行、失败回滚、忙锁、目录创建失败及恢复；发布A/B管理闭环，未验收运行与企业Desktop保持不可用。
6. 回退使用兼容身份库的代码或恢复一致快照，不能切identity_mode=legacy、删迁移标识或改共享密码绕过database数据保护。
