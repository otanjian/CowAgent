## Context

动机和范围见 [proposal.md](proposal.md)。当前实现是静态 HTML、CSS 与单文件 JavaScript；原导航迁移已有实施记录，本轮在独立历史页上增量实现外观调整和标题搜索。下面记录原迁移接入点，不能将原面板描述理解为仍需重建的当前状态。

| 接入点 | 当前行为与迁移关注点 |
| --- | --- |
| `channel/web/chat.html` | 工作台 `data-group="chat"`；中间 `#session-panel` 持有新建入口与 `#session-list`；顶部 `#session-toggle-btn`、专属 `#session-panel-overlay` |
| `console.js` 的 `VIEW_META`、基础与包装后的 `navigateTo()` | 菜单激活、面包屑、视图隐藏、未保存确认与懒加载；智能体页还记录并恢复历史面板开合 |
| `onNewChatButton()`、`newChat()`、`switchSession()` | 新建/切换复用现有聊天状态；新建强制展开历史，切换在手机关闭面板，均需去除旧布局联动 |
| `loadSessionList()`、`_fetchSessionPage()`、`_renderSessionList()` | 使用现有 `scope=all` 列表，含时间/项目分组、项目排序折叠、智能体身份及会话操作；滚动绑定唯一 `#session-list` |
| 回复完成与自动标题刷新、登录初始化 | 依赖 `sessionPanelOpen`、`_restoreSessionPanel()`；迁移后不能依赖开合状态 |
| `channel/web/static/css/console.css` | 固定 220px 中间栏与 768px 历史抽屉/遮罩规则；主导航采用 1024px 断点 |

当前已存在 `#view-history.history-view`、`_historyVisible`、列表请求序号和唯一滚动容器；列表尚未携带搜索词，行仍以窄侧栏样式展示。后端 `SessionsHandler.GET` 支持单智能体和 `scope=all` 聚合，`ConversationStore.list_sessions()` 已按 channel/user 限制并排序分页。工作区存在其他未提交改动；按最新函数定位并局部编辑，保留相邻导航与身份改动。

## Goals / Non-Goals

**Goals:**

- 使用既有视图架构承载历史列表，保留唯一列表及会话数据来源。
- 将面板开合依赖转换为历史页生命周期，维持聊天运行、草稿和未保存保护。
- 在移除旧布局的同一交付中完成桌面/手机、三语与主题适配。
- 使用统一内容宽度和轻量列表层级，提供全部授权历史的标题搜索，保持搜索与分页、行操作和自动刷新的状态一致。

**Non-Goals:**

- 不新增 API 路径、数据库、全文索引或路由框架；不搜索消息正文，不增加高级筛选、批量管理或虚拟列表。
- 不修改 Electron Desktop 页面结构，不调整会话数据权限、运行权限及历史保留策略。

## Decisions

### 1. 新增工作台内部视图 `history`

在工作台「对话」后提供 `data-view="history"` 菜单和 `VIEW_META.history`，复用 `session_history` 三语文案；内容容器沿用已实现的 `#view-history.view.history-view`。沿用 `/chat` 控制台内部切换机制，不新增浏览器 URL 或恢复页签持久化。

布局为「左侧主导航 + 主内容」，历史页内为标题/新对话操作区和下方可滚动列表。将现有 `#session-list`、`#new-chat-menu`、`#new-chat-caret` 移入页面，保持各 ID 唯一；保留共享多智能体弹窗。只调整容器，不维护第二份列表。

选择独立内容页是为了彻底释放其他页面的栏位并符合菜单导航。仅把展开按钮搬进菜单仍保留中间栏，不满足用户要求；将所有记录内嵌主菜单则会挤压已有功能入口。

### 2. 清除专属开合状态，复用受保护的导航

删除旧 aside 外壳、关闭/顶部按钮、专属遮罩及面板开合 CSS/JS；覆盖智能体进出、新建、切换、初始化和 tooltip 调用点。停止读取和写入 `cow_session_panel_open`，旧值忽略即可；不得清空其他 localStorage 项，项目折叠偏好、活动会话与智能体持久化继续使用。

历史加载接入现有导航链，只有未保存确认通过且视图实际切换成功后才加载/更新高亮；基础 `navigateTo()` 可能早退，包装层不能假定调用即成功。保留日志停止、文档编辑、品牌编辑、工作空间可见性等其他视图行为。移动端沿用主导航收起逻辑，不新增历史抽屉。

不保留空壳开关函数作为长期兼容层：它们属于本页内部实现，统一更新引用并通过静态检索和真实交互确认无遗漏。删除前核对 `_isMobileView()` 等通用辅助函数是否还有其他用途。

### 3. 保留列表渲染和操作，以视图状态控制刷新

沿用现有 `/api/sessions` 分页参数与 `scope=all`，该参数继续受服务端现有授权约束；复用数据结构、分组、排序和操作调用，包括非默认项目的重命名与删除，不扩大返回范围。首次进入及重新进入历史页读取最新列表；回复完成、自动标题更新和其他会话变更在可见时刷新，隐藏时标记待刷新，不改变当前视图。

保留唯一可滚动 `#session-list`，使用 flex 剩余高度、`min-height: 0` 与纵向滚动，迁移后在大屏不足一屏时也能继续加载至可滚动或无下一页。沿用现有分页大小，无新增持久化缓存。刷新用请求代次/上下文校验约束迟到结果，分页不重复请求同一页；失败不推进页码并允许重试。

区分首次加载、成功空态、加载失败和模式未开放。第一页重读失败可显示错误并禁用过期记录，后续页失败保留已确认记录。自动刷新避免打断正在进行的行内重命名或项目拖动，待交互完成后应用待刷新结果。沿用安全文本渲染，新增文案进入现有三语字典。

### 4. 在确认后提交会话切换

浏览历史页只切换视图，不执行 `newChat()`、改写 `activeAgentId` 或中断 SSE。选择记录仍复用 `switchSession(sessionId, agentId)` 和既有消息加载/工作空间恢复链路；相同当前会话只返回聊天。行操作不冒泡触发打开。

原 `switchSession()` 曾提前更新 `activeAgentId`，且未保存回调未保留 `agentId`；沿用迁移后的守卫和目标 `(agentId, sessionId)` 传递，通过导航和工作空间守卫后再提交身份/会话变化，取消保持原状态。快速选择以最近一次已确认选择为准，迟到消息不能写入另一会话。复用已有后台流管理，不重建运行系统。

新建仍调用单智能体/多智能体的现有流程并进入聊天，移除自动展开面板。行内重命名等处理器显式携带所属 `(agentId, sessionId)`，不能仅依赖当前活动智能体。删除继续使用现有确认、目标运行取消及清理接口；当前会话删除成功后接续相邻会话，没有其他会话则进入未持久化新对话。浏览与导航不停止运行，用户主动确认删除保留其原有取消语义。

### 5. 与相邻 change 和身份模式集成

菜单最终相对顺序为「对话 → 历史会话 → 智能体 → 待办 → 定时 → 场景应用」；智能体使用页/配置页拆分与待办显示名继续归对应 change。合并时以本 change 替换 `split-agent-configuration-and-workbench` 中过时的历史面板恢复任务，不能恢复中栏；归档按最终生效菜单统一规范，不同时保留相互冲突的邻接约定。

本次不新增 feature flag。沿用当前部署模式，未开放的读取/运行/写入显示既有说明；如果 database 模式生效，使用身份 change 已验收切片，不以 UI 调整开放消费者，也不在本次实现身份子系统。历史读权限不隐含新建/继续聊天权限。

### 6. 页面视觉与操作布局

标题/工具栏、搜索条、状态与列表共用最大约 1160px 的居中容器，桌面横向留白约 24～32px，手机缩减为 16px。列表使用白色/深色主题表面、轻边框和有限圆角，保留时间/项目分组；每行以标题为主，智能体/工作空间为次，右侧显示 `last_active`，当前会话用浅绿底及文字标记。只展示已有元信息，不请求消息摘要。

新对话使用明确主按钮，刷新为次要按钮。置顶/取消置顶、重命名、删除收进行「更多」菜单；菜单可用键盘/触摸，Escape/外点/滚动/离页关闭。菜单采用独立浮层防止被列表滚动裁剪，重命名仍使用行内输入，事件不冒泡打开会话。保留多智能体头像与项目管理能力。

搜索框按用户最新箭头标注放在标题块右侧，与右侧刷新/新对话操作同排；桌面搜索宽度随可用空间在约 320～420px 间调整。输入框说明为「搜索会话标题」，提供清空按钮；匹配数量在下方轻量展示，无内容时不占空行。窄屏自动换行，不能挤压标题或把按钮推到列表宽度以外。

### 7. 可选 `q` 的服务端标题匹配

`GET /api/sessions` 增量接受 `q`，服务端 trim 后限制 100 个 Unicode 字符；超长返回明确输入错误，不截断成另一查询。关键词为空或未传时走既有分支。仅匹配已存储会话标题的连续字面子串，英文 ASCII 大小写不敏感、中文直接匹配，`%`、`_`、引号等不具备通配符或 SQL 语义。

`ConversationStore.list_sessions(..., q='')` 将参数化 `instr(lower(title), lower(?)) > 0` 与既有 channel/user 限制组合，COUNT 和 SELECT 共用过滤条件，先过滤再排序分页。`scope=all` 只遍历现有授权范围：非空 q 收集授权匹配摘要，按既有去重优先级与置顶/最近活跃顺序合并后计算精确 total 并分页，不能只筛当前页或任意截断候选。空 q 保持旧客户端路径与字段兼容，不读取消息正文或引入搜索服务。

### 8. 搜索与列表生命周期

维护内存中的关键词、请求代次和查询上下文；输入约 300ms 防抖，中文输入法组合阶段不发请求，Enter 立即提交，清空立即恢复未搜索第一页。查询变更立即使旧响应失效，搜索的页码、total、has_more、错误与重试绑定同一关键词。迟到响应不能清除新请求的 loading，也不能追加进另一查询。

提交和刷新以输入框当前值为准，再同步内存关键词；不能只依赖此前是否收到 input 事件。Enter、change 与浏览器原生 search 事件均有提交/清空路径，改变关键词时取消旧请求，同词在途请求仍去重。明确非组合的 input/Enter 或已提交的 change/search 可恢复过期的组合输入标记；`isComposing=true` 或确认输入法的 `keyCode=229` 继续禁止提交半成品。

搜索结果保留会话打开及行操作；重命名、删除、自动标题/活跃变更后按当前 q 重新读取，不把不匹配的乐观新会话插入结果。搜索期间使用扁平结果列表，展示智能体/项目元信息，避免持久化折叠组隐藏命中；清空恢复原分组、折叠和排序，不把搜索结果排序写回项目偏好。离开历史页保留本页内存搜索词、取消待发请求；重新进入按该词刷新，退出/身份切换清空搜索及结果，不写 localStorage。

首读显示搜索中、成功无结果显示「没有匹配的会话」并可清空、失败显示可重试错误；旧后端不支持 q 时不得把全量列表当成搜索结果，响应增量回显 `query` 供新前端核对（空 q 无需此字段）。新后端与前端同批发布，先部署后端可兼容旧前端。

## Risks / Trade-offs

- [开合引用分散，删除 DOM 后可能静默失效] → 对旧 ID、状态、函数及 CSS 做引用检索，覆盖登录、新建、跨页与标题自动刷新。
- [新页面更高，分页哨兵和滚动容器可能失效] → 验证超过两页数据及首屏不溢出时的继续加载，确保全部历史可达。
- [跨智能体切换先写状态导致取消后归属错误] → 守卫前保留目标，确认后统一提交，回归取消与快速选择。
- [其他 change 修改相同导航函数] → 保留已生效功能和守卫，仅合并必要差异；旧历史面板恢复约定明确失效。
- [仅过滤已加载列表会漏搜] → 服务端授权范围内先匹配后分页，针对深页命中和多库去重验证 total/has_more。
- [输入变化、分页及自动刷新竞态] → 关键词/请求代次绑定，旧响应无权改写新 loading 或列表；中文组合输入完成后才提交。
- [大量标题匹配消耗聚合内存] → 只读取摘要且分批读取，不读正文；真实数据量记录查询耗时，保留以后优化查询的余地，不在本次引入全文系统。

## Migration Plan

1. **PRD-02 增量准备阶段**：核实当前导航及会话 API 行为，记录相关 change 的有效状态。PRD 原文恢复后补充映射；未恢复时以用户确认和现有代码作为本次调整依据。
2. **实现阶段门槛**：在有效导航基线及当前模式接口可用性确认后，同批交付 HTML、CSS、JS 和支持 q 的后端；后端可先于前端部署。若模式不支持某项能力，维持关闭并验证提示，不为展示效果绕过后端。
3. **验收阶段门槛**：执行规范场景，特别是旧偏好刷新、跨智能体切换、分页、后台生成和未保存取消；真实验证当前启用模式。database 未启用时记录未验证范围，不能宣称其隔离已通过。
4. **数据与偏好**：无业务数据迁移；只废弃面板开合偏好，不改会话 ID、存储、工作空间或其他偏好。
5. **文档与恢复**：更新 Web 说明中的历史入口、标题搜索及更多菜单。搜索回滚先回退新前端，再按需回退可选 q 后端逻辑，保留其他 change 与所有业务数据；原面板偏好仍可被迁移前版本使用。
