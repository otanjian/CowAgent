## Why

历史会话原来占用导航与主内容之间的独立栏位，现已迁至「工作台 → 对话」之后的独立页面；当前列表仍存在灰条过重、内容层次不足和操作对齐松散的问题。用户进一步要求优化页面并增加按会话标题搜索，以便从全部可访问历史中快速找到并恢复对话。

## What Changes

- 在工作台新增「历史会话」菜单，排列为「对话 → 历史会话 → 智能体 → 待办 → 定时 → 场景应用」，其他功能名称以后续已生效 change 为准。
- 点击菜单在主内容区打开历史会话页，菜单激活、页面标题和面包屑统一为「工作台 / 历史会话」。
- 移除中间历史会话栏、顶部展开按钮、面板关闭按钮和专属移动端遮罩；聊天及其他业务页面均不再保留其栏位。
- 将现有新对话入口、历史会话列表及其时间/项目分组、项目排序/折叠/重命名/删除、滚动分页、置顶、会话重命名、自动标题刷新和会话删除操作迁入新页面；选择历史会话后进入「对话」并恢复原会话及智能体归属。
- 清理面板开合偏好及联动，保留业务会话、聊天草稿/运行状态、工作空间与离页确认；补齐加载、空态、失败重试和响应式展示。
- 优化独立页面：标题、搜索与列表共用居中内容区；搜索框按用户最新截图移至标题右侧，与右侧「新对话」同排，窄屏自动换行；列表展示智能体/工作空间与更新时间，使用浅绿当前会话标记、绿色「新对话」主按钮，行操作收进「更多」菜单。
- 增加会话标题关键词搜索，覆盖全部有权访问历史后再分页；支持中文和英文大小写不敏感的字面子串匹配、清空恢复、无结果/失败提示及连续输入时的请求隔离，不搜索消息正文。
- 范围限定为截图所示 Web 控制台。增量扩展既有列表 API 的可选搜索参数，不新增 API 路径、会话存储、搜索服务或 Desktop 菜单改造。

## Capabilities

### New Capabilities

- `session-history-workbench`: 历史会话在工作台的菜单入口、页面布局与标题搜索、原有会话操作迁移、旧面板移除及会话状态兼容。

### Modified Capabilities

- 无。当前 `openspec/specs/` 尚无正式基线，本次新建规范覆盖既有产品能力的入口迁移。`prd-02-platform-navigation` 的工作台菜单顺序，以及 `split-agent-configuration-and-workbench` 的历史面板恢复和智能体相邻位置约定，归档合并时以本次明确要求调整；本次不改写其他 change 文件。

## Impact

- **需求依据**：用户 2026-09-08 的截图、迁移要求及「工作台分组内，紧接对话之后」的确认；对应项目 PRD-02 平台导航 v1.2 的增量调整。配置提及的 `doc/优化规划/PRD/` 原文当前缺失，尚未逐条核对，恢复后补充映射。
- **补充需求依据**：用户要求按已展示建议执行页面调整，并确认搜索范围为会话标题，覆盖全部可访问历史。
- **接入点**：`channel/web/chat.html`、`channel/web/static/js/console.js`、`channel/web/static/css/console.css`、`channel/web/web_channel.py`、`agent/memory/conversation_store.py` 与 Web 使用说明。沿用现有视图导航和三语文案体系。
- **数据唯一归属与兼容**：历史记录继续归既有业务 session/会话存储与 Agent 所有，不复制记录、不迁移 ID。既有 `GET /api/sessions` 增加可选 `q`；不带参数或空关键词保持旧列表语义和响应字段，搜索结果总量/分页基于匹配会话。AuthSession 与业务 session 保持分离。
- **跨 change 依赖**：接续 `prd-02-platform-navigation` 已有导航骨架；合并 `split-agent-configuration-and-workbench`、`add-workbench-todos` 时保留其功能入口，移除已过时的历史面板恢复要求。若启用 `add-tenant-identity-access-management` 的 database 模式，沿用其已验收读取授权及写入/运行关闭门槛，本 change 不开放受限消费者。
- **交付状态**：原导航迁移的实施记录和未完成验收保留；本轮新增页面优化与标题搜索任务并依用户授权实施，按真实验证结果更新勾选。无新增运行时依赖、独立 feature flag 或数据库迁移。
