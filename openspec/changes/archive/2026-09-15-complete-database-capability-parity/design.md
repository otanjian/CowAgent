## Goals / Non-Goals

**Goals:**

- 对齐产品规划 3.1，使本人维护、公共维护、实际执行与治理元数据成为不同授权动作。
- 复用现有身份和业务存储，补齐真实 Web/Desktop 入口，并保持后续 master 功能更新可合入 rdai。
- 让每个切片都有正常、拒绝、并发、恢复和真实传输证据；按切片实施，按完整覆盖条件收尾。

**Non-Goals:**

- 不恢复共享密码、免登录、旧 HMAC、任意宿主机浏览或管理员读取私有内容。
- 不重建 scheduler、Agent、记忆引擎、渠道身份库或第二套个人控制台。
- 不将“所有微信提供方都支持多人多实例”当成既有事实；适配器需要实现并验收所选接入形态。
- 不在提案阶段改业务代码、迁移真实数据或执行 master/rdai 合并。

## Decisions

### D1. 以 3.1 职责形成授权矩阵和完成清单

租户业务的授权顺序固定为有效会话、有效租户与 Membership、实际资源归属、允许动作、运行条件。账号设置等个人身份域及平台接口不要求租户选择，平台接口独立验证当前平台身份；个人记忆、个人渠道等租户内个人业务仍要求有效租户，不按 URL 中是否含 personal 判断豁免。私有对象的非 owner 拒绝位于平台 `all` 与租户管理员公共权限判断之前。治理信息只含必要归属、数量、用量及治理状态，不含任务标题/提示词、记忆正文、目录内容、消息和密钥。

### D3. 稳定接缝负责授权，上游业务实现保持单一

建议在 fork 自有模块中组织 `database_scheduler_handlers.py`、`memory_console_handlers.py`、`project_browser_handlers.py`、`scan_onboarding.py` 和能力登记；这些是拟新增位置，不表示当前已经存在。handler 只协调授权目标、业务服务与错误映射。身份解析只经现有 `auth.runtime`，调度执行身份只经 `agent/tools/scheduler/identity.py`。

对于新增路由使用现有 fork 扩展注册。对 10 个既有路由使用明确的 handler/策略适配；若注册器不支持替换，补入仅对指定既有路由生效的替换接缝，检查原 handler 来源与方法集合，发生漂移即要求登记。禁止重复追加同一 URL 依赖顺序遮蔽，也禁止复制第二份 `_WEB_URLS` 或策略表。

前端使用独立 JS 模块和既有 fragment 挂载点，`console.js` 仅保留稳定调用；Desktop 使用请求上下文装饰器和账号/租户 gate，`client.ts` 的业务方法和上游新增接口共用该入口，不逐方法散布 fork 分支。

上游独立分发可以保持其原有语义；rdai 的 database 运行若缺失强制授权接缝，必须拒绝消费者启动或调用，不能以可选模块缺失为由运行旧无身份 handler。此处区别于仅影响外观的可选扩展。

### D4. 定时管理面与后台执行共用目标解析

**D3 接缝回退规则的适用边界**：上游独立运行仅指由独立构建/发布装配明确选择、且不挂载 rdai 身份库或业务数据的上游发行形态；可选外观或界面接缝缺失可以退回上游展示，但不能扩大后端权限。rdai 发行形态的强制授权接缝集合必须由独立于待加载扩展的启动装配声明并检查，缺少身份、owner、租户、工具、任务执行或请求传输的必要接缝时，受影响能力返回不可用或启动失败，不能注册旧免鉴权处理器。不得以请求参数、插件停用或普通运行时开关将 rdai 伪装成上游独立运行。主规范中的“接缝可独立启用与回退”同步以 MODIFIED requirement 收敛此边界；合并验收分别覆盖独立上游、完整 rdai、rdai 强制接缝缺失及仅可选 UI 接缝缺失四种形态。

任务正文继续保存于既有 TaskStore，保留任务 ID、schedule/action、通知会话、接收目标、`silent` 与未知上游字段。增加必要的 owner/scope/schema 或 revision 元数据时使用兼容扩展；不得迁出一套与后台不同的定时数据库。授权接缝必须同时覆盖 HTTP 管理、`SchedulerTool` 对话调用与后台执行；工具声明 `self_authorized=True` 仅表示它必须自行完成同等对象授权，不能作为免检依据。

新个人任务由当前可信 tenant/user 生成 owner，选择公共 Agent 不会使任务变成公共。工具的 create/list/get/delete/enable/disable 全部进入公共授权服务，而不是直接操作按 Agent 共享的 TaskStore。创建时从可信请求或消息执行上下文解析当前有效身份、租户、资源授权与配额，原子写入 owner、scope 和 revision；上下文缺失、身份服务异常或 owner 快照失败必须拒绝创建，不能告警后保存无 owner 任务。客户端参数与工具参数均不得覆盖服务端归属。

列表先解析并过滤允许访问的存储与任务，再排序、计数和分页，不能先扫描返回全局 Agent 任务再由前端隐藏。详情、手动运行、启停、更新、删除都重新从真实任务解析 tenant、owner 和 Agent，拒绝客户端改写 owner、tenant、存储路径或未经验证的接收目标。HTTP 与工具共用动作矩阵、配额检查、脱敏审计和错误契约；同一公共 Agent 的其他成员不能读取、修改或推断本人任务正文及通知接收信息。

公共任务只有在存量有明确公共归属及执行主体时进入本租户的独立管理范围；租户管理员的公共权限不延伸到成员任务，平台治理入口不下发正文。机器执行主体使用真实服务账号授权模型，不伪造 Membership；缺少相应执行适配的公共任务保持隔离。

任务修改通过现有存储写锁或原子条件更新支持 revision；版本判断与写入不可分离。工具、HTTP、后台任务状态写入与迁移必须使用同一协调机制，不得通过直接写 TaskStore 绕过并发控制或丢失隐藏字段；不支持跨进程协调的部署形态不得开放多个写入者。手动运行使用幂等键生成一次入队，入队时与实际触发时均重新授权，并沿用既有资源分发前重验。审计及任务文件不在同一事务时采用持久化操作记录和补偿；不得先产生执行副作用再因审计失败谎报失败可重试。

停用阻止后续新触发，不假称撤回已开始的外部调用；删除正在运行的任务返回可处理冲突，若既有取消接口可用则明确区分请求取消与取消完成。

**BREAKING（历史无身份任务）**：缺少可信租户/owner 的旧任务保留内容但隔离停用，不再通过 `owner=None` 跳过 database 授权。迁移仅依据可信身份/会话记录回填，不按当前管理员、默认 Agent 或文件路径猜 owner；恢复需明确归属及资源复验。

### D5. 记忆兼容读只做作用域适配

`/api/memory` 与 `/api/memory/content` 保留已支持的列表/内容响应字段和分页参数。新增明确作用域：个人记忆为当前 tenant/user；私有 Agent 记忆要求目标为当前租户且本人拥有；公共 Agent 记忆按既有共享读取授权单独呈现。旧 `agent_id` 可解析为原 Agent 视图，但绝不退回租户共享根读取个人数据；无目标的个人入口只解析本人个人域，未知 category 或不明确归属拒绝。

复用已交付的 owner、可信 tenant/user 根、相对条目 ID 和接口字段，但不把相对路径正则或兄弟 change 勾选当成实际路径隔离证据。当前 `_target()` 只拼接路径，列表与正文读取会跟随软链接；因此任务 5.1 的安全前置尚需补强。修复必须位于原 `PersonalMemoryService` 的共同文件访问层，覆盖根目录、中间目录和条目文件的真实归属，并在枚举、读取元数据/正文、写入、删除及清空实际使用时执行。使用锚定可信根的受约束文件访问或同等防替换机制，不能检查后再次按可替换路径无约束打开；跨根软链接、替换或不可验证的归属应拒绝，不读取后再过滤。现有 `/api/memory/personal*` 与新兼容入口共同接入。

**正文、索引与清空是同一发布边界**：当前 save 在正文写锁释放后调用 `_after_write()`，可能发生“正文已保存 -> clear 删除正文并清理索引成功 -> 原 save 重新写入旧索引”。本 change 在原服务补入按 tenant/user 协调的操作版本和清空 generation，将正文提交、索引发布、删除/清空及后台回写纳入同一并发协议。每个发布者在最终提交时重验作用域、条目/操作版本及 generation，校验与发布不可分离；过期保存、索引同步或固化不得恢复旧内容，也不得删除较新版本的索引。

文件与多个索引不能原子提交时，复用并补强持久化操作记录和屏蔽标记：先建立可恢复状态，再执行副作用；未完成时报告 pending/incomplete 并阻止旧正文被检索，不提前宣布清空成功。重启后的重放仍须校验版本，状态损坏或无法确认安全发布时拒绝放行，不能清空屏蔽记录后当作成功。交付形态若仅支持单写进程，须显式限制多写者，不能把进程内锁宣称为跨进程原子性。不得另外建立第二套个人记忆 CRUD 或检索真值。

列表、正文、搜索、导出、工作区别名、下载、预览与检索必须得到同样的允许集合。个人清空不操作公共记忆、知识库或他人内容。以受控并发屏障覆盖保存/清空、索引同步/清空、旧固化发布/清空和失败重启，不能仅验证“清空后再启动一个旧任务”的顺序场景。路径修复与共享发布协议是新入口开放及完整记忆交付的前置，原个人写入接口也必须一并回归。

合并接缝同时登记 `agent/memory/personal.py`、`agent/memory/manager.py`、`agent/memory/summarizer.py` 及实际记忆工具发布路径。master 新增同步或回写入口时必须进入同一授权和版本协议，保留上游公共签名；缺失强制发布接缝时在 rdai 拒绝该写入，不绕回旧直接落盘路径。

保留旧 `admin.memory` 深链接的已登记作用域，向个人页提供明确导航，不把公共管理 URL 静默解释为个人管理。

### D6. 项目浏览恢复为个人根内选择，本机项目通过导入接缝接入

Web `GET /api/projects/browse` 以当前 tenant/user 的 projects 根为入口；返回相对目录标识、面包屑和有界父级，保留旧界面需要的字段但不泄露无权绝对路径。历史绝对路径只有在服务端证明位于本人授权根内时可兼容归一化，其余拒绝。目录读取和最终选择均重新解析真实路径，防止检查后软链接被替换；会话归属也要一致。

租户公共工作区继续走既有工作区授权入口，不因个人项目浏览而取得全共享树权限。平台文件根仅承担其原只读职责，也不能浏览嵌套成员私有目录。不能用 `agent.read`、平台 `all` 或字符串路径前缀当作个人目录许可。

对原先“打开本机任意目录”的需求，采用 Desktop 原生选择后的受控复制导入，完成后选择本人根内的新项目。沿用本机导入的 loopback 与每启动令牌校验，再叠加登录会话、目标租户/owner、一次性导入句柄与用途；浏览器传入任意服务器路径不具备这些条件。若上游仅支持单文件导入，目录遍历和导入放独立模块，不改变单文件入口签名。

导入前预览目标、文件数量/大小和是否会覆盖；默认创建新目录，禁止静默覆盖、复制其他用户运行空间/凭据库、穿越源或目标根的软链接。配额预占、暂存、原子发布及取消/失败补偿保证不出现半成品成功。云端/远程后端无法使用本机 loopback 时，使用获授权的目录上传传输，不将客户端路径解释为服务器路径。

选择受控复制而非任意目录挂载，避免运行时授权与宿主机原目录权限持续耦合。成员原有“已有项目进入工作区”的结果保留，任意主机路径访问不是本次等价能力。

### D7. 微信 QR 接入复用渠道服务，不保留全局注册状态

每次注册持有随机句柄，绑定 user、AuthSession、tenant、scope、owner、provider、目标实例/创建用途、有效期及状态版本。平台公共实例不伪造租户 Membership；租户公共实例要求当前租户管理员；个人实例要求有效 owner、允许类型与配额。跨账号、跨租户、跨实例查询返回不泄露存在性的拒绝。

提供方二维码/机器人授权结果只能证明接入控制权，不能证明消息发送者等于当前成员。私有路由必须另外完成兄弟 change 的本人身份挑战；公共群聊不可使用个人智能体、记忆或私有会话。

认证、授权、二维码完成和实例落库分成状态机：`pending -> confirmed -> committing -> committed`，另有取消、过期、失败状态。状态持久化于既有身份/凭据服务的扩展或同等受保护存储，敏感提供方结果加密且短时保存；多 worker 无法共享安全状态时拒绝该部署形态，不能各自保存同一全局 `_qr_state`。

微信新流程的客户端只取得一次性接入授权；服务端代发起者将提供方长期密钥加密写入对应实例，不写全局 `conf()`、`weixin_token` 或共用凭据文件。本 change 不将该响应收紧规则追溯扩展至飞书：飞书保留仅向已验证发起者一次性交付 `app_id`、`app_secret`、`scan_ticket` 及现有表单自动接入的兼容契约，秘密不得显示、持久化到浏览器存储或进入日志。飞书改造为服务端密钥托管须另行提出 change，不能在此次修改通用规范时隐式要求。

自动创建与手工提交复用版本、作用域、配额、审计及凭据事务。一次性授权仅允许一次成功创建；微信提交必须提供独立幂等键，并绑定发起用户、发起 AuthSession、tenant/scope/owner、provider、授权句柄、目标及规范化业务请求摘要。服务端统一解析默认值并计算摘要，凭据原文不进入回执。相同绑定、相同幂等键及相同摘要的重试只是回读该操作的既有非敏感结果，不是再次消费授权；每次回读仍须验证当前会话、成员资格及目标权限。新幂等键、变化的请求内容或不同主体不得重用已消费授权。

授权校验、实例/密文凭据写入、外部应用占用、审计记录、授权消费及幂等回执必须原子提交；外部连接使用提交后可恢复的工作项，同一实例不得重复启动连接。事务失败不消费授权，也不留下成功回执；相同键绑定的失败请求只能以原内容重试，修改内容须使用新键且原授权仍须有效。成功回执仅保存绑定摘要、实例 ID 及非敏感结果引用，保留 24 小时，不保存长期密钥或可再次领取的提供方结果。授权过期不延长新建权限，但已提交操作在回执期限内可通过当前授权回读；回执过期后返回明确不可重放结果，不能重新创建。已消费标记不得随回执一起提前清理，在原授权有效期内必须持续阻止新操作重放。

连接器按显式实例解析密钥和状态，校验外部应用唯一连接占用；返回已保存、连接中、已连接或失败，不能把落库成功等同于接入成功。扫码起始 GET 和后续状态修改须按其实际副作用校验来源及可信会话；旧响应字段可兼容，但不能保留旧全局副作用。

个人实例、绑定挑战及治理停用复用已交付服务，剩余提供方适配、个人执行和真实验收由本 change 承接。公共 QR 配置可在自身前置通过后先交付，但不能用公共 scope 的成功代替个人执行验收。对承诺支持的首个微信适配器分别记录提供方、版本、scope、连接形态和真实扫码/收发证据，完成本人私聊、他人/群聊拒绝、解绑及治理停用验收后，才更新相应类型的验收记录。

开放仍复用 `personal_runtime_enabled()`、`public_personal_ingress_ready()` 和部署总开关这一条事实链；配置可保存、个人实例可执行、公共实例可承载个人入口分别验收。类型验收记录不得自动打开部署开关，也不得扩展到未验收的其他提供方、版本或 scope。缺少外部条件时对应任务保持未完成，不能沿用兄弟 change 的“关闭即结项”分支宣布本 change 全部覆盖。

**适用审批的剩余责任**：本 change 在所承诺的实际 Bridge/工具分发接缝接入既有单动作审批服务，不重建审批引擎。需要审批的动作绑定当前 tenant/owner、渠道实例、目标资源、动作及规范化参数；待批、拒绝、撤回、过期、内容变化或重放时均不产生副作用。批准仅允许同一动作按现有审批契约执行，真正执行前再次校验身份、资源、配额及批准状态。明确不适用审批的动作记录策略依据，可独立验收；不得由客户端自报不适用，也不得以无审批动作的成功代替适用审批消费方的交付。未接通审批时只拒绝相应动作，不撤去已交付配置及其他独立能力。

### D8. Desktop 的上下文由一个请求接缝传播

拟新增请求上下文装饰器、主进程认证/传输 broker 和身份状态模块，统一保存当前权威自我投影、有效 tenant 选择和递增 context epoch；不保存角色或权限真值。认证复用数据库 AuthSession。明确选用系统浏览器授权码加 PKCE S256 流程，本地与远程后端使用同一协议，不再通过普通 `/auth/login` 的响应向渲染进程发放 Bearer。该协议验证用户授权及发起方对随机 verifier 的持有，不声称 PKCE 能证明客户端二进制来源；User-Agent、自报 desktop、公开 client_id 或缺少 Origin 均不能独立换取会话。

**Web 与兼容边界**：`/auth/login` 保留兼容字段，但 `token` 始终为空；认证只设置满足既有 identity-session 规范的 Cookie。现有无条件返回 `result.token` 的路径须修正，Web 与 Desktop 自报标识不能改变这一规则。原生协议使用独立扩展路由 `/auth/desktop/authorize` 与 `/auth/desktop/token`，不改上游公开客户端方法签名。未实现新协议的后端或旧 Desktop 显示升级/暂不支持，禁止退回旧登录取 token、`cow_auth_token` 或共享密码。

**发起与浏览器授权**：主进程生成高熵 verifier、state 和本次回调路径，先在字面量 `127.0.0.1` 或 `[::1]` 的临时端口监听，再打开选定后端的授权页。固定 public client_id 为 `cowagent-desktop`，仅接受注册的 loopback 回调形式，不接受任意域名、通配主机或自定义任意跳转。本地后端仅允许主进程启动并登记的实际 loopback 地址与端口；远程后端必须是用户明确配置的精确 HTTPS origin，地址变更须清除旧认证上下文并重新授权。授权页先通过普通 Web 登录/改密，再明确显示后端、账号和 Desktop 授权确认；即使已有 Cookie 也不能仅凭 GET 或已有登录自动授权。确认 POST 校验 CSRF、来源及当前 AuthSession，受限改密会话不得签发原生授权码。

**授权码交换**：授权码有效期 60 秒，服务端仅保存摘要，并绑定用户、发起 Web AuthSession、client_id、精确 redirect_uri、PKCE challenge 和已确认的授权事务；状态使用支持多 worker 的受保护存储。回调只携带短时 code 和 state，不携带 AuthSession。主进程只接受当前待完成事务的准确路径、state 及可信后端上下文，随后直接向同一 origin 的 token 端点提交 code、verifier、client_id 和 redirect_uri。服务端重新验证发起会话及账号状态，原子消费授权码并创建一个独立的原生 AuthSession；不能以 Cookie、自报原生标记或省略 verifier 代替交换。授权码重放或交换响应丢失需重新发起授权，不能再次发放会话。交换请求/响应禁止缓存，code、verifier、state、令牌及回调完整 URL 不进入日志或遥测；回调页设置无引用来源和禁缓存策略。

**进程与传输边界**：Bearer 仅驻留主进程内存，不交给 renderer、preload 返回值、localStorage、sessionStorage 或 URL；应用重启重新授权。renderer 仅取得脱敏本人信息、租户列表和登录状态。preload 暴露窄化的登录、退出、状态及业务请求/流 IPC，主进程校验 sender 为受信窗口的主 frame、页面为明确登记的打包入口或开发入口；不接受任意绝对 URL、认证头或后台 origin 覆盖。业务 action/相对路径经允许列表解析后，由主进程统一附加 Bearer 与 tenant，拒绝携带凭据的重定向，上传、流、预览和下载也不能绕回 renderer 持有令牌。现有通用 `httpRelay` 不得访问原生认证端点、loopback 回调或已认证后端，也不得复用 broker 凭据。数据库每请求重新授权仍是最终安全边界，IPC/前端投影不能替代它。

**退出与失败**：在线退出先撤销当前原生 AuthSession，再清除主进程状态；撤销失败应明确提示并停止业务请求，不得宣称服务端会话已注销。密码改变和账号停用沿用全会话撤销；后端重启、授权取消、state 不符、码过期与交换失败关闭临时监听并清理临时秘密。流及重连通过同一 broker 获取当前上下文，不自动携带旧会话访问新后端。

账号 gate 顺序为后端可达、登录、适用强制改密，然后按目标域分别处理。租户业务（包括个人记忆、渠道及智能体）进入有效租户选择和业务能力 gate；单有效租户可选定，多租户展示选择，零租户不初始化这些消费者。完成改密的零租户账号仍可访问 `/auth/me`、账号设置和退出；具有当前平台身份者仍可进入平台管理并使用获权平台接口，不要求 tenant 或伪造 Membership。平台页面目标不改变业务 tenant，平台身份也不能豁免租户业务资格。强制改密期间仅允许改密和退出，没有平台例外。租户列表只能来自本人权威信息，不能由 Agent ID、用户名或默认租户猜测。

JSON、FormData、流/重连、语音、预览/下载和本机导入经主进程 broker 共用受验证的 Bearer 与当前 tenant。不能加头的原生媒体请求使用既有资源派生租户且再鉴权的传输，或由 broker 带头取得数据后交付短生命周期 blob；禁止把 AuthSession 写入 URL。租户切换时取消旧请求/连接并清理旧缓存，以 epoch 拒绝迟到响应；不能把旧任务写请求换个 tenant 自动重发。

返回 401 进入登录流程，强制改密进入改密页，失效租户重新选择，403 显示具体动作拒绝，503 保留可恢复状态；不把这些响应转成空数据。Web 和 Desktop 共享页面/对象动作投影，个人页沿用兄弟 change 的五个 key，不给普通成员显示公共管理权限。

### D9. 开放矩阵按切片和动作登记

以单一服务端登记表达 `implemented/accepted/enabled`、支持的 scope、read/config/execute 与拒绝原因；复用现有可用性机制，必要时补最小登记模块，不在 route、`_consumer_availability` 和前端各维护一份开关。

恢复 10 个方法时同时更新策略、真实 handler、错误契约、角色菜单、对象动作及 Web/Desktop 入口。仅修改 `P("closed")` 不合格。授权失败与提供方未就绪/部署未启用分开报告。Desktop 原 `desktop_enterprise` 字段若保留兼容，取值必须从同一矩阵派生，不能永久写死 `deferred`。

开放顺序为 owner/存储边界、单项后端集成、Web 真实入口、Desktop 真实入口、外部扫码运行、依赖联合验收。任意代码仍受执行隔离和适用审批边界；不能因为定时恢复而重新开放未经验证的执行类型。

每次上游更新先在隔离的干净检出中记录源 master、目标 rdai 与 merge-base，盘点基线后新增/修改/删除的路由、handler 方法、公共签名、任务字段、传输与启动点。运行现有 `scripts/sync-from-master.sh` 时在该隔离检出执行，明确其只排练且会中止合并；它不能替代对最终解决冲突后的合并结果运行测试。

无文本冲突也必须验证语义。保留独立合并候选用于双侧测试：上游新功能回归、授权拒绝矩阵、10 个恢复入口的真实正向调用、Desktop 上下文和不复活检查。新路由或方法未分类、未支持的新任务字段影响授权、任何新传输绕过上下文均阻止合并验收。冲突基线按真实报告更新，不预先覆盖旧记录来制造通过。

提供三类可重复漂移用例：上游新增 HTTP 方法；上游扩展任务 action 且存在隐藏通知字段；上游新增 Desktop 传输方法。这些用例要证明新功能被保留且经过 rdai 授权，不能只测试文本中存在接缝字符串。

## Risks / Trade-offs

- 个人控制台依赖尚未完成：按切片隔离和联测，独立工作继续；交付状态同时列出剩余依赖，不以本 change 文档齐全代替实现。
- 旧无 owner 任务存在运行行为变化：保留可恢复数据，隔离停用并要求可信归属，禁止自动归给管理员。
- TaskStore、文件、审计与渠道连接跨事务：使用版本、幂等操作记录和补偿，未提交不启动副作用，未完成不返回成功。
- 微信提供方多实例或真实测试条件不足：保留类型/作用域明确的未就绪状态；不伪造真实扫码验收。
- 目录导入与原地挂载有体验差异：预览复制结果及配额，保证个人根内的后续选择和运行，明确原目录不会同步更新。
- 新 master 无冲突地改变语义：对最终候选运行双侧功能与隔离回归，不能仅依赖冲突文件清单。

## Migration Plan

1. 记录代码、schema、路由及依赖切片基线；备份身份库、任务、记忆和项目元数据，建立归属与租户双维度恢复清单。
2. 先落地统一 owner、作用域、版本和存储边界；与兄弟 change 协调迁移号。幂等迁移不重建会话/任务 ID、不改变历史公共实例归属、不重复发菜单 grant。
3. 可证明 owner 的历史任务保留有效状态并逐项复验；未知归属任务隔离。历史个人项目路径只在真实归属验证后保留，非法路径登记为待处理而非共享。
4. 依次启用定时、记忆读取、个人项目、公共 QR、Desktop；个人写入和个人 QR 仅在对应依赖切片通过后启用。每一项同时更新权威开放状态。
5. 实际双租户/多用户、真实客户端及支持的微信链路通过后，完成与个人控制台的联合验收。10 个旧入口不再存在仅因 database 模式而关闭的正常使用路径。
6. 回退先关闭新增动作、停止相关连接/触发并保留 owner、版本与操作恢复记录；不退回忽略新归属字段的旧构建。必要的版本恢复使用一致备份和维护窗口，不提供运行时 legacy 回退。
7. 将双侧合并回归和冲突登记流程纳入后续 master 到 rdai 的每次更新。提案阶段不修改真实冲突基线，不声称已完成合并演练。
