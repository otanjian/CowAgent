## Why

Web 控制台「系统设置 → 品牌设置」已出现在菜单中，但尚无对应页面与保存接口，Logo、品牌名称和品牌位文字仍由代码固定。需要把这些内容变为可预览、可保存、可恢复的实例级设置，满足本次用户明确提出的 Logo 替换与 Logo 描述需求。

## What Changes

- 将现有 `data-view="branding"` 菜单接入真实设置页，保留截图中的菜单位置，面包屑为「系统设置 / 品牌设置」。
- 提供 Logo 上传替换、恢复默认 Logo、品牌名称和 Logo 描述编辑；Logo 描述定义为品牌标识旁或下方展示的短说明，同时用于图片替代文本，不是智能体描述或提示词。
- 提供侧边栏、登录页、对话欢迎页的实时草稿预览，以及浅色/深色效果切换；点击「保存设置」后整组配置生效，取消编辑不影响已发布品牌。
- 统一 Web 侧边栏、登录品牌区、欢迎页与默认品牌头像的 Logo 来源；品牌名称同步浏览器标题，Logo 自动生成 Web favicon。自定义智能体头像保持自身配置优先。
- 支持配置和图片持久化、版本冲突提示、图片校验、加载失败回退、恢复默认确认和未保存离开提醒；保留现有登录、聊天、配置与桌面客户端接口兼容性。
- 本期仅配置当前部署实例的 Web 品牌；租户覆盖、主题色编辑、桌面安装包/托盘图标、文档站品牌、外链图片与自定义 CSS 不在本期范围。

## Capabilities

### New Capabilities

- `branding-settings`: 品牌设置入口、字段和编辑交互、管理权限、发布与持久化、Web 展示同步、故障恢复及兼容性。

### Modified Capabilities

- 无。当前不存在 `openspec/specs/` 基线规范；已有导航规范位于尚未归档的 `prd-02-platform-navigation` change，本次不将其误当正式基线，不修改其文件。

## Impact

- **需求依据**：用户 2026-09-08 请求及所附红框菜单截图；现有 `prd-02-platform-navigation` change。仓库配置声明的参考基线为 `doc/优化规划/PRD/PRD-00-总目录.md` 与 PRD-01～12 v1.2，但该目录当前缺失，无法核对对应业务 PRD 的编号和完整要求；本 change 按当前用户请求独立设计，恢复原文后再核对归属与冲突，不声称覆盖整份 PRD。
- **现有代码接入点**：`channel/web/chat.html`、`channel/web/static/js/console.js`、`channel/web/static/css/console.css`、`channel/web/web_channel.py`、`config.py`；新增独立品牌服务和测试，沿用现有 Python/Web 技术栈及 Pillow。
- **拟新增接口**：公开最小品牌读取、受保护的品牌管理读取/保存/重置、只读品牌图片路由；原 `/config` 仅提供兼容投影，不能成为第二写入入口。
- **唯一数据归属**：运行数据目录下独立的 `branding/` 品牌存储拥有发布配置、版本和派生图片；`config.json` 不复制品牌字段，也无需品牌启用开关；浏览器缓存与现有静态资源均不是品牌配置写入源。
- **跨 change 协调**：依赖 `prd-02-platform-navigation` 的菜单骨架，但不等待其账号改造全部结束；其「所有系统设置均占位」「品牌固定为容大AI」要求由本能力接续，归档时需同步消除冲突。品牌页面默认可用，未保存自定义品牌时使用内置品牌。
- **分阶段门槛**：先完成现有单实例鉴权与原子存储闭环；企业发布前验证真实的 PRD-10A 审计接入切片，多用户/多租户部署还须验证平台管理员授权与隔离切片。当前仓库未具备这些企业能力，不能凭页面可用或模拟接口认定企业验收完成。08S、09G、10B 不在本次无凭据、无 Agent 外部动作、无模型调用的配置范围内，恢复 PRD 后复核。
- **交付性质**：本次只生成设计与 change 产物，所有实现任务保持未完成；不覆盖当前工作区已有产品代码改动。

用户后续调整：取消品牌功能开关及未开启提示，单实例登录后即可直接编辑、保存。
