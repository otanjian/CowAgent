## Goals / Non-Goals

**Goals:**

- 用一个实例品牌记录统一 Web 展示，让一次保存同时发布 Logo 与描述，刷新或重启后保持一致。
- 将草稿预览与全局品牌渲染分开；把字段校验、并发冲突、恢复和权限结果设计成用户可理解的状态。
- 复用现有 Web/Python 技术栈，明确兼容模式与企业模式各自的可用门槛。

**Non-Goals:**

- 本期无租户选择器、租户品牌继承或按用户配置；品牌不属于 Agent、会话或工作区。
- 不增加主题色、字体、CSS、登录背景、Logo 裁剪器、深浅色两套上传、AI 生成 Logo 或外链抓取。
- 桌面 React 品牌位、托盘/安装包、文档站和消息 Channel 的品牌不跟随本页；不改变模型、Agent 身份与业务对话内容。

## Decisions

### 1. 页面结构与字段定义

入口沿用截图「系统设置 → 品牌设置」，使用已有单页视图机制，不新增顶层菜单或独立前端框架。直接注册 `VIEW_META.branding` 与 `view-branding`，登录后即可编辑，无需额外启用。

桌面宽屏采用左侧设置、右侧预览两列；窄屏顺序堆叠。预览使用页面内部示意卡片，不创建独立应用或嵌入真实登录表单。以下为结构草图：

```text
系统设置 / 品牌设置
品牌设置                        当前实例 · 已保存 / 有未保存更改
设置控制台的品牌标识与说明

┌ 品牌信息 ──────────────────┐  ┌ 实时预览 ──────────────────┐
│ Logo  [当前缩略图]          │  │ [深色] [浅色]               │
│ [上传 Logo] [使用默认 Logo] │  │ 侧边栏 / 登录页 / 对话欢迎页 │
│ PNG / JPG / WebP，最大 2MB  │  │ [Logo] 品牌名称             │
│ 品牌名称 * [容大AI       ]  │  │        Logo 描述            │
│ Logo 描述  [控制台       ]  │  │ 预览效果，保存后生效         │
│ 可留空，最多 100 字         │  │                             │
└────────────────────────────┘  └─────────────────────────────┘
[恢复全部默认]                         [取消更改] [保存设置]
```

| 字段/操作 | 规则 | 默认及展示 |
| --- | --- | --- |
| Logo | 单个本地文件；可替换或选择内置默认；不接受 URL、文件路径或 HTML | 内置 `rongda-ai-mark.svg`；预览等比 contain，保留透明度，不拉伸或裁切 |
| 品牌名称 `brand_name` | 必填、首尾去空白、单行纯文本，1～32 个 Unicode 码点；拒绝换行及控制字符 | `容大AI`；用于品牌标题及浏览器标题 |
| Logo 描述 `logo_description` | 可选、首尾去空白、单行纯文本，0～100 个 Unicode 码点；拒绝换行及控制字符，允许普通标点 | `控制台`；空值意味着隐藏说明，不重新填默认；不是 Agent 描述 |
| 上传 Logo | 文件选择或拖放；本地预校验后替换草稿缩略图 | 选图不立即上传发布，保存时统一提交 |
| 使用默认 Logo | 只把草稿中的 Logo 切到默认 | 名称和描述保持当前草稿，仍需保存 |
| 取消更改 | 还原最近一次成功读取/保存的快照，释放本地图片预览 | 不发送写入请求 |
| 恢复全部默认 | 对话框列出将恢复的三项，确认后立即发布默认组合 | 取消无副作用；请求携带当前版本，同样处理冲突 |

描述在侧栏品牌名下占一行，溢出省略并可通过悬停/键盘可达提示读取全文；登录品牌区与欢迎页最多显示两行并提供全文提示。非装饰性 Logo 的替代文本使用非空描述，空描述回退品牌名称；紧邻同义文本的装饰性图保持空 alt，避免重复朗读。登录密码输入指引、欢迎页业务说明另行保留。

表单标签、错误、对话框支持简体中文、繁体中文、英文；用户输入的名称与描述不随语言切换被翻译、清空或替换。所有自定义文本使用文本节点或上下文安全转义，包括现有 `productTitleHTML()` 分支；品牌描述绝不送入 Markdown 渲染器。

### 2. 编辑状态与交互结果

状态为加载中、只读、已保存、草稿有更改、提交中、校验错误、加载/保存失败、版本冲突。首次读取成功前禁止编辑；加载失败显示「重试」，不允许把默认回退值当成已读取的配置写回。

- 草稿修改只更新右侧预览。无变化、校验不通过或提交中禁用保存，提交中禁止重复提交及恢复默认。
- 保存成功以后端返回快照为准，更新全局品牌、草稿基线和版本；显示「品牌设置已保存」。
- 普通失败保留草稿和当前已发布展示。409 显示「品牌设置已被其他人修改」，保留本地草稿并提供重新加载服务端版本的操作；丢弃草稿前确认，不自动强制覆盖。
- 401 引导重新登录；草稿仅可暂存在当前页面内存，不能写入长期浏览器存储；重新认证后先取最新版本，再允许用户决定是否重试。
- 离开设置页有草稿时提示「留在此页 / 放弃更改并离开」，浏览器关闭或刷新使用原生离开提示。与现有文档未保存守卫串联，不能替换掉其保护。
- 设置页面加载时、进入其他功能视图时以及页面重新获得可见性时重新验证公开品牌快照。防止乱序读取用旧版本覆盖刚保存的版本；设置表单有草稿时仅提示服务器有新版本，不覆盖草稿。

选择「统一保存」而不是上传后立即生效，是为了防止名称/描述保存失败却已经更换全局 Logo。未单列临时上传 API，减少孤立图片与草稿服务端状态。

### 3. 展示范围和优先级

| 展示位置 | 发布后行为 |
| --- | --- |
| Web 侧边栏顶部 | 更新 Logo、名称和描述；描述为空隐藏；保留菜单尺寸和点击行为 |
| 登录品牌区 | 未登录可读取已发布品牌；独立的品牌描述不能覆盖登录操作提示 |
| 对话欢迎区 | 初次加载和新建会话重建 DOM 均使用同一品牌快照 |
| 默认品牌头像 | 所有原来使用产品品牌图的无自定义头像位置更新；已配置的 Agent 头像优先；其他 Agent 名称/首字母头像不变 |
| 浏览器 | 标题为「品牌名称 控制台」（控制台按界面语言翻译）；favicon 使用派生 PNG，统一更新现有 icon 链接，避免 SVG 旧链接抢占 |
| 其他已打开标签页 | 刷新、重新可见或切换功能视图重新读取后生效，不承诺后台推送实时更新 |

新增统一的品牌加载/应用函数，所有重绘路径只消费该快照。`/config.title` 保留旧字段并从有效品牌名称投影，避免迟到的配置请求恢复硬编码默认。Web 以公开品牌读取为权威来源；现有桌面端仍可读取 `/config`，不要求其采用新增字段，不改变认证协议。

没有自定义配置时继续使用当前随版本交付的默认标识，不能从截图中旧品牌字样反向覆盖工作区已经替换的容大AI 资源。已保存的自定义品牌直接生效，旧 `branding_enabled` 配置不再控制读取或编辑。

### 4. 持久化与图片处理

建议新增 `channel/web/branding.py`，把加载、验证、派生图片、版本化保存和默认值解析从大体量路由文件中分离。沿用已依赖的 Pillow，不引入新前端或对象存储服务。

唯一持久化布局：

```text
<get_data_root()>/branding/
  branding.json                # 当前已发布快照，schema_version + revision
  assets/<sha256>.png           # 规范化品牌图或 favicon，内容不可变
  snapshots/<revision>.json     # 保留最近可恢复快照
  .write.lock                  # 跨进程写锁
  .revision.json               # 已分配版本上界，不作为已发布快照或公开恢复来源
  corrupt/                     # 明确恢复前保留的损坏主配置原件
  tmp/                         # 请求内临时文件，失败清理
```

品牌记录包含 `schema_version=1`、单调递增 `revision`、`brand_name`、`logo_description`、`logo_asset_id`（默认时为 null）、`favicon_asset_id`、更新时间和可用的操作者引用。默认记录 revision 为 0。服务端生成所有路径及 URL；客户端仅传业务字段与图片字节。不设置品牌功能开关；旧 `branding_enabled` 配置被忽略。不能经 `/config` 白名单写品牌字段或开启管理能力。

上传限制为本次明确选定的参数：PNG、JPEG、静态 WebP；文件最多 2 MiB（2,097,152 字节）；宽高分别在 32～4096 像素内且总像素不超过 16,000,000；拒绝 SVG、GIF、动画 PNG/WebP、伪造 MIME/后缀、空文件和无法完整解码的数据。扩展名、声明 MIME、识别格式一致性与真实解码共同验证，不能直接复用仅按后缀判断的通用上传实现。内置可信 SVG 不受用户上传规则影响。

推荐上传 256×256 或更高分辨率的方形透明图，但长宽比不是拒绝条件。先限制读取字节数和像素，再完整解码；应用方向信息、去除 EXIF/附加元数据，规范化为 PNG，最大展示长边缩小到 1024；favicon 为保留完整图形的 32×32 透明画布 PNG。默认 Logo 使用随包预生成、来源相同的默认 favicon，不要求 Pillow 在运行时解码 SVG。生成资产以内容摘要命名，采用正确 MIME 和 `X-Content-Type-Options: nosniff`。

保存流程：先鉴权和字段校验、受限解码及派生 → 获得跨进程锁并重新读取版本 → 核对 expected revision → 先完整落盘所有资产及恢复快照 → 同目录临时 JSON 写入、flush/fsync 后 `os.replace` 发布新快照 → 更新内存快照并返回成功。替换提交点之前失败都保留旧发布状态，禁止先修改 `conf()` 或 UI 全局状态。单独原子替换 JSON 不能防止丢失更新，因此锁和版本比较必须覆盖同一提交区间。

恢复快照只归档提交前已经生效的旧记录；尚未提交的候选记录不能进入恢复或公开资产引用集合。提交已完成但响应丢失时，前端提示「保存结果未确认」，先重新读取服务器版本核对结果，不直接宣称回滚或无条件重试覆盖。公开快照的 `enabled` 与 `revision` 一并参与缓存标识，前端以请求序号和保存操作代次处理乱序，不能只取数值最大的 revision 而忽略关闭功能后的默认回退。

保留最近 5 份有效快照以支持运维恢复；清理只移除当前及保留快照均未引用且已超过 7 天的资产，且与发布共用锁。请求临时文件立即清理。读取遇损坏时使用可验证的最近快照或内置默认，同时在管理页标明异常并要求重新读取/恢复；不能静默覆盖损坏原文件。图片丢失时前端回退内置图且最多尝试一次，避免错误循环。

验收整改补充：管理读取返回 `storage_error`、`can_manage`、`can_reset`，损坏时普通编辑禁用，具有实例写权限的操作者仍可明确恢复默认。恢复前复制损坏原件并同步落盘，失败即停止发布。写锁内先持久化 `.revision.json` 已分配版本上界，再替换主记录；失败可产生版本间隔，但不把候选记录当作公开快照。旧存储尚无版本记录且主配置损坏时，恢复版本必须高于保留快照及其可能对应的损坏后继版本。备份仍携带完整已发布快照及引用资产，恢复时使用目标实例的版本上界。

选择独立文件存储是为了避开 `/config` 多模块写入竞争，以及避免升级覆盖静态资源。以后迁入企业配置存储必须整体迁移归属，不能长期双写。

### 5. 接口契约

以下路径为本 change 新增约定；不改变现有通用上传及 Agent 头像 API。

| 方法与路径 | 输入/输出与权限 |
| --- | --- |
| `GET /api/branding/public` | 无需登录；只返回 `enabled`、`revision`、`brand_name`、`logo_description`、`logo_url`、`favicon_url`；未保存自定义配置时返回内置默认；禁止路径、用户、权限、其他配置泄露 |
| `GET /api/branding` | 管理读取；返回已发布快照、内置 defaults、`can_manage`、限制及只读原因；正常部署需已认证，免密码兼容部署只返回只读视图 |
| `POST /api/branding` | multipart：`expected_revision`、`brand_name`、`logo_description`、`logo_action=keep\|replace\|default`；replace 必须附唯一 `logo` 文件，其余操作附文件则报错；整组保存 |
| `POST /api/branding/reset` | JSON：`expected_revision`；用户已确认后一次发布三项默认配置，revision 继续递增 |
| `GET /api/branding/assets/<asset-id>.png` | 仅合法摘要且被当前/保留已发布快照引用的资产；不接受路径片段、不列目录、不暴露临时图 |

成功使用既有 `status: success` 风格并返回最终快照；失败包含稳定 `code`、可本地化消息及可选 `field`。公开配置采用 ETag/重验证，资产采用内容摘要与缓存；公开配置读取可禁用缓存以简化初期实现，但不能长期缓存错误回退。当前标签立即应用保存响应，无需重启或强制整页刷新。

| HTTP 状态 | 典型原因 | 用户结果 |
| --- | --- | --- |
| 400 | 字段缺失、未知 action、长度/字符/图片损坏或像素违规 | 字段级提示，保留草稿 |
| 401 | 未登录或登录已过期 | 重新登录 |
| 403 | 无管理授权、跨站写请求、免密码部署尝试写入 | 禁止发布 |
| 404 | 未知资产 | 图片显示默认回退 |
| 409 | expected revision 已过期 | 提示冲突，不覆盖 |
| 413 / 415 | 超过 2 MiB / 不支持格式或 MIME 不一致 | 明确上传错误 |
| 500 / 503 | 存储故障 / 企业依赖不可用 | 保留旧发布状态，提供重试 |

### 6. 权限与阶段门槛

当前兼容模式使用已开启共享密码的实例认证操作者，不能称为已有平台管理员/RBAC。写接口在 `_require_auth()` 之外必须验证密码已开启；Cookie 请求验证同源 Origin/Referer 并使用绑定当前认证状态的 CSRF 防护，Authorization Bearer 走受验证令牌路径；新品牌写接口不接受 query token。页面灰化仅作提示，服务端必须逐次检查。

验收整改补充：品牌管理独立选择 Cookie 或 Authorization 凭据，不复用通用接口的 query-token 放行。管理 GET 向已认证且允许编辑或恢复的客户端返回 `csrf_token`；Cookie 保存和 reset 通过 `X-Branding-CSRF` 回传，并严格匹配同源。该值由服务端密钥及当前登录 token 派生，只驻留页面内存。当前仅 `identity_mode=legacy` 有写入适配；数据库及未知模式拒绝品牌写入，数据库管理 GET 通过真实数据库会话认证后返回只读原因。

免密码部署可看到只读品牌设置及「请先设置访问密码」原因，不能因 `_check_auth()` 的既有免登录放行而开放上传和重置。品牌公开读取是独立最小接口，不能放开 `/config` 来支持登录页。

阶段划分是本 change 的实施阶段，不伪称缺失 PRD 中的阶段编号：

| 阶段 | 前置与退出条件 |
| --- | --- |
| A：设计与菜单衔接 | 以用户请求建规格；确认导航 change 的实际状态、既有草稿差异及数据归属；登录后可直接使用品牌编辑 |
| B：单实例实现与兼容验收 | 完成真实认证检查、图片验证、原子存储、表单和全局展示；可在明确的单实例兼容部署验证；免密码保持只读 |
| C：恢复与回归 | 备份恢复、异常/并发、三语、深浅主题、窄屏和既有聊天/桌面接口回归通过；重启及旧开关残留不影响已保存配置 |
| D：企业发布接入 | PRD-10A 可靠审计切片通过；存在企业用户体系时还必须通过每请求 `branding.manage` 平台权限与隔离验收；缺少真实依赖时不得启用企业写入 |

企业模式的授权由统一认证服务提供可信主体，租户管理员不自动拥有实例品牌修改权；本服务拒绝不认识的身份上下文，不能回退到共享密码或根据业务 session 伪造权限。部署模式来自服务端可信配置，不由请求参数选择；发现企业认证上下文但缺少授权适配器时拒绝写入。

本能力只定义审计事件消费契约：`branding.updated` / `branding.reset`，包含操作主体、实例、时间、旧/新版本、变更字段名、资产摘要和结果，不包含图片字节、凭据或不必要的完整描述。企业存储适配器须通过配置提交与可靠审计受理的一致性验收；无法提供原子提交或等价持久化保证时关闭企业写入，不能以普通 `run.log` 或模拟成功替代。统一审计平台的实现不由本 change 重复建设。

### 7. 备份、迁移与导航规范协同

在备份清单增加可选品牌数据段，锁内取一致的已发布快照及被引用资产；不打包锁、临时文件或与品牌无关的工作区路径。恢复先校验版本、摘要和路径，再发布恢复快照。旧备份没有品牌段时，在新实例使用默认；在已有实例保留品牌配置并明确提示，避免无意删除。备份格式升级须兼容现有 v1/v2 读取流程，不能把品牌目录存在视为已经有备份能力。

恢复内容时分配目标实例的新 revision，保留备份中的版本作为来源信息，避免旧浏览器草稿恰好与恢复后的旧版本号相等而覆盖恢复结果；损坏、摘要不符或不支持的新 schema 不允许部分恢复。

如果导航 change 先归档，实施/归档本 change 时为正式 `platform-navigation` 基线补完整 MODIFIED delta：该菜单从占位集合移除；固定容大AI 规则限定为未保存自定义配置，桌面默认品牌规则保持。若导航 change 尚未归档，先协调归档次序，不覆盖其在途产物。当前仅新增 `branding-settings` 规范，避免为不存在的基线伪造修改。

## Risks / Trade-offs

- [缺失 PRD v1.2 原文] → 显式保留来源限制；恢复后按实际业务 PRD 归属整合，不凭记忆制造 PRD 编号或认定企业门槛已通过。
- [现有工作区有较多未提交产品改动] → 实现前复查差异并按功能局部接入；本次只增加 change 文件。
- [长条或低对比度图片在小图标处可读性有限] → 上传建议与深浅预览，等比缩放；不隐式裁剪，不自动改用户颜色。
- [默认头像与自定义 Agent 身份混淆] → 仅替换本来回退到产品 Logo 的位置，保留自定义头像和 Agent 名称。
- [文件提交与企业审计跨系统一致性] → 单实例存储不冒充企业审计能力；企业阶段以真实适配器的故障注入证据作为启用门槛。
- [已被浏览器缓存的公开图片无法撤回] → 清理只约束后续服务端读取，品牌图被视为公开展示资产，不承诺撤销客户端已下载副本。

## Migration Plan

1. 部署后无需品牌开关，旧 `branding_enabled` 值被忽略；未创建品牌目录时读取内置默认，不在启动时覆盖既有静态文件。
2. 单实例操作者登录后直接编辑和保存，首次保存才建立品牌快照；需要的名称和描述从默认起填，不扫描 Agent 工作区推断品牌。
3. 按阶段 C 验证备份、恢复与重启；旧配置即使保留 `branding_enabled=false`，也可编辑并读取已发布品牌及图片。
4. 配置/资产异常时以最近有效快照或内置图维持页面可访问；管理员执行受保护的恢复全部默认，或维护窗口恢复已验证备份。修复损坏数据时先保留故障文件，不静默删除。
5. 回滚旧应用版本前先备份品牌目录；旧代码不消费新增品牌目录，聊天、Agent 配置与会话不需要迁移。

## Open Questions

- 恢复 PRD 文档后需补充其真实路径、所属 PRD 编号与企业验收证据链接；若原文与当前范围冲突，应修订 change 后再进入对应企业阶段。
- 企业审计/授权适配器的实际模块名、事件封装及证据存放位置待统一平台切片出现后填入；本设计已经确定能力边界与失败时禁用写入的约束，不把接口占位当作依赖完成。
