## Why

当前容大 AI Web 控制台将日常使用、智能体维护和平台管理混排为 22 个入口，其中 5 个点击无反馈；配置职责、作用范围和导航状态也不一致。依据用户确认的《菜单结构评审与优化方案》，需要将菜单整理为工作台与管理控制台，并修复可用性和导航连续性，让用户能够准确找到功能、理解配置影响范围。

## What Changes

- 将导航分为“工作台”和“管理控制台”。工作台保留对话、历史对话、智能体、我的待办、定时任务、知识库六个候选页面；管理区按智能体开发、模型与接入、组织与权限、平台运维分组，实际入口随运行模式、后端能力和授权收敛。
- 隐藏场景应用、平台设置、审计、备份升级、开放 API 五个旧占位入口。系统设置承接真实部署配置并完成验收后，以新功能页面开放；不保留点击无反馈的伪链接。
- 统一菜单名称、页标题、面包屑和页签；集中登记导航元数据，给页面及需要恢复的页签提供 hash 地址，支持刷新、前后退、深链接及旧内部视图 ID 兼容。
- 将配置页拆为模型服务、智能体默认/单体设置、系统设置和个人偏好，沿用现有存储和接口授权，标明平台、当前租户、智能体和个人范围。
- 消费身份域的有效权限与开放能力摘要生成导航，必要时向既有摘要追加最小页面状态投影，统一侧栏、首页快捷入口、直接地址和页内管理跳转的可达性判断；读取失败不默认放行，也不把读取权限推断为执行权限。
- 统一折叠组的焦点行为、箭头、缩进及当前项可见性，保留桌面图标模式、移动抽屉、三语和外观偏好。
- 顶栏保留页面上下文、租户选择和本页动作；账号菜单集中个人资料、账号安全、个人偏好、帮助与关于及退出。共用租户选择器，区分产品介绍与更新日志；首页“打开功能”与“让 AI 处理”使用不同动作语义。
- 保留新建与返回对话、智能体使用与管理、待办与定时任务的不同职责；保持历史分组、业务归属、草稿、未保存编辑保护和后台执行。待办将“未完成”范围与互斥状态筛选分开。
- 按本轮补充要求，每个成员必须明确分配租户。database 模式中每个启用账号（含平台管理员）至少具有一个启用租户的有效 Membership；新建时原子分配，禁止变更导致启用账号失去最后一个有效租户，存量缺失先补分配。无租户账号只能进入受限恢复状态，不能直接进入工作台或正常管理页；不自动分配默认租户或提权。
- **BREAKING（导航呈现及成员租户约束）**：替代旧四分组、资源管理大组、无反馈占位和顶栏重复入口约定，并收紧此前允许启用账号没有有效租户的状态。旧 `/chat` 及内部调用继续兼容，资源权限、租户之间的数据归属和既有消费者关闭边界保持；租户约束属于明确新增的服务端身份规则。

本 change 对应方案第一、二批。第三批的独立工作文件页、场景运行、任务与调度执行关联、审计查询页面、备份恢复/升级、开放 API 管理、菜单搜索/收藏属于后续 change；本次不预建这些功能的表、接口或可用菜单。工作文件继续复用已获准使用的对话文件面板。

## Capabilities

### New Capabilities

- `console-information-architecture`: 双区域结构、完整菜单迁移、命名、占位处理与可访问的响应式侧栏。
- `console-route-lifecycle`: 单一导航登记、稳定 hash 地址、导航事务、未保存保护及会话/租户上下文连续性。
- `console-navigation-availability`: 消费有效身份与功能可用性、按作用域过滤全部入口、失效刷新及分阶段启用门槛。
- `console-settings-organization`: 配置职责拆分、默认/覆盖关系和个人偏好与运行配置的存储范围。
- `console-entry-consistency`: 顶栏、账号、首页快捷入口、待办筛选和相关页内导航的一致行为。
- `member-tenant-assignment`: 成员必须分配租户、启用账号有效归属连续性、无租户受限恢复及存量迁移。

### Modified Capabilities

无。`openspec/specs/` 当前没有正式规范；上述为新增规范，描述已有产品的调整，不将未归档 change 当作正式基线。与旧导航、外观、账号及身份 change 的逐条衔接见 compatibility.md；实施基线和归档前均须核对，不能按时间顺序覆盖整份旧规范。

## Impact

- 需求来源：`docs/design/menu-structure-audit-and-plan.md` 及本轮用户确认。项目配置将平台导航归入 PRD-02 v1.2，且既有 `prd-02-platform-navigation` 属于该责任域；PRD 原文 `doc/优化规划/PRD/` 当前未找到，实施基线任务记录缺口，恢复后核对，不虚构原文条款。本 change 是用户要求创建的后续调整，不是重做 PRD-02 登录或品牌改造。
- 接入点：`channel/web/chat.html`、`static/js/console.js`、`identity-admin.js`、`appearance.js`、`todos.js`、`workspace.js` 以及 `static/css/{console,appearance}.css`。可抽取小型导航模块，不更换原生 JS/Python web.py 技术栈，不改 Desktop/Channel 布局。
- 最小后端配套：配置与页面响应增加仅控制呈现的开关；在已有 `/auth/context` 合同中追加缺失的页面可用状态时，复用身份域资格、权限和消费者状态计算，保持原响应字段兼容，不新增认证端点或业务写权限。
- 成员归属配套：本 change 在既有身份服务、账号/成员/租户写入口及初始化/迁移工具中落实新租户连续性规则，复用原管理资格、事务、版本与审计；不新建成员管理系统。该规则独立于导航开关，classic 回退不能放宽约束。发布前完成存量预检和显式分配，未补齐时阻止受影响账号进入正常控制台。
- 身份依赖：复用 `complete-enterprise-identity-access-control` 的 `/auth/context` 有效权限、管理资格与开放能力摘要，以及 `extend-sidebar-account-actions` 的 `/auth/me`、本人改密和整页刷新租户切换。接口存在不等于真实切片已验收；本 change 消费合同，不另建身份副本或开放关闭中的消费者。
- 相邻依赖：保留 `move-session-history-to-workbench` 的历史行为、`split-agent-configuration-and-workbench` 的使用/维护与新会话归属、`add-workbench-todos` 的本人数据边界、`add-branding-settings` 的品牌归属，以及外观和账号 change 的存储/认证/焦点行为。
- 数据唯一归属：`identity.db` 持有账号、成员、权限和认证会话；配置服务与 Registry 持有运行和智能体配置；原业务库/目录持有会话、知识、记忆、待办和文件；外观模块持有既有个人偏好。导航只保存本地展示偏好和已验证地址，不持久化授权结果或第二份业务数据。
- 发布：以配置中的呈现开关分批启用；对 legacy 和 database 分别验收，关闭新导航不得恢复无反馈入口、隐藏焦点或绕过后端关闭边界。导航本身无数据迁移；新增成员租户约束需单独预检、显式补分配与验收，配置表单先核对存储来源再迁移位置。
