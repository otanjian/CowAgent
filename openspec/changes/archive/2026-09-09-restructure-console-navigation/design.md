动机及范围见 proposal.md。需求以用户确认的 `docs/design/menu-structure-audit-and-plan.md` 为准，审查时侧栏为 22 项，其中 17 项有页面、5 项点击无反馈；数字仅是检查时产品快照，不是所有模块功能验收结论。

## Goals / Non-Goals

**Goals:**

- 以一个导航登记和可用性适配层驱动两个区域、页面地址、标题与各种入口。
- 将原配置页面按现有数据归属拆分，明确平台默认、单体覆盖、个人偏好。
- 修复无反馈入口与隐藏键盘焦点，并维护会话、未保存编辑及身份切换连续性。
- 在现有技术栈内提供可分阶段发布和回退的变化，按实际服务模式验收。

**Non-Goals:**

- 不重写为 React/Vue，不改变 Desktop 或 Channel 的导航、认证与传输。
- 不创建通用授权服务、资源 grants、角色种类或新的业务执行权限，不通过本次菜单开关开放数据库关闭消费者。
- 不实现独立工作文件页、场景应用、调度联动执行记录、审计业务页面、备份升级、开放 API 管理、菜单搜索或收藏。
- 不迁移会话、文件等业务归属，不复制凭据或重做品牌、身份和历史数据存储；用户补充要求涉及的缺失 Membership 通过既有身份服务显式补分配，不改变当前租户切换的整页刷新规则。

## Decisions

### 1. 在同一控制台中切换工作台与管理区域

区域切换在侧栏顶部以有文字的控件提供；普通用户没有管理区可访问页面时不显示切换入口。管理区内部使用四个分组，默认仅展开当前组，允许主动展开其他组；不会因选择一个组而丢失另一组的业务状态。账号固定底部，导航独立滚动，保留约 240px 宽度和图标模式。

备选是继续在原侧栏堆叠分组或另建独立管理应用。前者不能消除日常与管理混排，后者会增加会话、认证和状态协调。本方案复用同一页面壳和服务，只改变导航区域。

不把“智能体”和“场景应用”提前合并为应用中心；保留“我的待办”和“定时任务”，前者默认是事项管理，后者是否可执行由消费者状态决定。

### 2. 单一导航登记与 22 项迁移表

建议抽取 `static/js/navigation.js`。登记包含 `id`、`area`、`group`、`labelKey`、`path`、合法 `tabs`、`viewId`、兼容别名和生命周期适配器；页面或页签各自登记 `scope`、`availabilityKey` 与动作能力键，不能用父页的单一权限覆盖不同范围的子页。声明业务动作的按钮不伪装成页面路由。

由登记生成菜单、标题、面包屑、`href`、当前项及可用性提示；原 `VIEW_META` 如需临时保留，只能由登记派生。原 `navigateTo(viewId)` 作为适配层进入统一路由，不保留独立加载/清理分支。

配置拆分后的支持页签固定白名单：模型 `providers/capabilities`，智能体 `list/defaults`，知识 `docs/graph`，记忆 `files/evolution`，系统 `general/security`，其他已有页签按实际页面登记。详情对象 ID 仅在原功能允许恢复时登记和验证，不把绝对路径拼到 hash。

### 3. 原生 hash 路由与可取消导航事务

选择 hash 路由兼容当前 `/chat` 服务路径，无需新增服务器 rewrite 或引入框架。页面链接使用真实 `href`，只拦截未加修饰键的普通站内点击，保留复制链接和新标签页行为。

统一处理顺序：

1. 解析目标，只接受登记页面、页签和必要安全参数；先确认身份及当前能力。
2. 获得最新导航序号和 auth/tenant 上下文，合并正在等待的离页请求；一次用户决定只提交一个有效目标。
3. 运行品牌、身份管理、智能体、配置、待办编辑、知识新增/导入、文档和文件的离页保护；同页切换页签或编辑对象也须覆盖。取消则不做任何页面清理或目标加载。
4. 确认离开后才运行原页面清理，例如停止日志连接、取消仅属旧页的读取；不取消独立业务执行。
5. 原子更新页面、区域、当前项、面包屑、焦点和浏览器地址，再调用目标加载；异常显示目标页错误/重试，不退成空白。
6. 所有异步结果对导航序号与身份上下文验证，旧响应被丢弃。

统一入口 `requestNavigation` 返回 Promise，结果明确区分 `committed/same-target/cancelled/denied/superseded`；旧 `navigateTo` 适配器返回同一结果。盘点并改写所有“跳转后继续动作”的调用，包括 `openAgentCreateFromComposer`、`openAgentCreateFromModal`、`startSidebarNewChat`、`startChatWithAgent`、`switchSession`、工作文件动作。调用者必须等待已提交或合法同目标结果，再验证操作资格和上下文后执行一次；取消、拒绝和过期结果均不打开表单、不创建会话、不写当前智能体/项目/会话指针。改变会话和智能体的准备值先暂存，离页决定前不得调用有持久化或清理副作用的 `newChat`；通知点击等异步入口也适用。

认证失效、强制改密、成员/租户失效属于强制状态转换，不是可被用户取消的普通导航。立即禁用相关读写、停止依赖失效权限的轮询并离开受保护视图；草稿仅按原模块允许的当前内存规则保留，不显示到新身份、不同租户或持久化到浏览器。普通取消导航仍保持原页状态。不得用“取消离页”继续停留在可操作的失效页面。

启动分为壳初始化和页面/消费者初始化。壳负责品牌、语言、外观、本人状态和路由；完成有效租户及能力校验后才初始化获准目标。当前 `initApp` 中创建/恢复聊天会话、工作区/会话配置、`restoreChatState`、`startPolling` 和知识列表请求须按消费者拆出；直接进入管理深链接不能先建聊天会话或读取知识。已经合法启动的独立后台回复可继续，但失去授权时停止相关连接/轮询，不宣称撤销已提交执行。

用浏览器历史状态记录本路由序号和已提交地址，协调 `popstate` 与 `hashchange` 去重。浏览器已经变更地址后用户取消离开时，回到原历史位置并抑制本次恢复事件，不用继续 push 的方式制造循环。手输 hash 或不含序号的外部历史条目也有规范化分支。刷新/关闭使用现有 `beforeunload` 保护；本次不承诺浏览器确认丢弃后还能恢复未保存表单。

初次没有 hash 时先完成身份和租户选择；默认页面按可用工作台顺序选择，其次为可用管理页。没有功能可用时显示中性说明与个人账号恢复。旧聊天会话选择仍按已有恢复流程，不以进入 `chat` 创建新会话。

备选是只给 `navigateTo` 加 hash 赋值；这会使浏览器后退绕过离页保护，并继续存在二次覆盖函数提前加载的问题，因此必须收口生命周期。

### 4. 可用性按现有身份合同派生，不另建授权系统

本人身份和可选租户来自 `/auth/me`，当前租户权限、租户管理资格和消费者状态来自 `/auth/context`。不从用户名 `admin` 或前端读取的角色名称猜测权限；平台资格使用已验证本人信息，租户资格使用当前上下文。

页面入口条件为：实现登记存在 ∩ 当前模式下功能已开放 ∩ 当前身份允许读取。页面只读、可写与可执行是不同能力。例如 `agent.read` 可以支持已开放的概览，但不能开放创建智能体或开始执行；`tenant.members.read` 允许名录/角色读取，不产生 tenant_admin 写资格。

现有 `consumers` 没覆盖每个页面时，在 `/auth/context` 追加最小 `console_pages` 只读投影；键为登记中有限的页面或页签能力 ID，值为 `available/read_allowed/scope/reason/actions`，`actions` 仅包含该能力实际已有的有限动作布尔值，例如 create、update、execute。键不等于新增权限 ID，后端沿用原判定与消费者开放状态派生。智能体目录、全局默认设置、当前租户成员和平台账号分别登记，不共享父页写权限。父页可见条件为至少一个子页可读；默认落到首个获准子页，禁止预加载其他子页。合法但被拒绝的指定页签显示拒绝，不当作非法页签静默落到别的范围。平台资格来自已验证 `/auth/me`，租户资格来自所选有效租户上下文；投影中的平台动作不因当前 tenant_admin 自动为真。保留原字段，未知键/动作默认拒绝；API 继续独立授权，不接受客户端投影为凭证。

该补充由本 change 的导航适配负责，与身份 change 的 `/auth/context` 维护协同；合同、资格判断及受限改密前置必须先有真实切片证据。不能为了填充摘要将未适配的配置、知识、日志等消费者改成开放。已验收读取和待办应显式返回准确状态，不能因摘要遗漏而永久从菜单消失。

legacy 仅在现有 `/auth/check` 已确认模式和认证后，使用登记的 legacy 实现可用性，继续执行原服务端校验，不调用 database 能力接口。database 查询失败不回退该分支。

读取失败时，停用依赖不确定上下文的操作，保留适用的本人信息、退出/重试。403 或关闭结果刷新能力，401 按当前 auth epoch 触发登录；页面重新激活及身份/租户变更时重验。上下文只放当前页面内存，不跨账号持久化；刷新请求序号与 auth epoch、tenant 标识共同隔离 A→B→A 的迟到响应。

平台页明示“平台范围”，不让顶栏租户选择暗示全局配置变成租户配置。依据用户补充要求，database 中所有启用账号（含平台管理员）必须先有有效租户归属；零租户不再是正常平台管理入口。本人接口可提供最小恢复信息，但不调用需要租户的 `/auth/context`、不伪造 tenant header、不启动正常管理或业务加载；具体服务端及迁移规则见第 9 节。平台接口自身的授权范围仍为平台，不能因此将平台操作授权改为 tenant_admin。

备选为前端维护角色白名单或为菜单新建权限表。二者会和已有权限、消费者关闭状态分叉；采用现有摘要的最小投影避免第二份真相。

### 5. 配置迁移只移动职责，保留数据来源

| 职责 | 新位置 | 原数据/接口与约束 |
| --- | --- | --- |
| 厂商密钥、模型及多能力 | 模型服务 | 复用原模型配置接口、掩码及供应商数据；主表单唯一 |
| 最大上下文、记忆轮次、执行步数、思考、子智能体、自主进化、默认执行范围 | 智能体管理 / 默认设置 | 复用现有默认配置写入；展示真实全局范围 |
| 已支持的单体覆盖、能力和核心文件 | 智能体管理 / 单体详情 | Registry、版本冲突和原文件 API；不发明新覆盖字段 |
| legacy 共享访问密码、明确的运行语言等部署配置 | 系统设置 | 原配置服务与模式判定；database 对未适配写接口继续关闭 |
| 界面语言、主题、配色、字号、通知、声音 | 个人偏好 | 复用外观和现有偏好键、作用域规则，不写全局 `/config` |
| 品牌名称与标识 | 品牌设置 | 保留公共快照、管理权限、草稿和发布版本 |

配置字段清单记录 read/write 调用、存储键、范围、默认/覆盖规则和模式可用性，实施前对真实当前代码核对。原语言链路同时涉及本地展示和 `/config` 更新的部分拆为“界面语言”和“运行语言”；个人语言用已有本地更新方法，运行语言只在真实适用的部署表单保存。默认值缺失继续用原默认，禁止无意覆盖已有偏好。

“个人偏好”是入口名称，不代表账号级存储：现有主题/配色/字号、`cow_lang`、`cow_task_notify` 和声音偏好按当前浏览器原键生效，同浏览器账号共用，界面须说明范围。不新增用户/租户前缀或偏好迁移；智能体选择、租户指针等业务偏好仍按各自原隔离规则保存，不能混用。

对现有不支持单体覆盖的字段只展示其真实范围和跳转，不新增数据库字段或覆盖算法。默认设置与单体编辑有各自未保存状态，原子纳入导航保护，保存失败不提前更新有效值。纯表单重排不改变配置 API 语义。

备选为先保留一个“高级配置”大页再仅改名。可作为阶段间兼容入口，但不能作为本 change 最终完成状态；最终每个配置字段必须有唯一主要编辑位置。

### 6. 统一局部入口与账号行为

- 顶栏保留面包屑、对话智能体、适用文件动作和租户上下文。语言、外观和退出转入账号菜单，复用原操作处理器。
- 账号菜单：个人资料、账号安全、个人偏好、帮助与关于、适用退出。账号安全继续本人改密流程，不新增 MFA 或账号管理功能。
- 保留旧租户调用的函数适配，但全部打开一个有名称的选择器，先处理草稿，再复用一次性 `switch_tenant` 与整页刷新验证。不新增 SPA 租户切换，不在选择项点击时抢先写新租户缓存。
- 产品关于页面/弹层显示当前可信品牌和有效版本；既有上游版本链接另标为“上游更新日志（CowAgent）”。不编造官网和支持链接，品牌/版本失败沿用已有回退。
- 首页功能快捷入口使用 `kind=navigate`，提示词建议使用 `kind=prompt`；前者受路由可用性保护，后者只填入草稿。工作文件继续对话面板并说明当前项目/智能体范围；不创建全局文件页。
- 我的待办默认 `scope=open`；互斥状态选项与范围分开，选已完成/已取消自动切换 `scope=all`。将组合解析到既有合法服务筛选，不改变状态、owner 或未完成计数；避免只在已加载第一页上过滤。
- 智能体页签为设置/能力/核心文件，记忆页“自主进化”根据真实内容明确为进化记录，设置跳转回智能体行为设置；知识保留文档/图谱和范围说明。

### 7. 分阶段开关与交付门槛

使用单一呈现配置 `web_navigation_mode: classic | split`，首轮交付默认 classic；服务端在现有页面响应中注入经过白名单校验的值，不要求打开 `/config` 来读取开关，不新增公开敏感配置接口。用户本地偏好不能变更该开关或功能开放状态。

在 B1 接入共享登记前就实现开关。`split` 只显示选定区域；`classic` 在单侧栏依次显示工作台和四类管理分组，两者使用相同的新页面、页签、配置主编辑位置、权限与路由。classic 不恢复旧综合 config 表单；区域切换和混排是布局差异，不能产生第二份配置编辑器。双区域独立展示要求仅在 split 模式验收，安全及数据合同在两种模式都验收。

| 阶段 | 可独立交付内容 | 进入及启用门槛 |
| --- | --- | --- |
| 0：PRD-02 后续基线 | 锁定 22 项与依赖、字段/入口矩阵 | 当前源代码与真实模式核对，记录 PRD 缺口及相邻未归档 change |
| A：导航修复 | 无效入口、名称、隐藏焦点、统一入口行为 | 原能力可达基线；与认证接口无关的修复可独立交付，classic/split 共用 |
| B：结构和职责 | 双区域、统一地址与生命周期、配置拆分、个人偏好整合、成员租户约束 | A 完成；legacy 原接口真实回归。database 还需身份摘要、归属预检/补分配及所涉安全切片证据；未开放业务不加载 |
| C：集成发布 | 两种模式证据、开关、升级回退及文档 | 路由、未保存、角色、租户和兼容验证通过后才在对应部署设置 split |

不同模式可分别启用，不要求等待全部延期产品完成。database 依赖证据未就绪时继续完成独立页面工作；不可将 mock 通过标成生产解锁。涉及真实业务消费者时，引用其适用的审计、凭据、动作审批、配额/隔离验收结果，本 change 不制作替代证明或重写消费者规范。

关闭 split 只恢复上述兼容排列；统一路由适配、无效项移除、可用性过滤、成员租户约束和键盘修复继续有效。不能回退到会绕过当前身份边界的旧构建。

### 9. 每个成员必须分配租户

这是 2026-09-08 用户明确追加的业务约束，超出单纯改菜单，纳入本 change 交付。database 模式每个 Membership 必须关联真实 Tenant；每个启用 User（包括平台管理员）至少有一条 active Membership 关联 active Tenant，允许多租户。停用账号保留真实历史归属但不能正常登录，恢复前必须补齐有效归属。legacy 没有数据库成员模型，保持现有模式，不生成虚构租户。

- 新建成员在当前已验证租户创建；平台或初始化工具如支持新建账号，必须显式指定有效租户或在初始化事务中创建真实首租户。User、Membership、原定角色及审计同时提交，不先创建无租户启用账号；绑定已有账号保留原密码和其他租户资料，不自动授予租户管理员。
- 停用/解绑最后一条有效成员关系、停用租户、恢复账号，以及未来任何会减少有效归属的写入口，均在原身份写事务中重验归属计数、操作者资格与版本。导致任一启用账号归属为零时拒绝整次事务，建议沿用 409 并使用明确业务原因 `last_active_tenant_required`。不能只校验被修改记录，也不能仅在前端禁用按钮；并发从两个租户移除同一账号也须保持约束。既有最后平台管理员/租户管理员规则同时成立。
- 先通过现有合法管理入口完成另一租户分配，再停用原关系；不得替租户管理员全局停用他人账号或允许其管理另一租户。离职账号如需全局停用，走原平台操作及审计，保留历史 Membership；全局停用不强迫为离职人员新建有效业务权限。
- 普通成员无有效租户时显示“待分配租户，请联系管理员”，只提供适用本人信息、改密、退出与重试。重试从 `/auth/me` 重新确认分配后再选择租户。平台管理员也不能绕过；若存量部署所有管理员均无有效归属，先由具备原部署维护权限的初始化/迁移工具按显式目标修复，不开放自助提权入口或临时放宽普通 API。
- 发布前只读预检启用账号与有效归属，生成限管理员查看的待处理清单；由有资格管理员指定真实租户并复用原写事务/审计补分配。禁止按名称猜租户、默认加入首租户、批量授予管理员、硬删除历史或改写会话/文件 owner。完成预检复查及真实接口验收后再发布新约束；遗漏或运行期失效一律进入受限恢复。回退布局不得回退此约束。

本 change 负责新增连续性校验、管理表单提示、存量预检及其测试，沿用身份 change 的服务/管理入口/事务安全实现；相邻任务不自动标记完成。若依赖写切片尚未完成，则作为 database 启用的前置任务并先完成，不能靠菜单过滤宣称成员归属已落实。

## Risks / Trade-offs

- [静态 HTML、巨型脚本与测试依赖原选择器] → 保留必要 view ID/函数别名，批量盘点所有内部入口，按功能回归，不通过简单搜索替换修改一切。
- [浏览器后退与多个离页保护相互触发] → 单一导航事务、一次决定、历史恢复抑制；覆盖品牌/成员/智能体/文件各类草稿以及快速连点。
- [摘要遗漏使已有功能消失，或假定管理员可用导致扩权] → 页面能力完整矩阵、显式只读投影、缺失拒绝；真实验证已开放读取，API 继续独立授权。
- [全局配置被误当单体/个人设置] → 字段归属表与写请求比对；移动前后核对值和继承，不改变存储合同。
- [数据库运行消费者仍关闭] → 工作台六项是候选目录，实际过滤；有意义的默认页和未开放说明，不为布局完整而开放功能。
- [账号入口减少后恢复操作丢失] → 退出未确认、重新检查身份、强制改密及无租户状态继续可达。
- [同一工作区相邻 change 正在变化] → 以实施时版本证据更新迁移表，保持原有已交付业务入口，记录差异而不覆盖其他任务。

5. 对通过门槛的部署设为 split，验证刷新、浏览器前后退、已有会话、个人偏好及语言。以相同数据运行一次切回 classic，再切回 split 的演练。
6. 如需回退，优先关闭呈现开关，保留兼容适配及安全修复。不得通过切换 identity_mode、删除迁移标志或清空数据库恢复旧布局。需要回退代码时使用已验证兼容当前身份合同的构建，必要时停用受影响管理入口而不是放宽权限。
