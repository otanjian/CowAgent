## Why

「系统设置 → 租户 / 用户 / 角色权限 / 组织架构」需要真实管理功能和可信租户边界。参考 OneAgent 的集中认证、RBAC 和租户工作空间，在 RongAI 现有 Python/web.py/SQLite、Agent Registry 与原生前端上实现最小身份管理版本。

## What Changes

- 接通截图中的四个菜单，沿用 `tenant/system_user/roles/org`、现有顺序和面包屑。
- 保留全局 User + 租户 Membership，支持同账号加入多个租户；采用企业管理员直接建成员/绑定已有账号，取消邀请、接受及专用恢复邀请系统。
- 使用数据库账号和可撤销 AuthSession；当前租户由页面明确提交、服务端逐请求校验成员资格，不持久化登录会话的“当前租户”，不实现跨标签同步或租户上下文版本协议。
- 平台管理员管理租户和全局账号；tenant_admin 管理本租户成员、角色和组织。自定义角色只分配已登记业务权限，不开放授权委派；平台身份不自动读取租户业务。
- 组织采用部门树、成员单部门和岗位名称文本；一期组织只用于名录和筛选，不产生部门数据权限，不引入多部门任职、岗位字典、资源部门标签或跨库部门迁移。
- 复用全局唯一 Agent ID 与每 Agent 的数据库/工作空间，只增加租户绑定和必要的个人资源所有者。默认租户登记既有目录，新增租户使用独立目录；不强制全量搬迁数据、重建索引或改写所有业务表。
- 首期交付 Web 四个管理页及明确授权的 Agent 概览、历史、知识/记忆受控读取；普通成员限本人或显式共享内容，tenant_admin 可读本租户已登记资源。新模式关闭模型执行、文件预览/上传、流式运行控制、外部通道、OpenAI API 和调度等未适配入口。完整业务接入留给对应后续 change，不把它们作为本次实现任务。
- 身份写入与最小内部审计在同一 SQLite 事务落盘，提供受限查询并真实验证恢复；取消 outbox、跨服务投递和通用能力就绪平台。
- **BREAKING（启用 database 模式时）**：共享密码/免登录不能授予权限，旧登录 token 失效；未适配消费者明确不可用。legacy 模式保持既有接口；模式切换通过维护窗口重启完成，不动态降级授权。

## Capabilities

### New Capabilities

- `tenant-management`: 平台租户创建、编辑、停用/恢复、管理员配置和当前租户信息。
- `identity-session`: 登录、可撤销会话、显式请求租户、切换及旧模式兼容。
- `user-membership`: 账号与成员分离，管理员建成员、绑定、停用与角色/部门分配。
- `rbac-authorization`: 平台/租户分域、固定权限目录、管理员专管、菜单/API 一致授权。
- `organization-management`: 部门树、单部门任职、岗位文本及引用完整性。
- `tenant-resource-isolation`: 现有存储的最小租户隔离、个人资源归属、旧数据登记和未适配入口关闭。

### Modified Capabilities

- 无。六份规范仍是本 change 内未实施的新增提案；`openspec/specs/` 无正式基线。本次直接更新提案，不把旧草案要求当作已上线功能或另加 REMOVED 主规范。

## Impact

- **范围依据**：用户的四菜单要求及本轮“最简改造、直接优化”指令。仓库配置所指 PRD-00、PRD-01～12 v1.2 原文仍缺失，记录缺口并以本次明确范围为当前设计依据；实施时登记 PRD 映射，恢复原文后核对每份 PRD 对应 change，不能虚构编号或整体覆盖结论。
- **改造落点**：独立 `auth/` 服务、Web 认证/管理 handler、HTML/JS；扩展既有 RuntimeIdentity、Agent Registry、state_dir 和受控读取接口，保留业务 session/run ID 与现有存储结构。
- **唯一真值**：`identity.db` 拥有身份、租户到 Agent 的绑定和身份审计；Agent 的 workspace/配置继续由 Registry 所用现有配置拥有；业务内容继续由现有业务库存储。配置仅保留身份模式、数据库路径等启动参数，不复制身份字段。
- **依赖切片**：本期真实实现并验收 PRD-10A 身份管理最小审计；08S 凭据、09G 外部动作审批、10B 模型硬配额在相应业务接入时验收，本期消费者关闭。任意代码执行保持关闭至执行隔离验收。
- **其他 change**：接续 `prd-02-platform-navigation` 菜单骨架，不改其他 change 文件。`add-branding-settings` 的已发布品牌可读；新模式下其写入须等待平台授权和可靠审计接入，本次不处理品牌跨存储事务。
- **交付性质**：只优化 change 文档；所有实现任务保持未勾选。详细取舍、首期边界及延期条件见 `design.md`。
