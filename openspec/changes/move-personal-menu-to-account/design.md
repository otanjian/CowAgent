## Context

动机与用户确认范围见 `proposal.md`。本设计基于当前工作区的 Web 实现，产物状态不表示运行行为已经实现。

| 接入点 | 当前行为 | 本次需要处理的边界 |
| --- | --- | --- |
| `channel/web/chat.html` | “我的”五项位于 `#sidebar-nav`，底部另有 `#sidebar-account-menu` | 将个人入口整体迁入一个账号面板，保留现有其他入口 |
| `console.js` 的账号渲染、展开和关闭逻辑 | 处理身份状态、焦点、外部点击、退出及菜单最大高度 | 加入资源分组、区域标记与移动底部面板，不破坏身份恢复 |
| `VIEW_META`、`navigateTo`、`_openNavArea` | 个人页映射到 `personal.*`；跨区域分支早于部分未保存检查 | 账号内新入口必须在区域提交前完成离页保护，并以成功导航更新标记 |
| `_applySidebarPermissions` | 主要扫描 `#sidebar-nav .sidebar-item[data-view]`，另查主导航的个人分组 | 扩展到账号内个人入口；不能把 DOM 移走后失去过滤 |
| `personal-console.js` | `PERSONAL_VIEWS` 定义五个页面，注册加载器，保留个人页面能力与迟到响应保护 | 继续复用这些页面，不增加第二套页面实现或顶部切换栏 |
| `console.css`、`appearance.css` | 账号浮层、图标侧栏、触摸尺寸、主题及减少动态效果已有样式 | 适配更长内容、当前资源状态和移动弹出面板 |
| 账号/个人页面相关前端与浏览器测试 | 部分断言依赖主导航里的个人分组和旧菜单尺寸 | 改为验证新宿主及用户路径，保留原权限和会话保护断言 |

规范基线为 `sidebar-account-menu`、`console-information-architecture`、`console-navigation-availability`；导航提交与离页保护继续遵循 `console-route-lifecycle`，账号操作和身份来源继续遵循 `account-menu-actions`、`self-account-context`。

已知基线差异：`account-menu-actions` 仍有“六项菜单”及账号租户入口要求，而当前 HTML 展示的常规账号操作为个人资料、账号安全、个人偏好、帮助与关于、退出登录。此差异不由本 change 扩展为账号功能补建；实施时登记实际入口与现有租户选择路径，不移除其规范责任、不删除既有能力、不重写账号操作条目数量。

## Goals / Non-Goals

**Goals:**

- 在已有账号面板内平铺个人资源，让“打开账号 → 选择个人入口”成为无草稿阻断时的两步路径。
- 让用户能发现个人资源、知道当前所在页面，并能在桌面、图标侧栏、移动端及低高度窗口触达全部操作。
- 菜单迁移前后使用同一个页面、同一套身份/租户/授权来源和同一条受保护导航路径。

**Non-Goals:**

- 不实施建议细节 3：不新增个人页面顶部页签、页面内个人快捷栏、个人中心中间页或第三个导航区域。
- 不重排其他工作台或控制台菜单，不新增菜单搜索、收藏、后台可视化配置或通用菜单管理系统。
- 不变更个人资源业务、后端权限规则、默认 grant、数据库和 API；不借机开放个人渠道运行。
- 本次仅形成 change 文档；所有实施任务保持未勾选，不执行代码修改、提交或部署。

## Decisions

### D1. 同一账号面板内分组平铺

目标结构如下；分组标题不接受点击展开，具体资源按权限过滤：

```text
主侧栏
  ＋ 新建对话
  对话 / 智能体 / 我的待办 / 定时任务 / 知识库 / 场景应用
  会话历史
  控制台（按现有资格显示）
  头像 / 用户名 / 展开箭头

账号面板
  完整用户身份 / 当前已确认租户
  我的资源
    我的智能体
    我的渠道
    我的记忆
    我的工具
    我的技能
  ────────────────
  账号设置
    个人资料
    账号安全
    个人偏好
  ────────────────
  帮助与关于
  退出登录
  既有品牌版本链接
```

账号设置及租户选择遵守 Context 所列既有能力边界，树中不创建新操作。身份区内的租户只用于说明个人资源属于当前有效租户；显示来自已确认上下文，无有效选择时显示中性状态，不能用成员名替代全局账号名。

个人入口只保留一份 DOM，使用账号菜单专用样式和个人入口标记。保留原 `data-view` 值，避免复制成 `.sidebar-item` 后被主导航布局或折叠规则误处理。账号面板同时服务 `/chat` 与 `/admin`；面板本身不成为新的导航区域。

选择平铺是因为当前恰有五个个人入口。二级“我的资源”子菜单会增加一次展开及移动端复杂度；独立个人中心需要额外中间页面。两者均不纳入本次范围。

### D2. 保留身份及五组稳定编号

| 显示名称 | 现有 view ID | 现有页面能力键 | 现有菜单授权编号 |
| --- | --- | --- | --- |
| 我的智能体 | `personal-agents` | `personal.agents` | `nav:personal.agents` |
| 我的渠道 | `personal-channels` | `personal.channels` | `nav:personal.channels` |
| 我的记忆 | `personal-memory` | `personal.memory` | `nav:personal.memory` |
| 我的工具 | `personal-tools` | `personal.tools` | `nav:personal.tools` |
| 我的技能 | `personal-skills` | `personal.skills` | `nav:personal.skills` |

继续使用现有个人入口/页标题翻译键，新增分组、提示、关闭按钮及个人区域状态文案覆盖简体、繁体、英文。触发器显示名优先、用户名回退、`@用户名` 完整提示均按既有账号规则保留；“个人资源与设置”是补充用途说明，不替换用户姓名。

入口展开箭头只表达面板开闭；个人区域的轻量背景与可访问说明表达页面归属。二者为独立状态，避免“账号菜单打开”被误认为“正在个人页面”。

### D3. 入口位置与页面授权解耦

账号内入口从 `VIEW_META`/既有个人页定义获得能力映射，复用既有 `/auth/context` 和 `console_pages`，不增加第二份角色列表或本地权限判断。将个人入口筛选与旧主导航宿主分离，使相同个人判定可作用于账号面板，并保持个人页加载器自身的二次拒绝检查。

刷新个人分组时完整计算显隐，不只追加 `hidden`：撤权后隐藏，再授权后必须恢复。所有个人项被拒绝或被关闭时移除空标题；上下文检查中/失败时保留明确的检查/重试状态，不提供可激活的未确认个人入口。全局资料、帮助、退出等适用账号操作继续可用。

菜单仅消费页面级摘要。打开面板不调用五个个人页面加载器，不预取资源数据，不开启渠道或其他运行消费者。`personal_channel_runtime` 关闭而目录可读时保留“我的渠道”；`member_personal_console` 关闭时按权威结果撤下个人入口，不改变后端仍允许的自有资源收回规则。

账号和租户变化沿用已有认证 epoch、上下文失效与个人页请求代际机制。进入新上下文前关闭旧面板、清除旧入口及区域标记，晚到响应不得恢复旧显示。不得把当前能力摘要另存进持久化存储。

### D4. 个人入口使用受保护导航，成功后才更新定位

迁移后的点击与键盘激活进入同一个个人导航适配入口，不直接调用个人页面加载器。顺序为：

1. 记录当前页面及原页面可恢复焦点；按当前上下文验证目标。
2. 关闭账号面板并解除移动面板的焦点/背景限制，将离页确认交给现有表单或编辑器。
3. 完成适用的未保存检查；取消时保留原区域、地址、编辑状态与当前项，并将焦点还给原页面。
4. 仅在检查通过后提交目标：从 `/admin` 进入个人页时切回既有工作台宿主，保留当前有效租户。
5. 成功提交后执行既有加载器、同步页标题和当前项，再聚焦可见目标标题或主内容；被拒绝/替代时不启动目标消费者。

当前 `navigateTo` 的跨区域分支早于部分 dirty guard，且外层包装还会追加加载。实施需对影响该入口的共用导航顺序和可等待结果做局部修正，不能仅把点击改成 `_openNavArea`，也不能在一个入口外先检查再让导航内部重复确认。使用既有受保护导航能满足行为时直接复用，不在此进行全量路由重构。

沿用个人页既有标识和 `/chat#view-personal-*` 入口。不要求本次补齐全站普通点击写入地址或浏览器历史的既有实现差距；对于已经支持的直接链接、恢复和前后退路径，账号当前项应随实际成功目标同步，不能导致回归。

### D5. 当前页面标记只有一份

对成功进入的个人页，清除主导航当前项，将账号内匹配入口设为唯一 `aria-current="page"`；底部账户按钮仅增加区域状态样式和描述，不设第二个 `aria-current`。面包屑保留“我的 / 当前完整页名”。

账号面板默认保持关闭，打开时让对应当前项滚动到可见范围。只展开面板不改当前页；账号身份、语言、品牌重绘后重新同步当前有效定位，不能丢掉区域状态。成功导航到其他页面、认证清理及资格失效时清除个人标记。已进入页面的数据读取失败时仍保留该页定位，由原页面呈现错误与重试。

### D6. 桌面浮层与移动底部面板共用内容

- 桌面展开侧栏：从账号卡片上方向上弹出。图标侧栏：在卡片右侧显示，保持原有发现路径。
- 使用现有移动侧栏断点（当前为 `<1024px`）切换到底部面板，不新增另一套断点规则。面板带标题与关闭按钮，使用模态对话框语义；打开时焦点进入第一个可见可用操作，Tab 在面板内循环，Escape/关闭按钮/外部遮罩关闭。
- 移动面板应挂载到不受侧栏 transform/overflow 裁剪的位置，并复用同一个账号内容实例；如需调整宿主，外部点击、焦点归属与关闭监听同步适配，不能复制两套操作或重复绑定。
- 桌面仍按非模态浮层处理：Tab 离开时关闭且不抢回焦点；关闭态、父分组隐藏态、disabled 操作不成为初始焦点。
- 面板宽度受当前视口限制，最大高度根据可视高度、安全区和账号锚点计算；建议移动面板不超过可视高度的 80%，内容区独立滚动。大字号时允许行高增长，不靠裁切文字或缩小触摸目标塞入全部内容。
- 使用普通指针至少 36px、粗指针至少 44px 的操作行；保留焦点轮廓、三语和主题兼容、减少动态效果。关闭移动侧栏或进入登录/改密限制流程时清除面板、遮罩、滚动锁和焦点限制。

桌面和移动采用不同弹层语义是为保留桌面现有 Tab 行为，同时让手机面板明确、可关闭；内容与授权仍只有一份。精确宽度、圆角和留白由实施时现有样式变量决定，不影响层级及交互契约。

### D7. 不新增呈现开关或数据迁移

本次是同一入口的宿主迁移。新增独立布局开关会形成旧主导航与新账号菜单两套测试和支持分支，因此不新增。继续验收既有个人能力开关的开/关状态；现有 classic/split 配置不得产生重复个人入口或改变授权。

发布时 HTML、JS、CSS 作为匹配版本交付，避免旧脚本寻找已移动节点；沿用项目现有静态资源版本机制。回退使用本 change 的前端差异反向恢复，不撤销其他 change、不改 grant 或数据，不使用个人业务开关充当布局回退按钮。

## Risks / Trade-offs

- [入口隐藏到账号下，首次发现成本增加] → 显示展开箭头及“个人资源与设置”提示，保留“我的”名称；接受个人页切换需要重新打开账号菜单，不增加被明确排除的顶部页签。
- [账号面板变长] → 个人资源/账号设置分区，桌面限高滚动，移动底部面板，低高度和大字号实测全部操作可达。
- [过滤器仍只查主导航导致权限遗漏] → 共用个人投影判断，验证撤权、恢复授权、全关闭、执行关闭但可读、无有效租户及检查失败。
- [跨区域跳转早于未保存保护] → 在区域提交前完成同一离页决定，并验证从控制台编辑态进入个人页的取消与成功路径。
- [身份/主题重绘或异步加载导致错误高亮] → 标记取自已提交目标与有效上下文；账号开闭不改变当前页，迟到结果不可恢复旧项。
- [移动 transform 裁剪及模态焦点残留] → 根级可见宿主、单份内容、明确关闭/卸载逻辑，覆盖关闭侧栏、切换断点和认证失效。
- [与未归档个人控制台及能力补齐 change 重叠] → 核对代码与规格切片后再实施，只提交本 change 的增量；不根据历史勾选声明现有缺口已完成。

## Migration Plan

### G0：实施前基线

记录当前未提交改动、五个个人页面和账号路径；核对 `enable-member-personal-console` 中页面注册、授权投影、能力开关、上下文隔离的相关测试/交付证据。确认该 change 的独立增量合并与归档关系，本 change 不覆盖其菜单 grant 要求。与 `complete-database-capability-parity` 对齐共同文件及实际页面能力状态。

### G1：功能与结构就绪

在同一实现批次交付入口迁移、权限/上下文适配、受保护导航、状态同步及响应式面板。五个入口均从账号访问、旧主导航不重复，旧链接及账号操作回归通过后才能进入浏览器验收。缺少相关个人页面依赖证据时保持该页面原关闭状态，不能靠静态菜单通过验收。

### G2：验收与交付

覆盖普通成员、租户管理员、平台管理员、部分撤权、无租户/强制改密、能力开关组合、上下文晚到、跨区域取消、短窗口/移动/图标侧栏、键盘与三语主题。记录真实浏览器操作、请求行为和截图证据；结构校验及模拟能力响应只能证明对应切片，不替代依赖页面的真实授权验收。

确认 HTML/JS/CSS 匹配发布、不新增迁移与 grant。演练仅回退本前端差异后五个入口重新出现在旧宿主、个人数据和权限不变。归档时只合并本 change 列明的增量 requirement，保留其他 change 的要求。此轮只编写上述计划，不执行实施或归档。
