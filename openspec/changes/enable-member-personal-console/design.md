## Context

动机见 proposal.md。当前已有成员功能权限、个人助理供应、owner 读/用授权、工作区管理、租户渠道实例和目录资源过滤，缺口集中在这些能力之间的连接及旧管理例外。

## Goals / Non-Goals

**Goals:**

- 在同一控制台壳内提供成员个人视图，复用已有编辑器、目录和运行链路。
- 让“本人可维护”在统一对象授权中成立，权限摘要和直接 API 得到相同结论。
- 用唯一资源归属及当前身份事实隔离个人、租户公共和平台公共操作。
- 支持存量成员与数据迁移，并允许按独立能力关闭新入口而继续保护私有数据。

**Non-Goals:**

- 不提供私有智能体向租户发布、成员自行安装公共工具/技能或管理员代登录能力。
- 不重建 Web/Desktop/Channel、Agent Registry/Bridge、业务 session、ExecutionRun 或 scheduler。
- 不因开放个人配置而开放尚未验收的任意代码、Desktop 企业登录或其他执行消费者。
- 不将应用内管理员限制解释为能阻止宿主机运维人员直接读取底层文件；这里约束产品 API、控制台和运行消费者。

## Decisions

### 1. 使用同一控制台，新增独立的个人作用域

登记 `personal.agents`、`personal.channels`、`personal.memory`、`personal.tools`、`personal.skills` 五个有限页面标识，菜单资源使用既有 `nav:<page>` 格式。复用既有组件，不新增独立认证系统或第二个控制台站点。现有 `admin.*` 标识继续表示其原作用域，旧管理深链接不能静默改成个人视图。

服务端 `console_pages` 同时给出可读、可维护、运行开放状态、作用域及拒绝原因；对象列表再投影 `can_edit`、`can_enable`、`can_delete`、`can_configure_personal` 等有限动作。前端不按角色名称、权限数量或作者名称推断动作。

新增内置 `member`、`tenant_admin` 的个人菜单 grant。菜单 grant 具有限制性（角色持有任意一条 `menu` grant 即绑定该集合），而内置角色此前不含任何 menu grant、仅受功能权限约束；因此默认集合取「该角色迁移前已可访问的页面 + 五个新个人页面」，使门禁启用既不隐藏任何既有可达页面，也不放宽原本不可达的页面（未被任何内置角色可达的页面不入集合）。存量迁移幂等补入这些 grant，不修改非菜单 grant、不重置用户编辑过的其他权限、不覆盖已有 grant。自定义角色不批量加权。迁移后管理员仍可通过明确菜单授权控制页面展示；菜单只控制入口，数据 API 仍按当前动作及归属独立授权。

选择独立个人页签而不是直接向成员开放整组管理菜单，可保持现有公共管理的接口和 URL 含义稳定。

### 2. 所有权形成对象动作授权，不形成全租户编辑权

保留 `agent_bindings.private_owner_user_id` 作为私有智能体唯一 owner；本人个人操作从已验证会话和当前有效 Membership 派生，拒绝客户端指定 owner 或将私有资源改为共享。统一授权入口识别私有对象的本人读、用、编辑、启停及适用删除动作，不向成员的全局功能集合粗放加入 `agent.enable` 等公共维护资格，也不为每个个人智能体补写角色 grant。

授权顺序为认证与有效租户/成员、真实对象归属、本人动作或显式公共动作授权、运行与政策条件。私有 owner 的允许和非 owner 的拒绝必须在管理员旁路前处理。平台 all 与 tenant_admin 只对其允许的公共职责生效；管理员可见的治理投影与私有详情分开，前者只含必要的归属、数量、状态、用量和脱敏操作记录。

模型、工具、技能与知识依赖仍逐资源判断。保存配置、启动调试以及每次后续资源调用均重验；仅有本人智能体维护权不足以调用未授权模型或工具。

### 3. 区分专属助理与自建私有智能体

为私有 Agent 绑定增加可迁移的来源标识，取值区分 `provisioned_assistant` 与 `user_created`；未知历史来源保持显式未知，不猜测。系统助理供应幂等键为租户、成员和系统供应用途，不再以“已拥有任意私有智能体”作为跳过条件。

用户自行创建时由服务端生成 Agent ID、当前租户绑定和 owner，复用安全工作区初始化；来源模板只能是获准模板，不复制其记忆、会话、凭证或实体知识/技能。新私有空间与共享根分离；自有知识初始化与在途知识权限 change 对齐。

系统助理保留默认登记及启停语义；自建智能体不自动改写个人或租户默认入口。删除仅开放给本人自建对象：存在运行中任务或有效渠道引用时返回冲突并列出本人可处理的原因；不能通过删除接口抹除系统供应助理、共享对象或他人对象。

创建使用幂等请求与原子配额预占；跨身份库、Agent 注册及文件系统的写入采用可恢复状态和补偿，只在全部必要步骤成功后返回可用。编辑使用现有配置版本/mtime 冲突机制，避免覆盖他人或另一个页面的新版本。

### 4. 渠道沿用现有实例存储，新增个人归属

扩展现有租户渠道实例记录，增加 `scope=tenant|user` 和可空 `owner_user_id`。历史实例统一保持 `tenant` 且 owner 为空；`user` 实例必须同时有租户、有效 owner 和版本。平台实例继续保留既有平台存储及入口，成员不写平台名册。

个人 API 建议以 `/api/personal/channels` 及受登记的对象子资源承载，复用服务层事务，但固定当前身份归属。公共列表只返回 tenant 实例；个人列表只返回当前租户的本人 user 实例；运行消费者可以读取获准启动的实例元数据，但每次处理消息仍解析真实发送者。

凭证沿用既有加密版本存储，通过实例真实归属推导个人所有权。管理 API 包括 owner 本人也只返回掩码；解密只在已授权渠道连接/调用边界发生。个人工具参数以租户、用户、资源标识唯一保存，敏感字段只保存个人凭证引用，不写公共 MCP 或工具配置。

名称唯一性按租户、作用域、owner 和渠道类型判断；启用同一外部应用的重复连接须按提供方稳定应用标识检测，不允许个人实例抢占现有公共应用连接。创建和启用在事务中重验允许类型与配额；停用不能成为无限创建对象的配额绕过。

租户管理员通过单独治理动作停用违规个人接入，不读取或替换其凭证、不改绑其智能体；治理停用记录独立于 owner 启用意愿，owner 不能自行清除。解除治理限制后也需本人明确启用并重新验权。

### 5. 自助身份绑定验证控制权，并与个人路由分离

保留既有 `external_identities` 的全局唯一三元组到 User 映射。新增绑定挑战及当前租户内的个人渠道关联，服务端固定 user、tenant、instance、用途和有效期；OAuth state 或一次性挑战的外部证明须经过提供方验签/可信回调及当前会话复验。仅填写 open_id、昵称或持有机器人凭证不能证明发送者身份。

挑战单次消费并限制尝试次数；重复映射到另一 User 返回冲突，不覆盖。为同一 User 在另一租户接入时复用既有映射，但单独建立当前租户、实例及本人路由的关联。

成员的“解绑”只解除当前个人接入关联并立即阻止其后续路由，不删除其他租户仍使用的全局身份映射。管理员既有账号预绑定接口继续保留管理权限，自助接口不能用于列举他人身份或任意待绑定尝试。

个人渠道及标记为个人绑定流程的未绑定入站消息不写管理员可读的昵称/消息预览，只留处理失败所需的脱敏状态。公共渠道原有待绑定流程继续按本租户管理；挑战码、凭据及用于验证的私聊正文不进入待绑定预览或审计正文。

### 6. 个人路由只在验证后的私聊中执行

入站顺序为可信实例、所属租户、提供方发送者证明、外部身份映射、有效成员、个人关联和目标归属，最后才初始化业务会话。个人实例必须满足发送者即 owner，目标为本人的有效私有智能体。未绑定、已解绑、停用、目标无效或身份事实不可用时拒绝，不回退到租户/平台默认或服务账号。

租户公共实例的公共路由只绑定同租户公共智能体。用户在公共实例上显式建立的个人路由仅适用于已验证的本人私聊；群聊和共享会话继续公共行为且不注入个人记忆，不因先前私聊选择而改变。

停用、凭证撤销、成员失效或工具授权变化应在后续消息与资源调用前生效。更新连接失败时标明保存状态和实际运行状态，不把“已落库”显示为“已接入”，也不静默继续旧凭证连接。

### 7. 个人记忆使用可信作用域与可恢复修改

页面区分“我的记忆”（当前 tenant/user，跨本人获准智能体）与“该私有智能体记忆”（当前 tenant/agent，owner 本人）；两者共享归属校验但不混用存储根。共享 Agent 记忆和租户知识不是个人清空动作的目标。

文件管理使用相对标识和服务端解析的真实根；拒绝软链接逃逸、伪造 agent/path 和不明确归属。读取、列表、目录搜索、下载及预览消费都复用实际来源校验；平台可浏览父目录并不取得其内成员私有文件权限。

编辑和清理使用版本条件。清空增加作用域版本或等效失效标记，使之前排队的 flush/dream 等任务不能凭旧版本重新写回已清空内容；新输入触发的新任务可按新版本形成新记忆。索引移除与内容修改需有可重试记录，失败时不能宣称清空成功，也不能从旧索引返回已删除正文。

### 8. 与现有 change 的合并职责

先吸收 owner 可达性与工作区实际归属的实现切片，再统一移除其 tenant_admin 私有内容例外；旧用例中“管理员可读他人私有文件”的预期需要改成拒绝及治理元数据仍可读。

知识写 change 继续负责公共知识写规则、`knowledge.write` 迁移和 own/shared 数据根选择。本 change 的知识 delta 只规定私有归属优先：其管理员写分支必须在 owner 过滤之后执行，非 owner 不能借共享视图、文件别名或 `can_write_knowledge` 访问他人私有 own 库。个人记忆管理不依赖给 member 增加知识写权限。

规范归档需按 requirement 合并，不用本 change 覆盖其他 change 对默认入口、知识模式、人设字段及工作区冲突处理的改动。实现阶段同步清理既有 Purpose 中与新 owner 规则相冲突的旧说明。

## Risks / Trade-offs

- 旧管理员旁路分散在列表、知识、文件和预览中 → 用统一 owner 判定并覆盖真实路径矩阵，禁止只修改菜单。
- 个人渠道涉及外部回调与多实例状态 → 只开放已有真实多实例支持且完成个人路由验收的类型，其他类型保留清晰未开放状态。
- 外部身份映射跨租户复用 → 全局映射与个人关联分离，成员解绑不删除他处关联。
- 数据库与工作区/连接启动不能单事务完成 → 使用可恢复中间状态、幂等补偿和准确的运行状态；失败不留下可执行半成品。
- 成员创建大量私有资源 → 复用租户资源上限并增加原子个人额度约束；具体额度由部署策略配置，不在代码中虚构固定业务数值。
- 旧预览链接或旧索引仍可返回私有内容 → 私有链接消费时重新校验 owner，迁移时使不满足新边界的旧私有令牌失效。
- 跨 change 的新旧知识授权不一致 → 私有知识切片在双方合并与授权矩阵通过前保持关闭，其他已独立验收能力可继续实施。

## Migration Plan

1. 只读盘点实例作用域、Agent owner/来源、角色菜单、外部身份映射和私有路径；备份身份库及关联业务状态，发现未知归属或冲突即保留隔离，不自动共享。
2. 以版本化幂等迁移增加实例个人归属、专属助理来源、绑定挑战及个人关联存储；旧渠道保持公共，现有 ID、凭证版本和外部身份映射不变。
3. 根据可信供应记录与本人专属默认登记标注系统助理；证据不足保留未知来源，允许已有合法读用但不开放删除。补入新个人菜单 grant，不重置旧角色配置。
4. 先部署后端 owner 拒绝规则与投影。按读目录、私有维护、记忆写入、个人接入、个人执行分别验收；开关只控制能力开放，不控制是否检查权限。
5. 分阶段启用建议开关 `member_personal_console`、`user_private_agent_management`、`personal_memory_write`、`personal_channel_onboarding`、`personal_channel_runtime`。具体命名接入既有配置目录，各开关默认在对应真实切片证据满足后显式启用；目录和既有功能不因个人执行关闭而被整体关闭。
6. 回退先关闭新动作和个人运行消费者，停止对应连接，保留已写元数据、凭证历史及 owner 检查。不能降级到会忽略 user scope 或恢复管理员私有读取旁路的旧版本；如确需恢复旧版本，只能在维护窗口按一致备份恢复并明确新数据处置。

阶段门槛：

| 阶段 | 开放前必须具备的证据 |
| --- | --- |
| 个人入口与目录 | 真实身份库、默认与自定义菜单矩阵、当前租户过滤、403/503 与迟到响应处理 |
| 私有智能体与记忆 | owner 动作矩阵、实际文件来源隔离、版本冲突/补偿、记忆检索一致性、运行依赖授权 |
| 个人渠道接入 | 密文落点、身份挑战防重放、应用冲突检测、原子配额、审计失败与连接失败恢复 |
| 个人渠道执行 | 真实支持渠道的本人私聊到实际分发链路、他人/群聊拒绝、解绑和停用生效、凭证/配额/适用审批及隔离切片 |

没有需要在提案阶段由用户补充的业务决策；首批渠道清单以已实现的适配器能力及验收结果登记，挑战有效期与个人额度作为可配置实施参数。
